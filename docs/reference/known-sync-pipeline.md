# 已知同步期的精确有限流水

SYS-C2E2G-HOLD-PIPELINE依据已登记标准§6.2.1.2 PSK、§6.3帧结构和§6.9 CRC，
优化接收实现的计算结构。Gardner/PI及本流水不是标准强制算法。
保留普通FT2/3/4、4Msym/s、SPS4、power30/error32的显式实验边界；
不扩展FT1/GFSK、WS63未知编码或其他采样配置，不改变默认接收。

## 值、状态与端口

`HoldTimingPipeline(state,cache,clock_origin)`独占已封存的同步缓存读端口。
`PipelinedPacketTimingService`在保持期排空后，将同一4DSP银行交给原正常定时服务。
`PipelinedTimingFrameReplay`把实际结果送入原严格头/数据CRC和MAC路径；
构造时要求显式`TimingWordFormat(30,32)`，不支持格式在消费准备上下文前拒绝。

```{mermaid}
flowchart LR
  C[同一注册同步缓存1R] --> E[4个25×18 DSP/两级加法树]
  E --> P[原六边沿功率RNE/下限反馈]
  P --> Q[两个结果槽/总计四个信用]
  Q --> N[一边沿注册NCO及计数结果]
  N --> A[有序接受/唯一包状态]
  A --> F[原归一化/严格帧服务边界]
  A --> D[同步结束/排空/切换原数据定时]
```

能量5边沿与功率6边沿重叠；功率仍逐个执行`(63P+energy)/64`、共同指数对齐、
最近偶数舍入及原floor。没有闭式IIR近似、能量侧RAM、功率平均值替换或额外缓存遍历。
乘法数量仍为每同步符号4个原生分片，收益来自重叠及固定速率保持期的结构简化。

保持期误差为零、速率严格为4，因此缓存地址为同一初始格点加4倍序号、分数相位不变。
只是精确查询的提前生成；不改同步评分、位置、网格、候选、峰值等待或CRC选择规则。
首数据符号起恢复原实际NCO查询、Gardner/PI、64步除法和全部原参数。

私有功率可在四信用内前推，主包状态只在接受有序注册结果时转移。
NCO/计数准备有一个实际边沿，不能在取结果时重算并视为零周期；
准备状态686bit单独计费，主状态保持到结果被接受，最多领先已存符号一个。
`peek()`只返回副本，主机诊断不能改变排队字或状态。

输出两槽满时冻结功率提交，缓存/能量/功率/输出合计最多四个上下文。
同步末尾必须完全排空，并保留一个银行切换边沿；同边沿正常数据请求返回背压。
正常数据阶段只推进原服务，不再推进保持期DSP，不能凭TDD或平均空闲计共享收益。
异常退出记录待处理字、序号及阶段；诊断快照是主机输出，不冒充免费的FPGA跟踪RAM。

未知归一化、载波、头部和译码继续停在显式服务点。功能求解使全局周期证据失效，
完整接收延迟仍为`None`；资源堵塞仍可导致有界丢弃，没有把这些工作填零。

## 格式、成本与预算

| 节点 | 格式/成本 |
|---|---|
| 缓存字 | signed22+signed22+signed8；原128×52缓存、一遍注册读，无新读口 |
| 能量 | 4个signed25×18分片，原生43bit；两signed45部分和、unsigned44能量 |
| 功率 | unsigned30+signed10；对齐44、求和45、原RNE和floor |
| 结果槽 | 每槽230bit，共460；含字、功率、标志、序号、发起/就绪时间 |
| 注册状态准备 | 686bit加有效/时间65bit；原96bit NCO及64bit计数并行宏 |
| 新增逻辑状态上界 | 2987bit：几何102、私有功率40、能量225、功率609、两槽460、统计512、时钟256、控制32、准备751 |
| 组合定时节点 | 原2510→5497bit，仍4DSP，新增原始RAM和缓存读口0 |
| 另计 | 原查询1689、帧控制2090、RRC/双路径/历史/插值/拟合/译码/TX/MAC/接口 |

旧4096bit节点门下，基线2510通过，新组合5497失败，超1401bit；不改写它。
原2048bit帧控制和16KiB预算失败也保留。
开发前定义的候选增量上限4096bit只是实验规划，不能当作整机已分配或默认采用。
增加约374字节逻辑状态换流水吞吐的取舍需随整机端口/并发继续评价。
逻辑bit不等于综合FF；DSP输入选择网络、96bit比较、宽RNE/加法/计数时序与布线未知。

每个保持符号还包含3次能量加法、1次36bit衰减减法、1次45bit功率加法、
2次44bit操作数规范化、2次44bit对齐/RNE、1次30bit结果规范化、1次下限比较，
以及1次96bit NCO加法和3路64bit包计数更新。保持期除法、开方、三角函数均为0；
正常数据的恢复除法不减少。每符号缓存读1次，私有功率寄存读/写各1，
准备状态需要686bit并行写入/转移，结果槽有一进一出寄存端口。

重叠增加并发要求：某些边沿同时执行两路45bit能量部分和与一路45bit功率和，
故不能把三者当作同一单ALU。另需并行规范化/移位，以及96bit NCO、包计数和统计计数资源。
八路64bit统计、服务时钟、固定地址/信用比较的加法与选择逻辑也存在，未计成零。
原节点的ALU共享布局本就未综合，新并发ALU的增量LUT/时序仍待映射；
目前只证明4DSP在保持/正常阶段排空后的共享，不证明整个算术图无需新增逻辑。

| 结构 | 时钟/存储证据 | 结论 |
|---|---|---|
| 原单信用保持 | 服务18周期；实缓存全就绪32/62字为639/1239边沿 | 基线保留 |
| 仅缓存能量 | 至少新增5632bit，原剩余13×126=1638＞1039 | 仅必要条件估算，未实现，单项不足 |
| 精确流水 | 连续就绪定时结果sink下II6，总计`6N+7`，32/62/126为199/379/763边沿 | 可执行整数/端口模型，非综合 |

实际16MS/s选择窗输入中，FT3/100MHz原在412边沿容量耗尽，新节点379边沿完成；
FT4/200MHz原在1039边沿耗尽，新节点763完成。FT4初始化在100/160MHz的溢出仍在。
该夹具只持续消费定时结果，没有归一化或MAC服务，不是完整包已实时恢复。
正常数据服务仍104周期，加原运输45周期超过200MHz的50周期/符号；四项总验收未关闭。

## 反例与验收

先保存计数溢出后部分提交、未预留注册提交边沿、同边沿银行切换及不支持格式消费上下文
的首版源码和复现，再分别修复。原非法终止标签测试先明确拒绝，再使用已有合法资源原因；
没有扩展原因列表、改载荷答案或放宽CRC。初始化溢出不能标成已验证完整同步状态。

新开发改变FT/MCS/导频/长度、干扰、CFO/SRO、分数起点及实际发送载荷的仿射/XOR字节映射。
变换在独立发送参考成形之前执行，不在接收后修改期待答案。
开发冻结源码/策略后才生成独立保留；旧集合只作固定回归。
每个接受状态、原字及采样轨迹要求与原有限节点精确一致；
相同结果只证明本次结构改动，不覆盖旧RRC2.348%＞2%或插值RMS超预算。
锁定/滑移尚未独立分类时不从CRC或判决残差推为零。

本地真实Python/扩展环境均得到：新开发6→6、新独立保留6→6完整正确，
载荷BER分别0/16768、0/13040；原30请求中的15个交接仍13完整。
另按冻结原件及原选择元数据重放上一阶段12包，仍11完整，原1bit CRC失败保留。
原成功零丢失，接收率增益0；整段/固定/随机回放的字、状态和轨迹相同。
新负例72704/74752采样（16MS/s下4.544/4.672ms）零新增误交付，观察很短，
上游仍是全记录最大值夹具，不据此宣称完整有界捕获或全环境零误检。
独立模拟真值的最大定时误差开发0.184865、保留0.190552采样，与原有限模型相同；
只在决策后计算，不是搜索步长精度，也不套用到缺乏精确真值的真实IQ。
正式61/96未重算，新节点没有Rust实现；扩展环境结果一致不等于该节点获得Rust加速。

`scripts/model_hold_pipeline.py`保存输入、源文件SHA、真实服务记录、CRC/长度/MCS/载荷/BER、
全部失败关联以及两结构的周期前缀。返回1表示四项整体验收仍开放，不能仅凭退出1计通过，
必须核验完整model/manifest及逐项断言。
