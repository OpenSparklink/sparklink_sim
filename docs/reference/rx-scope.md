# 目标窄带接收机的实现与验证范围

本表描述源码实际可运行的配置和已执行的验证，不替代适用标准的合法组合审查。
原始标准已在独立`sparklink-standards`找到，版本/SHA见[标准来源](standard-sources.md)；
FT1的目标配置及新增规范限值仍须逐项核对，不能推测。
优先4Msym/s、SPS4，即16MS/s离线输入。未知起点由接收器选择，真值仅用于事后误差评价。

## 严格浮点流式路径

`MacStreamReceiver` → `PSKStreamReceiver` → 校验头CRC → 读取长度/MCS → 载荷/数据CRC → MAC交付。
FT2普通A2的MCS由协商profile给定；FT3/4的B1从**已校验**头部读取MCS。
理想对齐`rx_chain`保留兼容，不作为本表的流式验收依据。

| 波形/帧型 | 已实现 | 本阶段严格IQ到MAC证据 | 尚未完成 |
|---|---|---|---|
| FT2 PSK/A2 | 未知起点、有界分块、真实头CRC12、载荷CRC | MCS0–12各37字节，导频0/8，两种分块；MCS8/12另有1/2047字节 | 全MCS长度/干扰/量化/整链周期边界 |
| FT3 PSK/B1 | 同上，头CRC24B及LLID；头中读取MCS | 与FT2相同的MCS/长度/分块矩阵，另测接收协商MCS不同仍使用合法B1字段 | 同上 |
| FT4 PSK/B1 | 同上，BPSK同步/头部，载荷按MCS | 同上 | 同上 |
| FT1/GFSK | GFSK模块、整体捕获、A3判决比特严格解析 | 仅既有局部/整体记录；PSK流接口明确拒绝FT1 | 有界未知起点到MAC流式路径、四层模型 |
| WS63 FT2/A3已知变体 | 显式同步字/种子/比特序/导频profile，已有真实IQ固定回归 | 继续引用冻结真实IQ，未混用普通profile | 量化/整链周期和未知编码变体 |

源码MCS表0/1为编码BPSK，2–7编码QPSK、8未编码QPSK，9–11编码8PSK、12未编码8PSK。
本阶段矩阵覆盖这些**配置实现**；未凭缺失的标准原文声明全部FT/速率组合规范互通。
未知厂测编码前缀、UWB、多音不纳入当前窄带完整接收机支持声明。

## 本阶段的冻结试验

`tests/test_receive_scope.py`有104个针对性用例：

- 78组FT2/3/4 × MCS0–12 × 导频0/8；载荷37字节。
  起点分数为`((FT*13+MCS)*.137)%4`，CFO为-25kHz/30kHz，SRO为±100ppm。
  每组比较整段与固定种子440117的随机1–513样本分块，均在EOF前交付。
  头CRC、数据CRC、长度、MCS和完整载荷分别检查；有真值的符号中心最大误差预算0.25采样。
- 12组未编码QPSK/8PSK在三种帧型下的1/2047字节字段边界，导频8，30kHz/100ppm。
- 4组B1实际MCS6/12与调用者配置MCS8不同的接收，验证不能靠调用者预知载荷长度/MCS。
- 三种帧型的6组坏头/坏数据CRC、3组合法头CRC但长度超profile上限，均不向MAC交付。
- FT1明确拒绝作为PSK流式支持，不用跳过或固定成功标志冒充GFSK实现。

独立解析RRC脉冲和角度映射产生RF参考；比特编码仍复用既有发送模块。
因此该矩阵只能补齐严格接收和接口回归，独立标准向量/字段参考仍是另外的验收门，
不能以收发双方共享编码的自回环宣布互通或完整SLE验收。

```sh
RX_SCOPE_EVIDENCE=/tmp/rx-scope-evidence PYTHONPATH=src python -m pytest \
  tests/test_receive_scope.py -q --tb=short --junitxml=/tmp/rx-scope-evidence.xml
```

证据目录按实际IQ/quiet/profile哈希保存独立NPZ、分块轨迹、实际CRC/交付、成本计数。
统计只在接收选择完成后写出，不参与同步或判决。默认CI不需外部IQ或可选Rust；
Python/Rust作业分别执行相同矩阵。原始硬件IQ未被修改。
本轮实际两环境的181个接收臂逐帧/交付/轨迹数组完全一致；
原生整数筛选等后端特有运算计数不同，分别保留，不作为相同硬件成本或吞吐结论。

## 四层验收门与存储限制

[精确定时除法前缀](timing-divider-prefix.md)只改变原数据期除法调度；显式配置、
真实主状态和CRC/MAC门保留。零商前缀检查另计1边沿、64位状态，非旁路104→75；
旧5497→5561仍超4096节点门，四项整体验收及其他数值失败不变。

[同步区归一化重叠](normalization-overlap.md)继续限定同一实验配置，仅改变已选同步缓存的
广播、四信用及有序结果合并；主字/轨迹/帧结果须与H1精确相同，数据期仍串行。
新增归一化状态7825bit及原控制192bit独立计费，不改变FT1缺口、旧数值门或四项整体验收。

[已知同步精确流水](known-sync-pipeline.md)只改变上述实验字接收的计算结构：
普通FT2/3/4、4Msym/SPS4和power30/error32，未扩大配置矩阵。
已选缓存的一遍读取、四信用/两槽、原逐字功率和后续实际Gardner/PI仍明确区分于完整捕获生产者。
定时结果就绪的周期夹具不等于完整IQ到MAC连续吞吐；新组合5497bit对原4096节点门失败，
旧RRC/插值/16KiB及控制2048门保持原结论，FT1/GFSK继续独立补齐。

上述测试只证明浮点严格流式接口。有限相关银行/整数预筛已有结构和定点证据，
其他前端、插值、环路、LLR/译码接口及全链有限调度仍待闭环。
默认最大payload及allowed MCS下，浮点接收器预留的`values/centers/rates/errors`数组为：

| 帧型 | 搜索窗/历史（采样） | 最大帧符号预留 | 四数组字节 |
|---|---:|---:|---:|
| FT2 | 256/384 | 74297 | 2971880 |
| FT3 | 376/504 | 82013 | 3280520 |
| FT4 | 632/760 | 82237 | 3289480 |

这说明浮点模型状态受合法最大帧限制，不表示这些数组可直接映射到原16KiB捕获预算。
后续硬件结构需按码块/符号流消费并单列跟踪诊断、软信息、译码、载荷缓存及端口，
不能把Python容器、浮点数组或包后批处理从成本表隐去。
原200MHz/18路乘法/16KiB捕获对照继续保留；全链资源和延迟尚未通过，未进入发射机阶段。


SYS-C2E1另提供[已选候选的滤波输入端口](selected-frame.md)，支持4Msym/s/SPS4下FT2/3/4
及独立WS63未编码A3上下文，复用本表严格解析，不扩大目标配置或宣称FT1支持。
它的独立功能/分块测试不能代替未知起点捕获、全链定点或物理回放调度。
四项验收状态分别登记在`rx-acceptance-gates.json`，均未完整通过。

SYS-C2E2H1接入[有限符号归一化](finite-normalization-words.md)：同一实际定时字、
40bit NCO、30bit倒数、相邻Q16 ROM系数线性插值及55bit输出，继续共用真实头/数据CRC和MAC。
显式普通FT2/3/4、4Msym/SPS4边界不扩大；新4DSP、3661bit外部状态及1RAMB18单列计费。
真实串行24边沿服务不证明持续16MS/s，残余载波/头/LLR/译码仍浮点或未调度；
旧RRC/插值数值门、16KiB和控制/节点预算失败不被覆盖，四项验收继续分别开放。

SYS-C2E2C-FIT补齐[已选同步区有限初始化](known-sync-word-fit.md)：同一52bit字广播至缓存与32步CORDIC/有界矩拟合，新增1DSP、3247bit状态和2281bit常数；新开发/独立保留各6完整、固定13完整且零退化，初始化数值门通过，但原插值/RRC数值失败不变。实际组合模型保留FT4在100/160MHz溢出，200MHz仅初始化就绪，后续同步功率回放/PI/头/译码周期未知，四项总验收均未关闭。

SYS-C2E2D-HANDOFF补齐[实际已选字流交接](selected-symbol-handoff.md)：复用同一源/缓存/拟合及插值核、原功率/Gardner/严格头/数据CRC；终止归还未消费后缀，未知算术服务显式停住，功能完成不提供总周期。中点优先四字暂存减少约25%源读、数据齐备运输仍45边沿；新1446bit控制和368mux2上界另计，旧数值/16KiB、实时服务、多包/生产者和FT1缺口仍保留。


SYS-C2E2E-TIMING补齐显式实际插值字功率/Gardner误差/PI/NCO及节点周期对照，见[有限定时](finite-timing-words.md)。普通FT2/3/4、4Msym/SPS4新开发及冻结保留各5/6，原13完整保留，增益0；全链定点、实际捕获生产者/多包流、整机资源及16MS/s仍未通过。4DSP/2510bit逻辑寄存新增另计，104周期定时加45运输的当前串行结构拒绝采用；载波归一化/头/LLR/译码未知不填零，FT1及未知厂测变体不推广。

SYS-C2E2F-LIVE-TIMING接入[实际有限定时与查询](timing-service-handoff.md)：同一源/缓存/核上的唯一状态提交，实际三边沿NCO查询及4DSP定时；载波归一化、头/载荷服务仍未知。查询1689bit、控制增量644bit另计，无新原始RAM/源端口或DSP。保留FT4初始化100/160MHz溢出和200MHz已知同步功率2268＞1039必要条件失败，普通FT2/3/4实验不推广FT1或厂测新字路径，四项验收继续开放。
