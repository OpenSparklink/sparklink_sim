# RRC、粗查询、原窗口和细搜索同钟组合（M25，实验）

对应窄带PSK接收实现§6.2.1.2/§6.2.3。此前粗核输出没有原窗口末尾，诊断通过外部事件表找回；
捕获搬运另用周期输入代替实际RRC释放。本阶段复用已有模块，携带原端点并接入真实释放沿。
不改变能量门、差分粗筛、归一化/排序/阈值、全部细搜索相位、等待或Gardner/PI。
不使用CRC、期待载荷或真值选择候选，也不将前缀的细搜索完成计为捕获整包或MAC交付。

## 接口和顺序

`BankedScaledCore(...,preserve_source_end=True)`在两个查询队列槽、一个活动槽和一个候选槽
各保留原端点，查询输入`source_end`必须属于已接收输入，返回沿不重新解释端点。
默认False，原输出、成本和查询周期保持；旧接口不能标识原窗口的反例继续保留。
`CoarseIngress`提供同名编译选项，pending tag+1随查询进入核心，不存主机查找表。
返回的snapshot仍为原意义，不能把较新的snapshot或当前输入位置当成窗口末尾。

`CoarseCaptureSource`接收RRC `(cycle,tag,word/None)`和原检测器`(cycle,tag,bool)`端口，
每个端口每沿至多一个。输入迭代器是台架刺激，仅各持有一个待到达描述符；不是接收机采集缓存。
先消费旧候选，再投递当沿标志/实际RRC字，再推进原粗核；新结果下一沿才可消费。
从返回的原端点及原chosen坐标构造`ReleasedCaptureRequest`，不访问诊断事件表或包位置。

`CaptureTransport.simulate(None,(),source_owner=...,released_requests=True)`显式启用组合，
使用实际RRC脉冲写入原历史、复制原窗并运行原`CaptureFineWorker`，不再替换为均匀输入时刻。
同一沿先取消失效epoch、释放旧结果、提交旧读，再处理真实输入/请求及新复制。
保留单候选端口、三拥有槽、4096点研究历史、原TDP读写规则及全部细搜索成本。
这是实验性单路径46bit/SPS4接口；双路径单音、尾部回放及MAC所有者尚未接入。

源标签缺失、无效输出、上游信用丢失或EOF缺标志使epoch失效，取消尚未交付的拥有槽并计数。
所有后续脉冲仍消费并计入原入口，不重编号、不写零字冒充数据，也不自动重新武装。
故障前已合法完成的细搜索结果保留；故障当沿及之后禁止完成或交付该epoch的新结果。
EOF只排空已有工作，不产生未来样本。非法端口、时间倒退、计数耗尽明确报错。
输入ADC无法背压；槽满、历史失效和源epoch取消分别记录，不用无限队列或静默限流。

## 资源和未建模部分

| 增量 | bit | 依据 |
|---|---:|---|
| 原端点上下文 | 256 | 4×(63端点+1保守有效位) |
| 新源控制 | 1068 | 待到达RRC174、标志128、时钟63、样本上限63、源时限63、closed1、故障时刻/有效64、8×64统计 |
| 捕获源故障控制 | 193 | 一位失效及三个64bit统计 |
| 合计 | 1517 | 低于实现前2048bit增量研究界 |

原M22释放描述符端口242bit另在捕获器计费，不把它或旧粗核/RRC/细搜索状态抵扣。
端点增加63bit查询读选择和63bit接收范围比较，宽线/选择的实际LUT及Fmax未知。
取消清有效位及指针，不清整块RAM；取消扇出和统计宽加法尚未综合。
无新DSP、IQ RAM或采样端口；原已有银行、三拥有窗和共享Y/M继续按真实宽深及端口计费。
原16KiB、RRC2.34835%>2%及插值数值失败保持，不因新元数据相同而改写。

RRC工作由实际`PairRRCFlow`服务轨迹与`FullMantissaRRC`字参考分别验证并计费，
没有把滤波算成零沿；数据值参考和调度刺激不等于新RTL。
单路径专用RRC8DSP、粗核12DSP、含准备细搜19DSP保守相加为39DSP，
不计TDD或跨阶段免费共享。源码模型的总RAM/FF/端口及整机余量须继续分别核对。
原始能量检测算术、载波、头/载荷消费和译码服务仍为未知，不能填零或宣布整链16MS/s。
100/160MHz的RRC过载与缺失保持显式；200MHz、宽加法和RAM延迟是待综合验证假设。

## 冻结验证

新开发及独立节点组合变化载荷族、FT2/3/4、QPSK/8PSK、合法包长、导频、PID、
幅度、CFO/SRO、分数偏移、单音、噪声、突发、强弱变化及错误同步字叠加。
普通profile与WS63厂测配置分开，本阶段不宣称厂测未知编码变体支持。
独立解析脉冲/重采样参考，RRC整段/固定/随机主机分块逐字节比较；内部端口始终至多32输入字。
每流只使用实际存在的最多3072点，不对短采集补零；生成数据与原始IQ目录分开保存。

台架还运行原未携带端点的粗核，在相同物理端口上比较全部查询决定、分数和时刻；
仅新增端点字段不同。每个实际细搜索窗与原来源逐字节核对，不只比较最佳项。
所有请求、完成、资源丢弃、取消和输入脉冲分别记账；同包多窗不当作独立包数量。
独立验证前严格冻结源码、政策和预算。冻结政策必须能原样JSON往返，保留整数键导致
合格开发被拒绝的真实入口反例，修复键表示并保持原通道数及严格冻结检查。

```sh
PYTHONPATH=.:src:scripts uv run --frozen --no-sync python -m scripts.model_coarse_capture \
  --output /tmp/coarse-capture-dev
PYTHONPATH=.:src:scripts uv run --frozen --no-sync python -m scripts.model_coarse_capture \
  --split validation --freeze /tmp/coarse-capture-dev/freeze.json --output /tmp/coarse-capture-held
```

目录必须不存在。预期退出1且必须有正向`model.json`；驱动异常不是预期通过。
这些是前缀结构/周期验证，头CRC、数据CRC、解码MCS/长度、BER和MAC指标仍为未知。
不将它们写成零错误，也不修改正式61/96或原失败集合。完整流式、全链定点、整机资源、
连续16MS/s四项验收保持开放，下一步接入真实合法头和帧末尾消费及全部下游服务。

每流实际前缀3072点，无EOF补零。开发/独立节点每百万采样的粗查询分别25499.13/25553.39，
细搜请求1356.34/1410.59，槽满丢弃379.77/434.03；这是这些短流的观察率，不是最坏上界。
`服务结束`包含`geometry_wait`和`confirm_pending`，不能计为同步确认、捕获成功或完整包。
没有完成头/数据CRC、长度/MCS解码及MAC交付测量，BER、真值定时/载波误差仍未知；
新弱信号收益没有测定，正式61/96及全部压力失败不变。

全部查询决定、分数、时刻与旧编译模式一致；36个实际细搜窗与原样本逐字节一致。
整段/固定/随机主机分块逐字节相同；在真实Rust依赖环境复制原12输入SHA重放，
每集合6个日历JSON及24个NPY成员相同，新组合节点仍为Python模型。
新增元数据不改变算术，增量整数误差为零，不能据此覆盖原RRC与插值数值失败。

最大拥有槽3、源primitive端口峰值2；没有历史过期或源epoch故障，15次槽满均逐项关联输入SHA。
最大观察请求延迟126888沿，按200MHz为634.44us；期间持续ADC约到达10151点，
大于4096点历史。已复制同步窗仍保留，但尚未转移合法帧尾历史所有权，不能据此宣布可交付。
这只覆盖有限前缀后排空，持续密集包/干扰和完整下游吞吐仍待验收。

针对性112通过；全量纯Python5518、Rust依赖5529通过，合并覆盖率各93.85%，
新源节点93.18%。七个分片最大91.415/79.525s，原120s及90.1%门保持。
