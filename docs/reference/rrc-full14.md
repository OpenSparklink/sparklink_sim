# 编译式 full14 RRC 节点实验

本阶段针对 full12 输入表示已经复现的数值损失，比较一个独立的
`Full14MantissaRRC` 节点。普通 FT2/3/4、4 Msym/s、SPS4、当前
81 抽头 β=0.4 RRC 属于实验范围；对应标准 §6.2.1.2 的 PSK 波形，
不把抽头数及格式选择解释为标准要求。WS63 厂测配置保持独立。

## 格式与有限结构

输入实部和虚部各 signed14，共享 signed8 指数，指数范围 [-48,32]；
从原输入执行 RNE，正溢出时重新从原值舍入，不能二次舍入。新类不提供任意
位宽接口，原 full12 API、默认接收器和流式后端的实验限制保持原样。
数字表示不意味着物理 ADC 增加精度，也不意味着增益改善信干比。

系数 C18 不变。signed15 预加法乘 C18 名义产生 signed33；实际固定系数证明
成对乘积绝对值上界 1,034,452,992，小于 2³⁰，中心乘积上界
595,550,208。因此可移除两个符号扩展位，继续使用 signed31 乘积槽，
signed37 累加器、signed19 输出不变。换系数后必须重新证明；构造函数拒绝
不满足当前界的系数集合。

历史、流水和端口按真实宽度计费。节点日历的逻辑状态为 25,460 bit，
相对原 24,900 bit 增加 560 bit；首选 quad LUTRAM 的 raw 存储增加
64 个 LUT6、4,096 个分配原语位，路由选择网络另列。69 位乘积槽、
8 个乘法单元、原端口和队列不变。这些是结构估算，无综合或布线证据。
浮点输入适配器到物理 ADC 的周期仍未建模，不能填零。

## 冻结评价规则

`scripts/rrc_full14_policy.json` 固定数值预算和增量资源预算；新开发集
24 个输入，只有全部通过数值、跨块、范围和成本门，才允许生成独立新保留集
30 个输入。载荷、FT/MCS、导频、长度、幅度、CFO/SRO 及干扰组合一起变化。
任何已查看集合仅作回归；保留集失败后不能据此调参。

全局归一化 RMS ≤0.002、全局相对峰值 ≤0.02、每 64 采样局部相对
RMS ≤0.02、范围事件零，沿用旧预算。输入逻辑 ADC12 控制与任意数字幅度
压力分别记录。整段、固定块、随机块必须得到完全相同的有限字和统计。
80 个 EOF 虚拟零与真实输入分开；同一流保持历史，不在包边界重置。

独立解析脉冲/信道生成输入，独立因果卷积作浮点参照；相关、定时、载波、
CRC、MAC 均未接入本节点实验，捕获、BER 和整包收益不据此计算。
100/160/200 MHz 下的日历、有限历史失效和端口冲突单列，不能用节点
200 MHz 的 II=12 推导完整接收机能承接 16 MS/s。

原输入 `blocks-1` 的 SHA 为
`0e1416d2646719e075ecf9b188df21588114425c7b096ae907cc25b8e1171189`。
其 full12 局部误差 2.3483526%＞2% 的失败继续保留。原 16 KiB
模块预算失败和完整流式、全链定点、整机资源、连续调度四项缺口均未被本实验覆盖。

## 冻结结果与采用范围

冻结单一格式后，新保留集只评价一次；其失败不会用于改选格式。下表各误差均为
该集合的最坏值，旧输入完整保留，数字通过不表示接收交付通过。

| 集合 | full12 数值通过 | full14 数值通过 | full12 / full14 全局 RMS | full12 / full14 局部64 RMS |
|---|---:|---:|---:|---:|
| 新开发24输入 | 24/24 | 24/24 | 0.027279% / 0.007289% | 0.521425% / 0.514583% |
| 冻结新保留30输入 | 30/30 | 30/30 | 0.025729% / 0.006739% | 0.704257% / 0.697146% |
| 已查看固定回归32输入 | 31/32 | 32/32 | 0.025909% / 0.006944% | 2.348353% / 0.688896% |

单独的 `blocks-1` 局部误差由 2.348353% 降到 0.549475%；集合最坏的
0.688896% 来自另一个输入，不能把两者混为同一窗口。86 个输入没有新增数值退化，
未见溢出/饱和事件。新开发和保留的 full12 本来都通过，不能据此计“恢复54包”。
原算法的旧失败结论保持；不同格式通过只计本节点修复，不清除其他旧量化反例。

整段、固定块、随机块的有限字和统计完全相同；真实 Python/Rust 两环境的
860 个 NPY 成员、数值分类及统计逐字节/逐项相同。该 FIR 算术本身仍由 Python
模型执行，“Rust环境一致”不表示 FIR 已移入 Rust，更不表示 FPGA 逐位验收。
独立浮点卷积和对称结构误差均满足原 1e-12 预算。

实际512点有限字端口日历中，quad 映射在200MHz连续输入下无丢弃，最大
延迟60周期；100/160MHz分别丢236/77个采样请求。200MHz输出阻塞实验
丢311个请求，另4个输出因历史过期失效；两槽、单产品读口、慢反馈等反例仍失败。
这些计数是资源请求，不是丢包率。14个场景保存所有端口冲突、失效与丢弃；
合成产品字仅验证RAM通路，未将真实FIR运算逐寄存器接入日历。

采用结论为**保留此有限字节点，供下一阶段显式集成**。当前不增加流式后端名，
不解除其他符号率/SPS/系数的参数限制，不改变默认接收器。所需原语、路由及
200MHz组合路径仍待综合/布线；物理ADC适配、解调、译码等未知周期仍为未知。
必要的TX、译码、实时MAC和接口预留继续沿用整机账本，不能把本节点成本当作整机总量。

该阶段全量测试身份为 Python 5860、Rust 5871，覆盖率93.91%/93.93%，
最长分片88.670/84.283秒；这是工程验证。远端CI必须按对应提交另行核验，
不会用上一提交的CI替代本节点验证。证据中保留最初路径错误和文档toctree警告及修正。

## 重复命令

```bash
PYTHONPATH=.:src:scripts uv run --frozen python scripts/model_rrc_full14.py \
  --split development --output /tmp/rrc14-dev
PYTHONPATH=.:src:scripts uv run --frozen python scripts/model_rrc_full14.py \
  --split validation --development /tmp/rrc14-dev --output /tmp/rrc14-held
```

第二条命令检查开发资格和源码字节；开发未通过时拒绝创建保留输入。
数值/资源失败返回 1，不改成成功退出。冻结证据根下的
`rrc-input14-structure/` 保存初始策略、原失败逐字节重放、输入/节点清单、
源码 SHA、全量测试和采用或拒绝结论。测试通过、节点资格和整链验收分别记录。
