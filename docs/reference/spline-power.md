# 完整增长功率复用（SYS-C2A）

本阶段按标准§6.2.3的已知同步模板，改进[整数细评分](spline-score.md)的计算结构。
只改变能量计算；同步统计、归一化排序、候选数、1/8网格、门限和峰值等待均不变。
`SplineScoreAssumptions(reuse_symbol_power=True)`是显式实验配置，默认仍为`False`。

## 恒等式与数据通路

对完整整数复数`a,b`，`|a conj(b)|² = |a|² |b|²`。
既有相关仍计算四个22×22实乘和差分实虚部；能量改为每符号两次22×22平方，
缓存前一符号功率，再作44×44完整乘积。没有中间舍入、截断、限幅或指数变化。
两个有符号22位分量的功率最大为2^43，采用44位无符号寄存器；乘积按完整增长分片。
原能量、相关、分子和交叉排序的位宽继续保持，不用相关幅度代替归一化排序。
零能量、门限临界值、相同分数的顺序以及最大值仍需未来样本的语义分别验证。

九个前一功率寄存器396bit、当前功率44bit、上下文索引4bit，共444bit。
单共享评分DSP、单端口Y/M银行及原查询/选中向量回放不增加；没有新增采样历史或候选队列。
准备阶段的2个DSP估算仍另计，不虚构跨阶段共享收益。

## 明确原监视预留的打包

原640bit预留写作40×16，既有文档已明确66项可按8bit打包；它容纳80个8bit槽，
存放的是位数计数，不是宽节点本身。原6657bit查询状态不变，复用后7101bit，增量444bit。
现在显式列出66/71个活动节点、80个预留槽和8bit格式，并核验每次计数小于256。
运行中出现未分配节点或计数溢出会报错；新增5个监视器使用原来已计费的余量。

首轮分析错误地把40×16当成只能放40项，误报416bit漏计和524bit增量，
源码/运行/分析及纠正依据全部保留；撤回该解释和预算调整，继续使用原冻结444bit上限。
纠正只涉及成本表示和范围防护，评分/采样/周期结果不变，不覆盖原2%/16KiB失败。
监视器的前导位检测、地址译码、比较/更新LUT/FF及流水时序仍未综合；状态位数不代表总资源。

## 独立节点与固定回归

新开发8例变化FT2/3/4模板、窗口、起点限制、单/双峰、零/常量/斜坡/异常样本、旋转和指数切换。
格式、结构和采用规则冻结后，再产生不同模板、几何和构造组合的8例独立节点验证。
这不是新的射频保留集，不能用它宣称弱信号捕获率提升。
使用独立Fraction样条权重、直接差分平方和核对每个候选分数和采样。
开发中一例准备饱和，两方案均拒绝且保留；该例没有评分，不能计为数值通过。
独立节点验证8例均完成，完整整数结果与基线一致。

再重放上阶段已查看的30个实际窗口，逐个核对冻结输入字和原默认微轨迹哈希；

首轮非法FT3 PID生成器和准备拒绝后错误读取数组的驱动失败均保留后修复，不改期待答案。

## 复现

先按[上阶段命令](capture-fine-integration.md)生成完整`capture-fine`证据目录；该命令预期退出1。
再运行（输出目录必须不存在）：

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_spline_power.py \
  --capture-root /tmp/capture-fine-repro --output /tmp/spline-power-repro
```

同样预期退出1，原因是调度/整机未验收。输出保存每候选轨迹、节点数值拒绝、原件哈希关联、
每时钟资源事件、实际运算与状态成本、开发冻结记录、源码和递归SHA。
CI复用同一作业中已严格校验的捕获窗口，分别运行真实Python/Rust后端并上传失败制品。
新增节点本身是Python整数结构/周期仿真，没有新增Rust数据通路；两种实际后端环境的一致性
不等于该节点已有Rust或RTL实现，也不作为墙钟加速收益。
下一步仍须缩短最坏服务、闭合相干确认和包内回放，而非无限扩展历史。
