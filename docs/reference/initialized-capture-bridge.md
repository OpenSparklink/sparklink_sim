# 实际捕获到有限初始化及合法帧消费

`InitializedCapturedFrameReplay`将实际`FineSelection`、已有交错有限相干确认，
接入[连续初始化与帧交接](initialized-frame-input.md)。对应已核对§6.2.1.2、§6.3、§6.9，
版本/SHA见[标准来源](standard-sources.md)。这是显式实验组合，默认接收器不变。
检测、预筛、细搜评分/网格/等待、9/20相干门、Gardner增益和CRC均保持。
一次候选只有一个答案，CRC不能触发换位置、CFO、相位或重试。

本实验仍用原full12/C18源字隔离消费器变化；此前full14流接口的数值结果单独保留，
没有在本次同时替换RRC。两项组合后的整链结论仍待验证。
有限生产者当前为单路原始RRC源；已验证浮点单音抑制/回退路径未删除，
但尚未把其双路径存储、端口和启停状态接入本有限组合，不能自动计入本次覆盖。

## 状态与样本所有权

```{mermaid}
flowchart LR
 A[持续RRC/粗筛/有界窗口] --> B[原细搜选定唯一答案]
 B --> C[实际有限相干确认]
 C --> D[1024字私有滑动历史]
 D --> E[已有有限初始化/插值/检测PI/归一化]
 E --> F[真实字头CRC/合法长度与MCS]
 F --> G[本包合法帧尾停止请求]
 G --> H[载荷参考或未建模服务退出]
```

复用原全局帧读取端口，一沿最多一个注册读回执。开始只复制选定同步四点插值
实际需要的过去/未来样本；初始化期间不复制后续采集。随后按实际查询前瞻
最多增加8字预取；当前可信边界最后三个符号禁止额外预取。
头通过前以头尾为界，真实CRC和合法长度/MCS通过后才取得实际帧尾。
三个最小合法NCO步长仍超过9采样，单独验证，不调整环路参数。

注册回执通过既有输入接口只写一次，更新输入统计。全局、私有索引和退休前沿分开；
事件分别报告`copied_source_end`和`consumed_source_end`，预取不冒充已消费。
原4096字源、捕获窗和选定缓存仍预留。每个实际时钟沿推进，不跳过工作。
坏头/非法长度/MCS退出且不交付；EOF排空已接纳工作，无样本时报告截断，不补零。
源过期、故障、取消及有限缓存丢弃明确留证。阻塞不公开头/载荷，内部有限工作可继续。
先取终止回执，再释放令牌；包间复位初始化/跟踪状态，保持全局已消费前沿。
单选窗口坐标仍限2²⁰采样，长期坐标重定位尚未完成。

## 初始化失败：释放不等于消费

后续失败清理复核发现：初始化拟合失败会清空整个借用RAM，桥却把清理后的
`history.head`作为全局已消费前沿。预取后缀没有进入插值/头处理，这会错误抑制
落在该后缀内的后续候选。现在`InitializedFrameReplay.consumed_history_end`复用
已有`initial_discarded_words`计数，在初始化失败时由`end−discarded`重建真正前沿；
正常初始化及帧内处理仍使用原历史退休边界。私有RAM照常释放，不重试任何同步答案。

接口故障注入保留已选同步缓存，但把原始回放口替换为零，因此只验证失败退出，
不算作合法无线捕获实验。原反例复制末尾2370，实际消费1346，原错误跳过1024字；
修复后报告1346，未处理后缀仍可用于后续候选。FT2/3/4分别验证空缓存清理、
无头CRC/数据CRC/MAC、后缀候选不被退休门拒绝及取消后前沿不再增长。

新增成本为失败路径上最多一次64位减法及选择，复用已有注册前沿和丢弃计数，
没有新增持久状态、RAM、DSP或端口。组合映射和Fmax仍未知；不将此清理修复计为
16MS/s证明或弱信号恢复收益。四项总验收、原full12数值失败及旧资源失败保持。
冻结证据`initialized-abort-frontier`保存原失败/修复回执、源码SHA、重放和完整验证。

原M37固定回归10流/12合法包的全部无线字段、轨迹、输入字、端口和丢弃统计精确
保持；原参考仍8完整，新实验桥仍3完整，没有新增恢复或原成功丢失。只新增单列的
失败前沿成本字段，不改动期待答案。负例仍为32768采样的有限观察，不外推绝对零误检。
115项相关测试、26项账本测试通过；Python全量5954通过/38明确跳过，Rust环境
5998通过/5明确跳过，两者覆盖率93.93%，最长分片60.497/56.790秒。
两种实际后端保持全部原测试身份，新增3项故障清理反例；新服务本身不是Rust内核。
正式旧61/96未重测；这项修复不改变实验桥未采用及四项总验收开放的结论。
