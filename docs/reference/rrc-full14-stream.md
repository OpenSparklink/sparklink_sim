# full14 RRC 的严格流式集成实验

本阶段复用已通过节点数值验证的 `Full14MantissaRRC`，增加显式
`rrc_backend="word-full14-c18"`，接入原有 `PSKStreamReceiver` 和
`MacStreamReceiver`。默认 `reference` 和原 `word-full12-c18` 不变。
只改变 RRC 输入表示，不更换同步评分、搜索网格、Gardner/PI、载波或译码参数。

## 支持边界与处理状态

当前编译格式仍限 4 Msym/s、SPS4、81 抽头 β=0.4。关闭静默跳跃，持续
执行同一前端；不同速率/SPS 或跳过滤波的组合继续显式拒绝。此限制是实验边界，
不是标准要求。扩大配置须重新验证系数、误差、延迟、环路和调度。

本阶段目标为普通 FT2/3/4、MCS8/12、导频0/4/8/16。使用实际同步模板、
40/48/64符号前导码及普通 A2/B1 头上下文。B1 的11位长度包含数据CRC，
因此 CRC24/32 时最大载荷分别为2044/2043字节；A2 最大载荷2047字节。
旧 legacy B1 证据仍按其原契约读取，不能重标成标准帧。

标准依据为 §6.2.1.2、§6.3、§6.4.1.3/.4、§6.4.2.2.2、§6.9及§6.10；
原始版本/SHA 见[标准来源](standard-sources.md)。独立角度映射和解析脉冲参考仍
复用了已有比特编码器；不能把该自回环当作唯一互通证据。

| 环节 | 本路径实际处理 | 定点与周期状态 |
|---|---|---|
| 输入/RRC | signed14/8指数、C18、乘积31、累加37、输出19 | 有节点有限字和依赖日历；物理ADC适配、实际寄存级结合仍缺失 |
| 检测/粗相关 | 复用持续能量检测、scaled10相关及原预筛 | 复用既有结构，原动态范围和资源缺口不消失 |
| 单音处理 | 复用既有因果抑制和原始/抑制双路径 | 两条历史及相关银行都计费；此入口仍有浮点处理 |
| 细搜/定时/载波 | 原8相位评分、Gardner/PI和原载波细化 | 不把其他独立字/周期模块的通过转移至本入口 |
| 头/载荷/交付 | ordinary字头后端、真实头CRC、合法长度/MCS、真实数据CRC、严格MAC适配 | 该入口直接调用服务，未接入全部正延迟日历；载荷仍有浮点解映射 |

WS63 A3 的已知无编码合成回归单列，保留显式同步字、CRC和头中MCS语义。
没有给未知编码前缀去前缀或改参考答案。其他MCS尚不据本实验增加支持宣称；
FT1/GFSK 完整未知起点路径仍是独立缺口。

## 跨块与资源

同一流只构造一个 RRC 实例，80点历史跨包保持。流式 EOF 复用原42个
未来零采样后封闭，不额外调用 standalone 的80零冲洗。整段、固定257和
Philox随机1..509分块必须保持实际有限字、事件、载荷及采样轨迹完全一致。

单音选项本来就保存原始和抑制两条搜索历史。首次测试辅助器误用了单路径
缓存式，原始41项失败已保存；浮点/full12/full14诊断均为每路径384点、
实际总峰值905点。修正为逐路径检查同一上限，并按
`2*history_limit +80 FIR +31 energy +(quantum-1) pending` 计总量，
未增加接收历史或原相对预算。不同帧型的同步长度决定各自原有上限。

节点增量沿用已冻结的560bit和64个raw内存LUT，乘积槽、DSP、端口及队列不增加。
这里是静态编译格式选择，不宣称逐包动态切换硬件格式免费。双路径、码块、
解调、头/载荷服务、TX/MAC和接口仍按整机账本另列；未知周期保留为空，不能填零。
100/160/200MHz的RRC日历不是整链16MS/s结论，更不是综合或布线证明。

## 验收规则与证据

新开发29流（24正例、5负例），包含28个合法包；新保留35流包含35个合法包。
变更载荷、FT/MCS、导频、包长、幅度、CFO/SRO、分数起点和干扰组合。
每批负例40960采样，仅2.56ms@16MS/s；零新增误检必须附这个有限观察量。
密集包间隔属于捕获压力，不单独证明MAC/TDD间隔合规。

三臂只改变RRC：浮点RRC、full12、full14，后续配置完全相同。
输入/期望内容/真值在接收终止后才用于归因，接收函数不接受它们作为选择依据。
CRC、合法长度、期望MCS、完整内容、BER和交付分别记录；CRC失败但内容无误
仍为失败，未编码单比特错误也不能计恢复。

实际 RRC 输出端口通过只读副本观察，并与独立因果卷积比较原预算：全局RMS
0.002、相对峰值0.02、局部64点RMS0.02、范围事件零。实际输入上的数值失败
不会被相同整包结果覆盖。原full12的2.348%失败及原16KiB失败仍保留。
完整诊断数组属于调用者保存的离线证据，不反馈接收决策，也不把这些日志当作
硬件缓存。仅凭此仪器化路径不能证明整机内存或实时吞吐。

真值定时误差记录包头/中间/包尾和首次连续64符号≤0.25采样的窗口；
周期索引变化是相对解析真值的诊断量，原环路锁定状态仍为未分类。
PI状态与注入ppm的差、同步/载荷后CFO误差分别报告。未单独核对增益/相位
参考约定，不把判决残差写成真实载波相位误差。输入位置延迟也不是硬件计算周期。

仅在新开发门及原88流/64包固定回归均通过后，才允许生成独立新保留集。
原始输入按冻结元数据和SHA读取，不换被覆盖索引。保持浮点和full12原成功不丢失、
负例无新增候选、无误交付/重复，起点差≤0.125采样、轨迹差≤0.25采样，
历史/帧容量不变。失败后拒绝采用，不在该保留集上挑其他格式或参数。
压力样本剩余失败保留，诊断失败不等于理论不可恢复。

```bash
PYTHONPATH=.:src:scripts uv run --frozen python scripts/model_full14_stream.py \
  --split development --output /tmp/full14-stream-dev
```

新保留还需显式提供开发目录和合格固定回归回执。冻结证据根
`rrc-full14-stream/` 保存基线、策略、逐输入SHA、三臂三分块实际轨迹、
漏检/误检/CRC/数值/采用失败，以及工程验证与提交绑定。全部四项整机验收仍分别未完成。

## 冻结评价结果

源文件、算法、格式和采用规则在独立新保留生成前冻结，未根据该集合重新调参。
下表各行的浮点/full12/full14具有相同包判定；固定回归按原88流的逐输入SHA
复核，它不是此前另一个51/35集合，也不替换正式61/96记录。

| 集合 | 合法包 | 捕获 | 头CRC/合法长度/期望MCS | 数据CRC/完整正确 | 剩余失败 |
|---|---:|---:|---:|---:|---:|
| 新开发29流 | 28 | 23 | 23 | 17 | 5漏检、6数据CRC失败 |
| 固定回归88流 | 64 | 57 | 56 | 39 | 7漏检、1头CRC、17数据CRC失败 |
| 独立新保留35流 | 35 | 28 | 28 | 22 | 7漏检、6数据CRC失败 |

整包增益为0，原浮点/full12成功包零丢失。不能将这个结论扩大为所有数值或BER
都无退化。仅在已解析且可比较的载荷上，错误比特/比较比特分别如下；漏检和
未解析载荷未按零错误计算。

| 集合 | 浮点 | full12 | full14 |
|---|---:|---:|---:|
| 新开发 | 581/25472 | 582/25472 | 581/25472 |
| 固定回归 | 2328/98400 | 2327/98400 | 2329/98400 |
| 新保留 | 2759/53416 | 2760/53416 | 2760/53416 |

开发`tone-2`从3错降至2错，仍为CRC失败；固定回归`tone-1-1`从full12的39错
增至41错；新保留`burst-1`相对浮点从449错增至450错。上述增减不改变失败
身份，均附输入SHA、实际候选、采样轨迹及载荷证据，不宣称恢复。

| 实际RRC端口最坏误差 | 新开发full12/full14 | 固定回归full12/full14 | 新保留full12/full14 |
|---|---:|---:|---:|
| 全局归一化RMS，% | 0.039743 / 0.010544 | 0.114481 / 0.028975 | 0.167266 / 0.041709 |
| 局部64点RMS，% | 0.525773 / 0.508257 | 0.179238 / 0.045452 | 0.519087 / 0.500168 |

本批实际端口的三项冻结误差门均通过、范围事件为零；这不重写先前full12的
2.348%＞2%反例。全局误差约下降4倍，局部低能量区改善较小，未换算成接收增益。

152流在真实Python/Rust环境重放，包判定、载荷、BER、漏斗和实际有限字一致；
新开发/保留三分块的浮点轨迹也逐字节相同，固定回归的1512个已记录数组成员相同。
同模式整段/固定/随机分块保持同一状态和轨迹，不重置包内环路。
两批新负例各40960采样（各2.56ms）中零候选、零误交付；观察时长不足以证明普遍误检率。

三批共49个剩余失败逐包保存在`FAILURE-LINKS.json`；其中1项有错误减少但仍失败，
其他48项尚不能分离同步、环路与样本损伤。没有对本批做真值重放，因此不宣称
它们理论不可恢复。`BIT-ERROR-CHANGE-LINKS.json`单独保留比特退化，不能被整包相同覆盖。

采用结论只限显式实验入口的功能和RRC节点数值集成。原默认、原误差门和
原16KiB资源失败不变。节点逻辑状态24900→25460bit、raw LUTRAM估算512→576，
8DSP及端口不增加；该增量不能取代整机账本。RRC日历II12，200MHz可承接本节点
输入；100/160MHz和下游阻塞的有界丢弃仍保留。其余解调/载波/LLR/译码工作没有
完整周期绑定，不能从节点结果推出整链16MS/s。

工程全量Python/Rust分别5912/5923个测试身份，覆盖率均93.93%，七片最大
103.546/99.301秒，原测试身份全部保留。可选依赖等跳过单列于JUnit。
这与算法、资源和硬件验收分别记账；完整流式目标范围、全链定点、整机资源和
连续16MS/s四门均未关闭。FT1/GFSK未知起点流式仍缺失。
