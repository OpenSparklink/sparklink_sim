# 有限样条查询与完整增长同步评分

SYS-B3C2延续[准备节点](spline-flow.md)，对应标准§6.2.3接收同步实现选择。
显式模型保持18/22/14格式、全部样条RNE、每峰九相位、最多两峰、间隔4采样、
原相位优先的平局次序和最强峰等待未来样本规则。默认接收器没有改变。

## 数据通路和数学依据

`SplineScoreFlow`直接继续使用准备控制器的同一组Y/M单端口银行。
原始输入仍为19+19+8；显式18位对齐端口带公共指数，只用于与旧浮点边界的数值集成，
不能把对齐装载周期当作完整输入转换成本。每个运行只拥有一个最多640点窗口。

一个整数峰附近的九个相位，在每个符号位置最多共用三个Y和三个M字。
比较逐相位四字读取与六字共享，所有CSD、舍入和评分运算完全相同。
SPO银行每周期一个读写地址，注册读延迟1/2，最多四个在途读信用；冲突及信用不足等待。
读延迟2的首轮曾出现6个在途读，现用四信用限制保留原断言，首轮源码和失败仍归档。

实际profile同步模板按规定交替旋转生成。FT2差分模板可用两个±1分量及公共因子表示，
FT3/4使用轴向±1；公共因子在归一化中抵消，不能用期待载荷或CRC选择模板。
不属于同能量轴向/对角字母表的模板明确拒绝，不近似虚构支持。

设插值字为复数整数y、差分d[k]=y[k]conj(y[k−1])、模板差分字为s：

- C=Σd[k]conj(s[k])，E=Σ|d[k]|²，R=Σ|s[k]|²。
- 归一化平方分数为N/(ER)，其中N=|C|²。
- 排序比较N₁E₂和N₂E₁，共同R抵消；零能量对应零分，比较分母取正。
- 既有0.85诊断门限以17/20输入，比较400N和289RE。常量积执行移位加法。

门限与排序独立核对，不以相关幅度替代归一化排序。无运行时除法、开方或三角函数。
报告显示分数、相位及现有浮点相干确认桥接仍可用浮点；它们不是已完成的定点相干接收链。

完整增长格式使用45位差分、最多53位相关、98位能量、107位分子及206位排序中间结果。
每个宽积都拆成正24×17有效位的乘积，装入一个有符号25×18 DSP原语（[AMD UG953 DSP48E1](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/DSP48E1)）；
负号、幅度、部分积累加及超宽加法分别计费，不把宽主机乘法当作单DSP一拍。
微操作模型采用DSP延迟3、32位ALU分段延迟ceil(width/32)；这是可执行宏调度假设，
不是每个进位寄存器的RTL，也没有200MHz综合或布线证明。

每峰保存九个上一符号、相关和能量上下文，第二峰顺序复用；不保存18×128个候选向量。
排名完成后只重放选中相位一次，重放的读取和CSD也计入。输出阻塞保持当前字，
超出有限诊断时限显式中断，不退回功能模型。中断后的跨窗口排空/重新分配仍须整合到拥有槽控制，
本节点不声称已证明该生命周期或ADC实时背压。

## 冻结验证与保留失败

开发和独立验证均改变载荷、FT/MCS、PID、导频、合法长度、分数偏移、CFO/SRO及干扰组合，
不是只更换随机种子。六种开发字输入比较两种读取结构，冻结共享方案后评价六种新字输入；
直接Fraction样条权重和有理数评分作为独立字值参考。

| 新集合 | 捕获/合法包 | 头CRC | 数据CRC/完整正确 | 可算载荷错误bit/bit | 负例样本 |
|---|---:|---:|---:|---:|---:|
| 开发，旧/新相同 | 8/8 | 8 | 6/8 | 56/13120 | 56278（3.517ms） |
| 独立验证，旧/新相同 | 8/8 | 8 | 7/8 | 918/19712 | 81834（5.115ms） |

上述负例中均无候选及误交付；观察量很小，不能推断所有环境绝对零误检。
BER是可计算的译码后载荷bit错误，编码/未编码的配置分别随帧保存，不是统一原始信道BER。
开发dev-6仍错53bit、dev-7错3bit；validation-6错918bit，均保持数据CRC失败。
这些样本未作独立真值载波重放，不能仅凭本次结果断言理论不可恢复。

整段、固定257点和随机块的主接收轨迹对照通过；旧tone单包固定回归保持完整正确。
这是一个旧成功输入，不冒充旧96包或真实厂测全部回归。新方案未推广默认配置。
源/导数字、整数平方分数与独立参考一致，正常数值接收对照无额外量化损失或接收增益。
首次验证后所有输入冻结；后续只按原清单SHA重放，不在该集合挑选参数。

首轮报告因`truth/cfo`与公共诊断接口的`sync_start/cfo_hz`字段名不一致，漏算BER及真值误差。
保留首轮文件和源码，后续仅补后验字段别名并按原SHA重放，未改变原始输入、载荷、算法或参数。
接收决策、采用规则和通过率不使用这些真值字段。零计数且分母为0的首轮结果不解释为零BER。

另保留一个明确数值兼容失败：极小表示幅度下，旧浮点1e−30分母下限使分数接近0，
整数尺度无关统计仍为1，分数差超过原0.005预算。该点只说明原表示/归一化不一致，
不是可恢复RF包或额外ADC精度证明；不能用整包相同覆盖它，不能将新评分器升为默认。
原RRC2.34835%>2%、16KiB、原低SNR和初始化退化记录亦未被清除。

## 成本、取舍与16MS/s限制

| FT2，256点/32同步符号/一峰九相位 | 逐相位读取 | 共享读取 |
|---|---:|---:|
| 查询及选中相位重放读取 | 1184 | 320 |
| 算术操作 | 相同 | 相同 |
| DSP25×18部分积次数 | 6222 | 6222 |
| 包含原始扫描/准备的服务周期 | 63599 | 63119 |

共享读取下降约73%，服务周期只下降约0.75%，不能将读取减少直接说成吞吐提升同等倍数。
选定服务含1543周期准备、选中向量重放和归一化排名/门限，不含相干确认、包内环路或译码。

每引擎额外状态保守预留6656bit，包含九上下文、模板、缓存、宽ALU/部分积、
输出字、控制和监视；准备状态5210bit没有免费扣除。FT2银行320个内存LUT、完整640容量1280个，
仍分别计入整机账本。每次模型保存实际操作数量、节点声明/观察位宽、读取、周期和阻塞。
66个观察位宽字段可在640bit监视预留中按8bit打包；声明位宽是配置常量，控制与选择器逻辑尚未综合。

选中相位的重放成本不同；该固定FT2候选几何的一峰服务上界为63759周期，
另外单列两峰成本，不能把63119这个实例当作全配置最坏值。
串行方案按63759周期投影，在100/160/200MHz、121次每32输入点请求的压力下均丢弃118次，只完成3次。
这是规定请求压力，不是已经证明真实干扰总会生成该请求率；实际前端事件时间线尚未联合。
按200MHz每请求400周期的压力预算，63759周期至少需160份这种串行服务能力，
不能据此把158个引擎免费添加到整机。译码、TX、实时MAC/AES/DMA及端口/寄存器仍有未分配成本。

结论分开记录：共享输入读取作为等值结构保留；完整增长、单DSP/32位ALU串行评分结构
因吞吐与存储复制成本拒绝用于目标连续链。它不是硬件不可实现性证明。
下一步应依据观察位宽研究紧凑的差分/能量表示及流水并行度，优先复用已有有限字归一化思想，
在新开发集上冻结再验证；不削减九相位、不放宽0.005/0.125预算来迎合当前集合。

## 复现

```sh
PYTHONPATH=src UV_CACHE_DIR=/tmp/rx-uv uv run --frozen --no-sync python \
  scripts/model_spline_score.py --output /tmp/sle-spline-score
```

目录须不存在，预期退出1。输出含冻结前protocol、selection、输入/元数据、所有帧与错误、
独立字参考、微操作轨迹、平方归一化反例、资源队列失败及递归SHA清单。
冻结证据根`spline-score`还保存首次验证、报告修正、独立后端重放及实际CI制品。
要重放已经查看的原输入，可显式指定`--frozen-inputs`及`--manifest-sha256`，
验证整个原清单后读取原文件；不可换用新数据集索引。纯Python与Rust环境分开记录，
本节点为Python结构模型，现有Rust路径没有独立实现这个新评分核。
