# 候选返回时刻与原搜索窗口（M22，实验接口）

本阶段补齐普通PSK接收结构（§6.2.1.2/§6.2.3）的一个搬运接口缺口，
不改变同步评分、门限、候选数量、网格或CRC选择。沿用现有窗口、细评分和尾部模型，
不恢复已拒绝的三槽整段尾部保存方案，也不新建IQ缓冲。

## 为什么需要两个坐标

旧`CaptureRequest.after_samples`同时决定请求到达和源窗口末尾，适合原零调度延迟台架。
M21已查看的固定回归中，16个启用候选返回时，RRC又释放了14..16个采样。
继续用旧末尾入场会在候选尚未返回时开始复制；改为最新计数则取错窗口。
独立递增字反例分别保留了提前入场和整窗后移11字的失败。

`ReleasedCaptureRequest`保留`after_samples`为原窗口末尾，另要求关键字`available_cycle`，
只在`simulate(..., released_requests=True)`显式启用。当前台架仍使用均匀16MS/s滤波字到达；
它尚未连接实际RRC释放脉冲、粗查询所有者或完整帧所有者。

## 准入、所有权和退出

每个时钟最多一个请求脉冲，时间严格递增，源末尾单调。请求返回时源窗口必须已经到达；
同沿多请求、非因果源端点和超出有限实验时域的时间作为接口错误拒绝，不在主机迭代器中偷偷排队。
输入刺激的有限时域/源就绪检查是台架预检，不是已实现的物理异常检测器。

请求只在自身真实返回沿入场。复制仍读取原端点之前的固定窗口，不压紧样本、补零或改取新窗；
之后采用原历史过期和拥有槽满退出，ADC继续输入。EOF后仅使用仍然保留的原样本。
释放时间在准入后死亡，向细搜索传入原`CaptureRequest`几何，拥有描述符不保留第二份时间戳。
CRC、期待载荷、真值包起点均不参与准入、候选选择或失败重试。

默认端口保持旧事件/结果/成本结构。两个模式不能混用描述符，避免没有计费却使用新端口。
源码归档的27个旧时钟/几何/端口/阻塞对照逐字与逐事件比较；这是接口回归，不能计为新RF收益。

## 有限成本

实现前冻结256bit新端口研究界：一个179bit待入场描述符，加63bit前次返回时钟，合计242bit。
包含原源末尾63、返回时间63、路径1、峰数量2、两个峰20、最小tick13、前瞻16和有效1bit。
两个63bit时钟比较及既有请求计数非零检查另计，组合LUT/时序未知。
没有新IQ RAM、DSP、源/目标RAM读写端口或拥有槽；既有搬运12BRAM研究界不变。
时间字段在释放后不继续收费或免费隐藏在每个拥有槽中。

这只是接口的增量账本，源历史、复制/评分工作RAM、查询队列、单音双路径、RRC、解码、
TX、实时MAC、DMA和基础工程仍分别计费。它没有解决整机FF预留冲突，也没有批准新系统预算。

## 仍然存在的细搜索瓶颈

同一只读审计把原整数候选送现有细评分，FT2/3/4单请求分别63759/117738/230418沿。
200MHz、持续16MS/s假设下，期间至少再到5100/9419/18433采样，尚不含复制、排队、确认和回放。
入口每32采样可提出查询；若持续启用，三个服务时间远大于400沿到达间隔，不能用有限FIFO解决过载。
`needs_future`或`confirm_pending`也不能算捕获成功；本阶段没有调度相干确认。
该审计只使用原SHA与实际同步模板，不含真值或CRC选择，不是新的保留集验收。

单纯修正窗口坐标不会恢复这些资源丢弃。下一步应在原起点/评分预算下研究细搜索复用或服务结构，
保留旧局部四次搜索起点超预算反例，不能直接采用被拒绝方案或无限扩大历史。
当前四项总验收仍分别开放，原RRC/插值数值失败、16KiB失败和正式61/96不被改写。
100/160/200MHz均为模型条件；没有新增FPGA综合、布局布线或完整16MS/s证据。

## 复现接口反例与回归

```sh
uv run --frozen --no-sync pytest tests/test_released_capture.py tests/test_capture_transport.py \
  tests/test_capture_fine.py tests/test_capture_tail.py -q
```

测试覆盖源未就绪、晚到、EOF、过期、路径、拥有槽满、非法时间及三种几何/时钟；
实际接收能力、全链定点和真实粗/细/帧交接仍需独立验收。

## 本地结果

新增28项，相关四模块104项通过；两真实依赖环境全量5439/5450项且原用例全部保留，
覆盖率93.82%/93.83%，本模块98.59%。27种旧默认时钟/几何/端口/阻塞的结果、
全部字、事件与成本精确；准入、过期、槽满及EOF反例均明确计数。
端口242bit满足实现前256bit研究界，默认RF未修改或重新宣布收益，四项总验收仍不通过。
实际CI和物理时序必须另行核验。
