# 实际有限定时与查询服务交接

SYS-C2E2F-LIVE-TIMING沿用[有限定时节点](finite-timing-words.md)，对应已登记标准
§6.2.1.2的PSK实现、§6.3帧结构和§6.9 CRC。没有改变同步评分、候选、网格、
Gardner/PI增益、载波方法或实际profile。普通FT2/3/4、4Msym/s、SPS4仍为实验范围。
FT1/GFSK、新WS63字路径和整机四项验收均未据此宣布完成。

## 一个状态所有者与实际值路径

`FiniteTimingFrameReplay`复用原`SelectedFrameReplay`的源、注册缓存、插值核、
真实头/数据CRC及MAC交付，不复制整段尾部，也不重新搜索或拟合同步。
默认接收与旧回放接口不变；新类要求显式`TimingWordFormat`。

```{mermaid}
flowchart LR
  NCO[有限NCO状态] --> Q[三边沿查询服务]
  Q --> C[注册同步缓存或源历史与插值核]
  C --> T[实际DSP与恢复除法定时服务]
  T --> B[显式载波校正及归一化服务边界]
  B --> H[头CRC与合法长度MCS或载荷CRC边界]
  H --> NCO
  H --> M[完整合法帧交付MAC并归还未消费后缀]
```

`claim_timing_state()`只允许包开始前取走一次状态，之后功能版`push_symbol()`关闭。
实际`TimingWordService`提交状态后，`accept_timing_result()`只执行原浮点归一化/存储，
不再调用功率/TED/PI/NCO方程。结果计数必须恰为已存符号数加一，原字与已提交字必须一致。
重复、缺失、错误字、未观察到未来采样或严格头/载荷边界未处理时明确拒绝。

结果已提交但归一化尚未执行时，定时计数可比已存符号多一。它是有界在途状态，
不是重复接受；资源终止时分别保留两者，不回滚或伪造一个完整符号。
正常排空用`release()`，有在途工作时用`abort()`，正常释放不计为工作取消。
包间重新创建状态；多包捕获生产者和仲裁仍未接入。

## 查询与样本完整性

`TimingQueryService`只采样稳定的有限状态，不调用功能版坐标属性：

1. 锁存96bit当前/前一坐标、64bit计数，计算97bit中点和。
2. 整数拆分与最近偶数舍入，输出64bit格点、17bit相位（0..65536）和未来样本界。
3. 计算下一组实际插值依赖的历史退休界，注册并保持回复，等待唯一接收。

相位端点65536继续使用原核约定，不更改相位网格。未来界与原`ceil(current+3)`等价，
中点由两坐标之和直接在33位小数上舍入，不经过binary64。独立Fraction测试覆盖半LSB、
端点、零索引及大于2^60的节点坐标；大坐标节点测试不扩大原已选端口的1Mi采样限制。

查询回复携带状态计数；过期回复在发起插值或定时之前报错。同步缓存读之前核对实际查询
与封存缓存的格点/相位。原源银行仍1R1W，四字暂存和中点优先复用不变，EOF不生成未来字。
已校验头决定合法帧末尾；坏头不进入载荷，终止释放实际已读前缀，未消费后缀仍留在原银行。

首版观测回调意外得到活查询对象别名，且缓存匹配校验误放在非符号分支。
故障注入证明回调可令描述相位24576变24577，同时仍接受原缓存请求；普通帧回归未覆盖它。
修复保留原输入与源码，向主机回调提供深拷贝并将匹配防护放在实际缓存请求之前。
诊断回调不能控制接收答案；主机观测副本不算已实现的FPGA跟踪FIFO。

EOF可在下一查询已经完成、其未来采样尚未到达时结束。此时查询数比提交符号数多一；
额外查询没有产生完整符号，截断和空载荷仍保留为失败。首版诊断驱动误要求二者相等，
已保存448已提交/449已查询的同帧同轨迹反例。修正只允许显式截断时最多一个未提交查询，
其余帧、原字、轨迹和状态精确检查不变，未放宽CRC或完整载荷要求。

## 周期证据与未建模服务

每个运输边沿同时推进插值、定时和查询服务，时钟失配立即报错。输入信用、保持回复、
正常释放、取消、EOF和源耗尽均显式处理。功能归一化/头/载荷调用永久使整链周期证据失效，
完整延迟始终`None`；每个已建模服务的自身延迟和实际值仍可独立验证。

归一化包含原载波旋转/增益处理；头/载荷还包含原载波细化、软信息、译码和CRC。
这些工作的实际周期仍未知，不能用CPU返回时间或零周期替代。
服务观测同时记录局部服务延迟与全局历元是否仍有效，避免把功能回放的累计边沿冒充ADC延迟。

100/160/200MHz连续16MS/s前缀测试不执行任何未知服务，明确停在归一化边界后继续供给输入。
FT4在100/160MHz先发生初始化历史溢出；其他可交接情景在下游保持阻塞时有界终止，峰值512字。
这些是阻塞压力下的资源终止，不能计为评分算法漏检或数据CRC失败。

对当前退休规则，已知同步回放期间尚不能越过初始保存的最后两字：
FT4/200MHz初始化后剩1039边沿，126次实际功率服务自身下界2268；FT3/100MHz为412对1116。
这个必要条件尚未包含缓存、查询、控制或未知服务，只能拒绝当前串行结构，不能证明所有结构不可行。
后续优先比较同步功率复用及反馈/运输结构，不增加无界尾部缓存，不放宽旧16KiB失败。

## 增量成本与验收边界

| 项目 | 本阶段逻辑/运算估算 | 限制 |
|---|---:|---|
| 查询服务 | 1689bit寄存上界，0 DSP，0原始RAM/源端口 | 三宏边沿，97bit加法及64bit比较/加法假设1边沿 |
| 控制器 | 原1446→2090bit，增量644 | 9个64bit统计、64bit历元与4bit控制；不免费忽略 |
| 实际定时 | 沿用4 DSP、2510bit，保持18/正常跟踪104周期 | 没有与其他模块共享收益 |
| 缓存请求防护 | 64/17bit比较各1、移位和64bit加法 | 与注册请求同边沿的宏假设，组合时序未验证 |
| 源/缓存/插值/拟合 | 沿用各节点估算，单独记账 | 不把逻辑容量直接当物理BRAM，不重复或漏计 |

查询各级257/258/291/355bit、时标/控制/统计528bit分别计费，合计1689bit。
三边沿输出后立即取回复仍需一个信用冷却边沿，最小II4。正常定时服务的II105不变。
上述逻辑位不是实际综合FF/LUT，宽运算与200MHz布局布线均无新证据。
新增查询与控制相对前一阶段合计2333bit；原定时、原缓存/插值/拟合及RX/TX/译码/MAC均另计。
新控制器2090bit还超过原控制器2048bit上限42bit，该旧预算失败明确保留。
新阶段在波形前冻结的查询2048bit/控制增量1024bit只是实验成本规划，不撤回旧控制器上限，
也不是已批准的整机预算。不得把功能交接过门解释成该资源门通过。

四项门继续独立：完整流式还缺实际捕获生产者/多包/FT1；全链定点还有旧RRC/插值数值失败
和载波/归一化/LLR/译码；整机端口并发和连续16MS/s仍未闭合。普通与厂测profile不混用，
未知厂测编码前缀不剥除。没有新增综合、时序或设备证据，默认配置不推广。

## 本阶段功能与接收结果

新开发6包：头CRC/合法长度/MCS均6，数据CRC/完整5，载荷BER为1/16224。
剩余FT4/MCS12、509字节、单音叠加突发包错1比特，仍完整失败，不据诊断失败断言理论不可恢复。
冻结后独立新保留6包：头CRC/长度/MCS/数据CRC/完整均6，BER0/18880。
这些结果与同组功能版有限定时逐项相同，新增捕获/整包收益0，不能跨集合将5/6→6/6解释为改善。
原30请求中15可交接、13完整成功全部保留，其他几何/相干拒绝及2个数据CRC失败继续保存。

实际查询、插值字、采样轨迹和定时状态相对既有有限节点精确一致，新增数值损失0；
这不是相对浮点参考的全链量化损失为0。原RRC2.348%＞2%、插值与16KiB失败不变。
新的负例观察量开发67584、保留69632采样，16MS/s下约4.224/4.352ms，零新增误交付；
它们是全记录差分最大值单候选夹具，不是持续输入捕获生产者，更不是全环境零误检证明。

独立模拟发送端的定时/CFO真值仅在决策后另行评价：最大绝对采样误差开发0.197225、
保留0.169390采样，和原有限节点相同。首/中/尾32符号误差与初始CFO误差、输入SHA及轨迹SHA
保存于证据`truth-diagnostics-*.json`；锁定、收敛、周期滑移和真实载波相位误差仍未分类，
不由CRC或残差推为零。真实IQ缺少精确真值时不套用这些误差。

## 复现与冻结

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_timing_handoff.py \
  --split development --timing-root "$TIMING" --capture-root "$CAPTURE" \
  --selected-root "$SELECTED" --output /tmp/timing-handoff-development
```

预期退出1，必须同时检查完整model和manifest，不能把异常退出当验收成功。
开发完成后用`--split validation --freeze .../freeze.json`评价独立新组合；已查看集合仅固定回归。
冻结根`timing-service-handoff/`保存输入/源码SHA、服务值/周期、全部失败、恢复和退化关联。
新的比较要求帧、实际查询/字、采样轨迹与有限状态和既有数值节点精确相同；它不改旧误差预算。
真实扩展环境与纯Python分别记录，新定时/查询服务没有Rust实现，不据此宣传墙钟加速。
