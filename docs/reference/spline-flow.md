# 有限端口、实际字值的样条准备

SYS-B3C1接续[整数样条](spline-fixed.md)，面向标准§6.2.3接收同步的实现。
它保持原全局not-a-knot方程、18位源/22位工作/14位系数小数、RNE/饱和位置，
以及全部捕获评分、门限、相位、候选等待和包内环路。默认接收器不变。

## 结构与接口

`SplineFlow`处理一个已拥有的4..640点窗口。容量是编译配置；处理短窗口不免费缩小物理存储。
原始端口为19+19+8有符号RRC字，实际扫描最大分量、选择公共指数、RNE对齐，之后前向递推、
后向求导数。独立已对齐18位端口显式带10位公共指数，不能用它证明输入量化或RRC周期已通过。
模型不读取期待输出、CRC、载荷或真值，黄金模型只供外部核对。

三个Y字及其标签保持有限缓存；前向上一行直接旁路，后向Q回复有一个保留槽。
原位布局以偶/奇工作银行保存前向状态，消费后改写导数；分离布局另设完整前向银行。
每银行每周期只允许一个共享读/写地址。edge c后发命令，edge c+1采样或提交，
回复在c+读延迟到达；新增输出寄存器不会使读值晚于捕获时刻变化。冲突等待，不增加隐藏端口。
每个运行重置状态，未提交的M字标记无效；超时显式丢窗口，结果阻塞保留状态且不暂停ADC。
窗口取得和ADC连续覆盖由外部拥有槽负责，不能直接把主机诊断快照计作硬件免费备份。

原语假设来自AMD Vivado2025.2的
[RAM128X1S](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/RAM128X1S)、
[RAM256X1S](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/RAM256X1S)
和[UG474分布RAM表](https://docs.amd.com/r/en-US/ug474_7Series_CLB/Distributed-RAM-SLICEM-Only)。
这里用共享地址异步RAM加显式读寄存器，不假设独立第二读口；128/256点每bit分别计2/4个LUT。
分段译码、选择器、布线、控制与计数器更新时间仍须综合/时序核对。

## 冻结与数值验收

开发前定义缓存3字、FT2每引擎400个内存LUT研究上限、原位/分离两布局、
读延迟1/2和算术行延迟2/3。行延迟是假设的展开图延迟，不能用总操作数除理想并行度代替。
选择规则只依据字值完全一致、研究内存上限和R1不慢于分离布局。
新的开发输入包括零、极值、交替符号、强弱指数变化、脉冲、混合指数及实际RRC字。
冻结原位/R1/行2后才生成不同长度和图样的独立节点验证；这不是新的RF保留验收。

337个开发场景、36个独立节点验证全部与冻结整数参考的Y、M、指数和全部数值统计完全一致。
外部内存镜像另行核对每次读回复、延迟、写提交及单端口约束。流水中断和结果阻塞的轨迹也保存。
旧tone成功IQ整段、固定257点及随机分块均完整正确，所有事件数组逐位相同。
`CycledUniformCubicEighth`只在显式诊断替换中使用；后续CSD查询、评分和包内处理仍为原功能实现，
主机调用等待不会推进实时ADC时钟，因此这是数值集成，不是完整接收周期闭环。

本阶段接收收益为0、相对冻结整数节点新增量化损失为0；没有新RF捕获率或BER增益结论。
原RRC的2.34835%>2%反例、16KiB失败、旧低SNR/CRC失败继续保留；没有修改预算或位宽。
首轮驱动错误导入造成的失败及修正前源码亦归档，不计为算法通过。

## 运算、状态与周期

| N256准备项 | 原功能图/日历 | 新实际字值模型 |
|---|---:|---:|
| Y读 | 1024 | 509 |
| 前向工作字读 | 511 | 255 |
| 扫描/对齐/准备 | 1544周期地址情景 | R1/行2第1542周期就绪，含edge0共1543周期 |
| Y+工作逻辑内容 | 20480bit | 20480bit |
| 具体存储估算 | 3 BRAM36 | 原位320内存LUT，分离496 |

这主要改善存储端口与重复读取，没有显著减少递推关键路径。

| 读延迟/行延迟 | 原位就绪周期 | 分离就绪周期 |
|---|---:|---:|
| 1/2 | 1542 | 1542 |
| 1/3 | 2053 | 2053 |
| 2/2 | 1673 | 1546 |
| 2/3 | 2056 | 2056 |

原位布局在R2/行2更慢，不能笼统宣布优于分离布局。每行峰值为2个实常系数积、14个实加减、
4个RNE、26个饱和结果（52次边界比较）及10个常移位。选定宽度的乘积情景需2个25×18片，
并非任意位宽乘法都只占1DSP。系数150bit；N256明确状态/标签/流水/控制监视预留5210bit，
另计20480bit数据，不包含前级已计费的原始拥有槽。监视更新及整个行图2周期尚无时序证据。
每次运行记录实际递推运算量、读写次数、等待及未完成回复，不把峰值与总次数混用。
前级扫描另列每窗口最多2N次绝对值、前导位检测、归一化移位、非零判断和复合峰值比较，
以及2N次对齐移位、一次公共指数更新；这些不是递推操作计数，也没有免费删除非线性工作。

## 整机与吞吐边界

FT2容量256专用引擎320内存LUT，四引擎1280；加RRC1064为2344。
沿用整机条件账本，四引擎不再新增12BRAM，但第四原始拥有槽仍占2BRAM，条件小计103→91BRAM。
若保留尚未批准的35BRAM余量，剩14个，须继续为译码、TX、实时MAC/DMA分配，不能视为整机已满足。
按理想装箱，加基础2732及RRC268个SLICEM后为3320/4350；没有新增综合/放置证明。

完整640容量原位每引擎1280内存LUT，四引擎5120，加基础和RRC理想占4280/4350个SLICEM，
尚未含其他功能，已非常拥挤。不能把FT2专用估算冒充FT3/4完整成本，也不能用理想装箱承诺布线。
这些是可比较的映射建议，不是批准新整机预算，更不是取消旧16KiB/18DSP/宽算术门。

将实际1543周期准备服务放入已有窗口搬运队列，只是**偏乐观的准备段投影**。
16MS/s、每32输入点一个请求的121次压力中，100/160/200MHz均有队列丢弃；
每256点一个请求的16次均完成。细查询/差分/相干评分、候选回馈、环路与译码尚未计入，
不得将它表述为完整捕获链16MS/s通过。四引擎在200MHz的准备算术下界也不证明端口并发或下游截止期。
持续干扰的算法漏检与此处调度丢弃分开记录，不能限流后隐藏漏检。

## 一条复现命令与证据

```sh
PYTHONPATH=src UV_CACHE_DIR=/tmp/rx-uv uv run --frozen --no-sync python \
  scripts/model_spline_flow.py --output /tmp/sle-spline-flow
```

输出目录须不存在，预期退出1：节点通过，整机验收仍未完成。
输出包括执行前protocol、冻结selection、全部输入字、每场景结果、选定完整周期轨迹、
开发/验证与原成功包回归、资源/队列失败、依赖和递归SHA清单。
纯Python与真实Rust环境分别复现；本节点没有独立Rust实现，双环境一致不等于Rust版硬件实现。
冻结证据根的`spline-flow`保留原始规则、首轮失败、源版本、测试/覆盖率与实际CI制品。
外部旧RF24流未在本节点阶段重新跑，旧证据继续有效但不冒充本阶段新验证。
