# B1长度合同与真实帧边界

## 问题与独立反例

在已推送的`fd715ab`复现：A2的两个长度对照正确，FT3/4 B1与CRC24/32的
四个反例均有正确头CRC，但接收器把数据CRC字节重复计入载荷长度。
实际帧尾397/621符号被计算为410/634或415/639，未知起点接收未交付。
原始六个NPZ、完整SHA与旧失败结论保存在`tests/data/b1-wire-length/baseline.json`。
修复后的测试逐字节使用这些输入，期待载荷不变。

两版原始标准的§6.4.2.2.2一致：非重传B1长度包括物理层数据、可选MIC和数据CRC；
零长度表示三者均不存在。A2/A3的§6.4.1.3.2/.4.2长度不包括数据CRC，不能统一减去CRC。
版本、原件SHA及已核对范围见[标准来源](standard-sources.md)。

## 接口与失败行为

`PSKReceiveProfile.ordinary`默认采用`length_contract="standard"`：

- 真实头CRC通过后才读取字段。保留`header.data_length`原始值，另给出
  `payload_length_bytes`及`data_crc_present`，后者不表示数据CRC已经通过。
- 非零B1长度减去协商CRC24/32的3/4字节，再计算分段、编码、导频与帧尾。
  非零长度小于CRC字节数为`invalid_length`；有效信息/MIC长度另受profile上限约束。
  B1最大2047个线上字节只容纳2044/2043个信息/MIC字节。
- MCS15是依赖前次调度的重传/CBG位图，仍显式`unsupported_mcs`，不把位图解释成长度。
- 零长度B1不调用载荷译码器、不附加数据CRC；消费控制字段及其实际导频后输出
  `valid_empty_control`事件，`data_crc=None`、`payload=None`，不冒充MAC数据交付。
- 坏头CRC不读取长度或解码载荷。截断头、截断数据、非法长度及错误LLID继续保留失败事件。
  长度只控制同一已选候选的消费与释放，不在CRC失败后重选同步、定时、频率或相位。

`mac_to_iq`的普通B1也改为正确线上长度，并核对自定义头的长度/MCS。
低层已知配置`tx_chain`保留默认附加CRC的理想API；新增显式`data_present=False`仅允许
真实头CRC正确、零长度B1且数据为空的情况。该小修复服务于接收互证，不是大规模TX实现。
FT2空帧末控制导频省略保持；FT3/4按§6.3.4/.5每4个控制符号后的导频计数。

### 旧实验兼容

早期B1自回环把长度当成信息/MIC字节数，不能继续声称它证明标准B1长度合法。
已查看的`test_selected_rx.ordinary`、`test_receive_scope.make_profile`固定回归显式选用
`legacy-b1-payload-length`，保留原线上字节、原载荷和原数值/资源失败。
这个合同必须在接收前由输入来源决定，只允许B1；不提供自动探测、CRC回退或重复试解。
新普通链路默认及新长度向量使用标准合同。WS63 A3不受这项B1修复影响。

## 复现与结果边界

在未安装Rust扩展的锁定Python环境执行（输出目录必须不存在）：

```sh
PYTHONPATH=src uv run --frozen python scripts/check_b1_length.py --expected-rust no --output /tmp/b1-length-new
```

已安装实际Rust扩展的独立环境使用`--expected-rust yes`。
脚本先核对原始输入SHA与实际后端，保存源码/依赖、完整头、漏斗计数和采样轨迹。
同后端整段、固定1/32/257及随机1–513分块要求逐元素一致；跨后端预定义容差为
符号1e-12、中心1e-10采样、速率1e-8 ppm。真值仅用于事后误差统计。

六个固定长度回归由2/6到6/6；其中四个B1是帧语义缺陷恢复，不是低SNR捕获增益。
原61/96压力集未重跑，不能将其写成65/96。早期35个压力失败及诊断分类不变。
固定负例只覆盖FT4/CRC32：静默4096、噪声32768、单音32768采样，合计69632采样，
相当于16MS/s的4.352ms；有限观察中零交付不代表全环境零误检。
这不是新RF保留集，不用于选择参数或放宽既有预算。

## 结构与验收账本

新增长度变换每个已校验头执行一次：11位零检测、与CRC字节数比较、常量减法。
不增加逐采样乘法、除法或开方；原始长度与导出的信息长度不能在上下文中混用。
若另存导出长度与存在标志，需要11+1位上下文；能否复用现有寄存器须由接入模型证明。
这只是操作/状态估算，尚无该变换的注册端口/周期模型或综合LUT/FF结果，不填零周期。
不能把有限浮点数组、Python完成时间或头部Polar银行模型当成整链接收调度。

四项验收仍分别开放：完整流式结构/FT1、全链定点、整机资源及连续16MS/s均未通过。
word-full12-c18原2.348%＞2%、插值误差及旧16KiB失败继续保留。
整头word集成原型暂未推广；必须先接入正确长度合同并重新验证。
其他待审计项包括FT3/4恰落整导频间隔的载荷末尾规则、全部合法长度与编码组合、
实时头部/载波/载荷服务与队列。六个长度向量不是完整波形或标准互通认证。
