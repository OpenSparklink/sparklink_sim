# RRC银行、复制和LUTRAM端口（SYS-B2）

本阶段将**现有RRC周期日历**的逐周期读写接入明确的有限内存模型。
不修改81抽头、beta、SPS、舍入、位宽、同步、定时或载波算法。
标准关联为§6.2.1.2；RAM组织是实现选择，不是标准要求。
`word-full12-c18`仍为实验后端，原2.348%>2%数值失败保持有效，
不能因为内存逐字相同便宣称滤波数值验收完成。

## 端口反例和候选

基线保存在实现前的`SYS-B2-baseline-source.tar`及`rrc-bank-baseline-probe`。
原始128×32bit历史按样本低3位分8银行，每银行16个有效字。
现有每组四个对称抽头需要最多两次同银行读。直接使用RAM32X1D时，
SPO与写地址共用；输入写入该银行的周期，只剩一个任意地址DPO。
100/160MHz积压日历出现原始地址仍有效的冲突，**拒绝通用采用该方案**。
200MHz所测日历没有冲突不能消除这个反例，也不自动扩展其他调度。

候选原语依据[AMD UG474 v1.9表1](https://docs.amd.com/r/en-US/ug474_7Series_CLB/Distributed-RAM-SLICEM-Only)
和[7系列RAM32M说明](https://docs.amd.com/r/2024.1-English/ug953-vivado-7series-libraries/RAM32M)。
每个原始银行用16个32×2Q RAM32M，四份写数据相同，读A/B独立，C/D输出未使用仍计费。
产品则按`j%4`分四银行，地址为`slot*11+j//4`；每银行用69个RAM64X1D，
独立DPO读和一个写，三个拥有槽占33行、物理深度64。没有假定任意多端口RAM。

`PairRRCFlow.simulate(access_sink=...)`只是观察接口，每周期至多8个原始读、4个产品写/读；
不能更改日历、反压输入或选择结果。`RRCMemory`保存独立副本，广播写入后按真实端口读取。
冲突返回缺失响应并留下诊断，不偷偷多读一拍、重试或增加端口。
同地址产品读写及下一捕获沿的覆盖都显式报错；不得依靠未定义的RAM冲突行为。

原始读是异步输出到现有对齐阶段；当前样本显式旁路，启动期负索引返回零。
产品读在下一周期交付，复用已计入的276bit读流水及SUM元数据。
不存在额外“零延迟”产品读或免费的新增流水寄存器。
异步读→路由→对齐的一周期路径仍需综合/布线验证，本轮没有这类证据。

## 数值、日历与失败

4096点连续输入取自仓库冻结合成IQ，经**原有full12输入适配器**得到32bit字；
产品数据由独立69bit生产参考生成，覆盖内存通路，不替代实际FIR乘积和量化验收。
单元测试另覆盖零、最大字、所有权、过期及两个读写重叠边界。
这不是新的SNR开发/保留集，也不提供新整包收益或真实ADC标定结论。

| 结构情景（4096点） | 原日历丢弃 | 新quad端口冲突 | 产品读写冲突 |
|---|---:|---:|---:|
| 100MHz，无阻塞 | 1954 | 0 | 0 |
| 160MHz，无阻塞 | 674 | 0 | 0 |
| 200MHz，无阻塞 | 0 | 0 | 0 |
| 200MHz，输出阻塞100–4100周期 | 311，另4个输出历史过期 | 0 | 0 |

还有100/160MHz阻塞及算术II2、系数口3、产品槽2、产品读口1、消费者II14等变化，
共23个情景。18个新观察日历与六个**实现前**原日历逐项相同；
成功响应按独立输入/产品参考检查，过期响应必须缺失，不能与新端口冲突混为一类。
quad情景共核对3972452个原始/产品响应，旧资源丢弃与过期均保留。
这些是采样处理请求和内存响应，不是实际丢包率或BER。

普通dual方案在100MHz无阻塞时产生1001个银行冲突、160MHz669个，报告中保留全部地址。
quad方案作为**存储结构候选**保留；不升级默认接收器，也不清除数值门或整机门。
跨包保持连续历史，不因包界重置RAM；模拟EOF只排空已有处理，
没有自动增加滤波尾零，既有RRC流式接口仍负责其已定义的冲洗。

## 资源：逻辑信息、复制单元和物理原语

实现前冻结的研究预算为1200个**内存LUT**，不等于整个模块LUT或整机预算。
原18DSP/16KiB限制及所有失败继续保留；不因芯片剩余资源自动放宽。

| 条目 | 原直接BRAM映射 | 新LUTRAM映射估算 |
|---|---:|---:|
| 原始历史8读及持续写 | 8 BRAM36 | 512个内存LUT、128个理想SLICEM |
| 四个69bit产品银行 | 8 BRAM36 | 552个内存LUT、140个理想SLICEM |
| 合计 | 16 BRAM36 | 1064个内存LUT、268个理想SLICEM |

这个估算依据原语和端口组织，**不是实际综合节省16个BRAM的报告**。
每源采样写入一个银行的四个副本；每产品写入两个副本。
原始RAM的32768bit原语容量、产品RAM的35328bit均包含复制和填充。
不能只把4096bit/9108bit有用内容当物理存储。
另预留1280bit控制/监控，不收取新的产品读流水，数据乘法新增0；
原8乘法器、43宽/64小单元等算术估算没有因换内存自动减少。
宽比较、监控更新和路由尚未完整排程，不凭这些数字宣称总II满足。

原始操作数路由按上界4096个bit输入、旁路512个bit输入单列，
控制/路由的LUT和时序未知，不以0填入总账。没有先记系数ROM/未用端口裁剪的收益。
使用上述布局和控制后，捕获已知未复制信息下界150124bit（18.33KiB）；
替换为已计原语的复制/填充单元后，部分分配205016bit（25.03KiB）。
两者都超过原16KiB，而且仍未包含整个接收机。

原SHA绑定基础报告有538个LUT用作内存，其中分布式RAM50、SRL488；
17400是芯片内存LUT容量，不是空闲RAM。已有2732个SLICEM也含逻辑，
不能用17400−538当可自由放置余量。解析器分别保留占用与未知放置能力。
理想新增268个SLICEM的打包计数不是布局布线证明，尤其200MHz仍未验证。

## 整机约束及下一阶段

在原基础73BRAM不减、窗口搬运10、独立确认ROM1、包槽5的条件规划中，
原始/产品RAM改用上述LUTRAM后的已计小计为89BRAM。
候选25%整片预留35后还余16；**该预留未批准，整机预算未冻结**。
系数ROM、粗筛银行、细搜索样条暂存/实际读口、包内载波、Polar、TX、
实时MAC/AES/DMA等仍必须分配，不能将剩余16个全部给RX。
目前只减少一个已确认的端口/粒度浪费来源，不足以宣称整机满足。

下一步将细搜索窗口准备、读口与有限调度接到既有RRC/捕获模型，再收敛
包内载波和译码期限。完整接收机验收前不展开大规模TX，但保留其资源与并发规划。
已查看所有信号集合仅作开发/固定回归；以后算法改动须用改变载荷、干扰形式及配置组合
的新开发集，冻结采用规则后再评新保留集。本次没有在失败保留集上挑其他载波步数。

## 复现

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_rrc_memory.py \
  --output /tmp/sle-rrc-memory
```

目录须不存在，预期返回1，表示数值/整机验收仍未完成。
输出保存23个日历、全部冲突/过期/丢弃、输入及响应摘要、源码/依赖哈希。
冻结根`system-feasibility`另有原日历对照、物理报告SHA、实际双环境输出和CI制品核验。
该模型本身是Python，Rust依赖环境的相同结果不代表本模块已有Rust或硬件加速实现。
