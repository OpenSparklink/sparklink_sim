# 有界候选尾部与逐字回放（SYS-C2D）

本阶段针对[细搜索模型](score-word-arithmetic.md)完成后仍存在的样本保留缺口，
对应标准§6.2.3接收实现选择。它是滤波字传送的有限结构/值/周期模型，
不是相干确认、头CRC、Gardner/载波环、译码或MAC交付的完整实现。
默认`CaptureTransport(...).simulate(tail_replay=None)`保持原结果和释放时机。

## 因果状态与所有权

显式传入`CaptureTailReplay`后，只有已获准的粗请求能取得尾部槽。
在请求到达时打开租约，不等候同步/CRC成功；下一采样起，把所选路径的46bit滤波字
写入该槽。未入队请求不分配内存，后续复制过期会取消租约。
没有使用真值起点、载荷、CRC、已知长度或未来细搜索答案决定保存哪些输入。

原始拥有窗口仍按原端口复制并保持不可变。细搜索完成后，`ready/confirm_pending`
先回放整个窗口，再回放已到达的尾部；读到当前输入边界才发出实时交接的下一绝对索引。
原窗口直到此时才释放。几何等待/不合格结果不回放。
细搜索和回放在本候选中串行，下一细搜索不能免费重叠；不把它称为最优调度。

尾部溢出是粘性的：停止该租约后续写入，保留已输出的部分数据作为失败证据。
原细搜索继续占用完整服务周期，未给提前取消或乘法器复用信用。
在可释放时记录`tail_capacity_exceeded`资源失败，不作为CRC失败或包交付成功。
ADC不背压；下游阻塞可能导致溢出，不能靠无限FIFO或覆盖未消费字解决。

## 数据通路与端口

固定研究候选为三槽、每槽4096字、每字46bit；没有改变19+19+8表示或增加量化。
每槽独立1R1W TDP银行，持续输入最多同时写三槽。
全局只允许一个在途注册读/输出字，RAM响应延迟1周期；消费II固定4。
输出阻塞保持该字和读索引，未消费的槽位不复用。
同址读写不依赖器件未指定行为，推迟读取；EOF只排空已有字，不生成假样本。
复位租约清指针/有效状态，旧RAM位不能成为新一代有效数据。
实时交接索引锁存，不随之后输入漂移。

窗口、尾部由不同物理银行提供，细搜索/回放互斥访问同一拥有窗口。
回放不增加源历史读口；保存尾部来自当前输入线，不能读取整份采集的未来内容。
独立绝对索引参考核对所有输出字、握手间隔、溢出发生时的占用及读写同址事件。
回放完成仅证明从窗口起点到交接点的字连续；后续实时消费者、帧状态与缓冲仍需整合。

## 成本和冻结规则

运行前冻结尾部上限24BRAM、额外状态及搬运连接上限4096bit、消费II4，
开发后没有根据独立节点验证或已查看RF回归增加容量。

| 新增项 | 成本/假设 |
|---|---:|
| 尾部逻辑内容 | 565248bit，69KiB |
| 物理尾部银行 | 24BRAM36：3槽×4深度块×2个36bit切片 |
| 描述符、计数、单字读流水、连接状态 | 3347bit寄存器预留 |
| DSP | 0 |
| 每输入最多新增逻辑写 | 3；每46bit字写2个原语切片 |
| 全局读/输出信用 | 1字；每槽1写+1读 |
| 原拥有窗口副本 | 0；窗口延长占有，不代表免费存储 |

原运输10BRAM加尾部24为34BRAM；再加已核对基础工程73已107。
还未包含全部前端、细搜索、译码、TX、实时MAC和接口增量。
原16KiB模块预算失败保留；24BRAM是研究候选上限，不是已批准整机预算。
25%整片余量仍是待论证建议。上述为容量/端口估算及可执行周期模型，没有综合或时序保证。

控制周期仍采用明确的宏假设：64bit计数、比较和地址计算一周期，银行译码及选通可在该周期完成。
它不是如逐字评分ALU那样的分段进位实现，200MHz未获时序证明。
对每个到达采样，除统计监视外，最多作1+L次64bit递增、2L次占用减法及2L次容量/峰值比较，
L≤3为当前健康租约数；每个回放字另有地址/索引、期限比较和统计更新。
数据通路仅搬运，不作乘法、除法、开方或三角运算。
统计逻辑的同拍多次增量、宽加法/比较、扇出和选通LUT仍需设计及综合，不能当成零成本。

## 冻结输入结果与拒绝结论

新开发4例变化窗口、服务时间、负载密度、零/极值/弱字和阻塞；冻结后新节点验证4例
进一步改变几何、时钟、服务时间和组合。全部实际输出字与独立参考一致，溢出被显式记录。
这是字/端口节点集合，不是新的射频保留集，不宣称捕获率收益。

随后重放既有24流的30个实际请求，核验原输入、父manifest及每个拥有窗口SHA。
原19个评分结果不变；新增租约延迟在新日历中实际计费，不能沿用原释放时间。

| 固定请求，三个独立时钟 | 100MHz | 160MHz | 200MHz |
|---|---:|---:|---:|
| 连续回放完成（含EOF排空） | 6 | 8 | 8 |
| 输入仍继续时交接 | 0 | 1 | 2 |
| EOF后排空 | 6 | 7 | 6 |
| 尾部容量失败 | 11 | 9 | 9 |
| 原始拥有队列丢弃 | 2 | 2 | 2 |
| 未评分等待完成 | 11 | 11 | 11 |

源历史环的缺口与新尾部回放分别记录；有尾部时不再把旧“必要保留失败”计作实际回放失败。
原来17个待确认结果均只有不完整的历史；现在部分能逐字回放，**不计为6/8个包恢复**。
200MHz下FT2五个待确认结果均完成回放，FT3为2个、FT4为1个；其余9个尾部溢出。
其中6项回放依赖EOF，不得当作持续输入收益。追加确定性字流延续、保持原粗请求，
在200MHz的乐观无新增请求对照中仅5项实时交接，12项尾部超容、2项队列丢弃。
这只是字接口存储压力，不是合法RF波形；未运行延续段的新捕获，真实负载可能更重。
继续输入时，一项排队请求在首次允许回放前就需要18641字尾部；
因此把三槽4096简单合为12288字池也不能单独证明足够。必须同时减少最坏服务/排队，
或明确付出更多存储，不能假定共享一定满足。
整包、CRC、长度/MCS、BER及低SNR接收收益未由本节点评价，原真实接收结果不改变。

**三槽私有4096尾部配置不采用为目标整机方案。** 它满足局部24BRAM/4096bit研究上限，
但FT3/4仍溢出，整机资源和期限未闭合。不能只提高容量参数便声称支持。
下一步需比较按实际路径共享重叠尾部/有界分块池或进一步减少服务工作，
重新冻结端口、状态和系统余量；不围绕已查看集合挑一个更大容量判通过。

## 复现

先生成[捕获窗口](capture-fine-integration.md)及[逐字细搜索](score-word-arithmetic.md)证据，
然后运行（输出目录须不存在）：

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_capture_tail.py \
  --capture-root /tmp/capture-fine-repro --score-root /tmp/score-words-repro \
  --output /tmp/capture-tail-repro
```

预期退出1表示目标配置/整机未验收；必须同时核对`model.json`和完整manifest，
不能把驱动异常当成预期失败。原46bit滤波输入含父阶段的42个滤波EOF字，
它们与原始ADC观察点分别记录，不借此证明RRC连续吞吐。
两后端环境实际运行并逐值核对；本模块本身是Python结构/周期模型，不是新增Rust/RTL实现。
