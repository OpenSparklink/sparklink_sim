# 活跃帧期间的有界排队窗释放（M32，实验）

本阶段只修改候选槽的生命周期，复用既有共享差分、归一化评分、全相位细搜、
相干确认、Gardner/PI、载波和真实 CRC／合法帧消费。帧依据仍为标准 §6.3、§6.9，
版本与原始 SHA 见 [标准来源](standard-sources.md)。它不是新的空口特性或标准限值。

## 为什么需要独立的检查

[实际头服务日历](captured-header-calendar.md)补上正的译码等待后，固定回归中有三个
原成功候选因槽满丢失。只读逐沿审计发现，入队时没有整个过期的窗口；但是活跃帧
消费样本期间，23 个已复制的排队窗变得完全落在已消费前沿之前。原细搜前检查要等
当前帧结束才能释放这些槽，过晚释放会占用下一包所需的有限窗口。
这只是调度归因线索，不能仅据此宣布恢复，也不取消原头等待或增加槽数。

新 `retire_queued=True` 必须同时显式启用实际所有者的 `retire_before_fine`。
默认值为 false，不改变原接收路径。检查只借用完整复制、上一沿以前已就绪的 FIFO
头描述符，保存一位有效和一位排除判定，下一沿提交期间不调度该队头。

判据为 `source_window_end <= previous_edge_consumed_frontier`。整个原窗内允许的
`start_tick < 8*window_samples`，所以该判据排除了窗内所有可能同步起点；
跨越前沿的窗继续原细搜。前沿来自实际消费索引，包含坏头或坏数据已消费的样本，
不依赖 CRC、期待载荷、真值、评分或另一个候选答案。原处理器已经采用这个所有权语义。
本阶段既不寻找帧内的重叠包，也不据 CRC 重试答案。

## 因果性、跨块和失败退出

检查读取上一沿的前沿，而非同沿刚返回的原始字。已复制窗口没有待提交写入；
判定下一沿才生效，并且早于新的帧消费、窗口入队或调度。未过期队头仍保留，
当前帧消费时可继续检查；最坏每个活跃／就绪时钟一次比较，不能按静默平均免计。
原细搜前比较与活跃帧阶段互斥，借用同一宽比较器。

源 epoch 故障先取消待返回判定，再按原 epoch 规则释放每个拥有槽一次。
下游阻塞不停止 ADC，也不阻止提交已经有效的元数据释放。原始数据读写仍沿用同一
共享环、同步窗、单信用读取和索引；任意主机分块不改变这些逐沿行为。
EOF、坏头、非法长度、截断和历史过期沿用严格帧所有者，不填入不存在的样本。

## 四层证据与成本边界

浮点参考和既有有限字捕获数据通路保持原样；这是有限元数据控制实验，没有新增
信号量化。共有细搜的输入字、整数评分及原成功包轨迹要求精确一致。
这种一致性不能覆盖旧 RRC 2.34835%>2%、插值超预算或未完成的载波／LLR／译码定点。

| 新增项目 | 成本／假设 |
|---|---|
| 状态 | 64 位排队释放计数＋2 位控制，共 66 bit；增量节点研究上限 128 bit |
| 已有细搜前释放＋新增释放 | 合计 132 bit；不把旧单节点 128 bit 当成组合预算 |
| 选择／比较 | 新 63 bit 二选一输入；共享 63 bit 无符号比较器，最多每活跃／就绪沿一次 |
| 计数更新 | 每次释放一次 64 bit 加法；溢出显式报错 |
| 元数据读取 | 两个寄存器操作数；原就绪队头借用至下一沿，无额外描述符副本 |
| IQ 存储／DSP／样本端口 | 增量均为 0；原历史 4096、拥有窗 3，原端口上限 2 不变 |
| 时间 | 元数据比较 II=1、注册返回 1 沿；100/160/200 MHz 对应 10/6.25/5 ns 假设 |
| 综合／布局布线 | 无新增证据；宽比较、选择、加法能否单沿完成仍需实现验证 |

已有单路径搬运控制加本增量，FT2/3/4 分别为 4172/4174/4176 bit；
共享 4096 字历史和三个拥有窗的具体 TDP 映射仍各占 14 BRAM36 站。
这些是 `CaptureTransport.estimate()` 的搬运子系统预留，包含有限请求及队列控制，
不含 RRC、粗核、细核、帧所有者、头／数据译码或 TX/MAC，不能当作整机总量。

观测器保存的检查日志属于调用者诊断，物理统计导出服务尚未建模，不能假设无限日志
或免费调试端口。新增控制必须与 RX、头译码、上一包译码、TX 准备、实时 MAC、DMA
并发记入 [整机账本](system-feasibility.md)，没有新的跨收发共享抵扣。
芯片容量与原模块 18 DSP／16 KiB 预算分开，原预算失败继续保留。

周期模型只验证这些实际控制沿、窗口搬运、已有粗细搜索和正的头部等待。
插值、环路、相干确认、载波、解映射、载荷译码的完整算术日历仍未组合，
完整延迟保持 `None`；不得将局部释放收益写成整链持续 16 MS/s 通过。

## 冻结实验和复现

新开发集改变载荷族、FT2/3/4、MCS8/12、包长、导频、包间隔及干扰组合，
再变化起点、分数偏移、CFO/SRO 和幅度；不是只换随机种子。
每组 12 个合法包和四类各 8192 采样负例。独立解析脉冲／重采样参考生成 IQ，
真值与期待内容仅用于事后关联、BER 及完整包核对，不进入接收选择。
整段、固定块、随机块分别运行；已有所有已查看集合只作固定回归。

```sh
PYTHONPATH=.:src:scripts python -m scripts.model_queued_retirement \
  --output /path/to/new-development --split development
PYTHONPATH=.:src:scripts python -m scripts.model_queued_retirement \
  --output /path/to/new-validation --split validation \
  --freeze /path/to/new-development/freeze.json
```

首条命令在执行前保存源码、策略和参数，采用规则要求真实完整包收益，不能仅把原槽满
改名为过期释放。之后冻结源码、参数、预算和采用规则，才允许生成新保留集。
保留集若出现原成功损失或新增负例确认，则拒绝，不在同一集合反复调参。
两条命令的返回 1 表示局部验收拒绝，不能隐藏为成功；0 也只表示局部实验通过。
头 CRC、数据 CRC、长度、MCS、完整内容、BER 和每百万采样候选／丢弃分别记录。

完整流式、全链定点、整机资源和连续吞吐四项总门继续分别为未通过。
FT1/GFSK、编码载荷和未知厂测编码不在本局部实验内，正式压力集 61/96 不由它改写。

## 开发结果：拒绝采用，不消耗新保留集

预先定义的新开发输入共 99041 个采样，包括 12 个合法包和 32768 个负例采样。
原头服务等待保持开启，两臂对同一原始 IQ 分别运行整段、固定块和随机块。
采用前规则要求至少一个新增完整包恢复；结果未达到，不根据结果修改规则。
开发命令实际返回 1，候选仍仅作显式实验，独立新保留集没有生成。

| 项目 | 已知头等待基线 | 新增排队释放 |
|---|---:|---:|
| 实际相干确认 | 10 | 11 |
| 头 CRC／合法长度／许可 MCS | 9 / 9 / 9 | 10 / 10 / 10 |
| 数据 CRC／完整内容 | 8 / 8（目标 12） | 8 / 8（目标 12） |
| 数据 CRC 失败 | 1 | 2 |
| 可计算错误／比特 | 188 / 10872 | 193 / 12880 |
| 已知细搜服务沿 | 278616 | 306340 |
| 细搜前注册检查 | 29 | 19 |
| 活跃帧排队比较 | 0 | 20225 |
| 排队窗提前释放 | 0 | 16 |
| 槽满／历史搬运丢弃 | 24 / 0 | 18 / 0 |
| 原成功包丢失／新增完整恢复 | — | 0 / 0 |

新的确认来自突发背景流的第二包，实际得到合法头和 5 位载荷错误，仍为数据 CRC
失败，不能算恢复。两臂 BER 分母不同，新臂多解调了失败载荷；不能把总错误增加
直接当作同一载荷的定点损失。共有细搜字、评分和原成功包轨迹精确一致。

细搜服务工作增加 9.9506%，另有 20225 次连续元数据比较。
这些比较与当前帧处理重叠，不能直接加到完整延迟，但仍消耗比较器、选择及控制活动。
槽满减少并未转为新完整包收益，说明只释放旧窗不足以闭合当前调度。
固定已查看反例中第二包恢复只是一项回归，不覆盖这个新开发拒绝结论。

负例观察为 32768 采样，即 16 MS/s 下 2.048 ms；两臂都没有相干确认或 MAC 误交付。
整组每百万采样的细搜请求分别为 171.6461／191.8397，实际确认 100.9683／111.0651，
槽满 242.3239／181.7429；负例零新增的结论仅限上述有限观察量。

四个仍失败的目标包均保留原 SHA、全部候选、帧及位轨迹：单音流第二包显式历史过期；
错误同步字背景第二包有 188 位错误、数据 CRC 失败；幅度阶跃流第二包无终止关联，
算法与调度贡献尚未隔离；突发流第二包由无关联变为上述 5 位 CRC 失败。
没有对这批输入做真值定时／CFO 重放，不据它们断言理论不可恢复。

随后将同一冻结开发输入作为固定回归，在实际 Python／Rust 环境复核：
95 个 NPY 成员逐字节一致，除 19 个显式 `integer_screen_backend` 标签外，
所有流报告和对照结果精确相同；标签严格同一性失败另存，没有忽略为逐字节通过。
原生组件可用性有实际探针；有限字算术模型本身仍由 Python 执行，不称作全链 Rust 后端。
单位测试分别为 Python 5676 通过／38 跳过、Rust 5720 通过／5 跳过，
覆盖率 93.88%／93.87%，最长分片 94.471／90.158 秒；68 项针对性测试另行通过。
这些是软件验证，候选采用、四项工程验收与实际硬件能力仍分别报告。
