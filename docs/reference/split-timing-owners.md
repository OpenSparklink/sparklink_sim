# 独立检测与PI/NCO所有者

§6.2.1.2规定PSK波形，本页的流水拆分属于接收实现选择。
在[固定年龄采样闭环](feedback-age-sampling.md)之后，新增两个明确有限的周期节点。
默认接收机、Gardner误差、功率递推、量化、PI系数、速率限幅和同步规则均保持。
本阶段没有新增RF捕获收益或采用新的误差年龄，四项总验收仍开放。

## 状态和接口

`split_timing_states(power, start_tick, hold_symbols, fmt, config)`使用原规则验证初值，
只保留各节点实际持久字；临时主机初始化对象不成为另一份硬件状态。
格式仍为power30/error24、30/32和38/32，同步长度32/62/126。

| 所有者 | 更新内容 | 不持有的状态 |
|---|---|---|
| `TimingDetectorService` | 当前/前一字、功率、当前误差、真实输入计数和检测统计 | 无NCO坐标和速率积分器 |
| `TimingPIService` | 送入的有限误差、速率积分器、前一/下一坐标、查询计数和限速统计 | 无检测功率和前一样本 |
| `SplitTimingQueryService` | 原三边沿坐标快照、RNE相位及历史/未来需求 | 不推进任何定时状态 |

检测器复用原4DSP功率/TED重叠及整数除法，在误差之后增加一个注册提交边沿。
PI复用原KI/KP的实际DSP分解、宽加法、RNE、限速及NCO步骤；不调用功能参考提前计算答案。
两者各一输入信用、一份保持输出，消费后不能在同一边沿重新准入。
计数或最终提交溢出时，所有者状态、完成计数和时钟都不部分更新。
取消清除未完成输出，正常释放要求先排空；新包重新建立状态。

检测输入计数和前瞻NCO计数独立。原单所有者周期服务明确拒绝新状态，
新查询服务只接受独立NCO所有者。不能提前推进整个原状态来假装实现流水。
误差年龄和带标签FIFO由后续包级控制器决定；PI节点不自行选择误差、CRC或真值答案。

## 数值和周期证据

74项针对性测试覆盖36组格式/年龄/同步长度、实际节点逐步状态、独立Fraction PI舍入、
三边沿整数查询、保持/取消/重复准入、坏输入、计数/NCO耗尽及有界调度反例。
另外冻结不同的9252个边界字节点，含非规范小尾数、零值、指数-128至127及大于binary64精度的坐标。
独立检查FIFO应用顺序、PI舍入和整数查询相位；检测规则与功能参考共享，
实际乘法/除法微程序独立执行。这不宣称整个检测器具有新的独立标准向量。

| 当前有限节点 | 最大服务延迟 | 消费后最小再次准入间隔 |
|---|---|---|
| error32、radix4检测 | 35边沿（原误差第34边沿就绪，另1边沿提交） | 36边沿 |
| error24、radix4检测 | 31边沿 | 32边沿 |
| 非零PI/NCO | 17边沿 | 18边沿 |
| 零误差PI/NCO | 7边沿 | 8边沿 |
| 整数查询 | 3边沿 | 4边沿 |

这些是执行微程序的结果，依赖原DSP延迟3、宽加法/比较/RNE一边沿等未综合假设。
它们不是完整符号反馈周期；查询、源读取、插值及包边界尚未与新所有者耦合。

## 有界节点台架

使用预配置320个插值字对，三条容量均为`age+2`的检测结果、PI结果及误差消息队列，
只按已注册消息调度。已看到的功能结果仅供输出检查，派发不读取参考答案。
输入不能暂停，第一次忙或保持输出导致的丢对即显式中止；不使用无限队列。

三组不同范围/持续比值工作量和输入相位台架，各24种周期/年龄/阻塞组合。
100/160/200MHz下4Msym/s对应每符号25/40/50边沿，仅是本台架的到达周期：

| 台架条件 | 已观察结果 |
|---|---|
| 40/50边沿，无下游阻塞 | 每组8种年龄/周期均320/320有序交付，所有字与同年龄功能参考一致 |
| 25边沿，无下游阻塞 | 全部年龄出现检测器忙丢对，保留已交付前缀 |
| 下游阻塞640边沿 | 全部组合有界退出，不隐藏丢弃 |

从原bb250ba归档运行同一age0字对与到达序列，原4DSP单所有者在三个周期均只交付32个前缀，
第33个输入字对遇忙退出；新8DSP台架在40/50周期完成320个。
这是额外银行换节点服务率的证据，不是多恢复288个包，也没有证明age0能及时生成实际下一采样查询。

这是已配置节点数、已提供插值字对的台架，未包含未知包头、实际长度判定或EOF交接，
不能据此宣布完整流式接收或16MS/s。原串行短前缀98边沿和24个连续源溢出失败仍保留。

## 成本与共享反例

两个节点现在使用两套专用4DSP银行，共8DSP；相对原定时银行增加4DSP。
实数/复数及系数乘法沿用原25×18原语分解：检测功率/TED各4个原语产品，
非零误差的KI/KP各4个，未把43×35乘法当成单个DSP。
宽部分加法、最终加法、功率归一化与PI/NCO加法分别计费。

| 项目 | power30/error32的逻辑上界 |
|---|---|
| 检测持久字 | 455bit，含计数、检测统计、hold选择和前一样本有效位 |
| PI持久字 | 397bit，含独立计数、应用误差及速率统计 |
| 两节点寄存器 | 4615bit，保留原微程序临时分配的保守上界，不扣未实现的槽复用 |
| 台架节点＋三队列＋控制，age0/1/2/3 | 7319/8279/9236/10196bit |
| 逻辑源端口 | 每次输入一个104bit当前/中点字对及有效信息；单52bit实际插值流的拼装尚未耦合 |
| 新原始IQ/滤波RAM | 节点不增加；源历史和包队列整体期限仍未验收 |
| LUT/FF映射、物理端口、Fmax | 尚无综合或时序证据 |

队列按每份保持快照、标签、有效位、指针、占用及控制计数记账，
不是把Python字典当作免费硬件。上述全部情况仍超过旧4096bit节点门；
原16KiB、2048bit及前端数值失败也不改写。这里没有批准新的整机预算。
整机账本中的译码、TX、实时MAC、射频接口及DMA预留继续独立。

原均匀周期和一组抖动输入未观察到共享冲突，不能据此减成4DSP。
加入由真实边沿推导的39/41边沿间隔反例后，160MHz台架每年龄出现411处同边沿资源冲突，
包括前一误差KP与后一TED的4DSP捕获、部分加法和最终加法。
无仲裁直接共享的方案被拒绝；需另行实现有界仲裁、上下文和延期，再重新测截止时间。
两套专用银行的交付结果不证明共享银行可用。

## 当前结论与复核

独立状态/值路径及节点台架通过相同算法的零字差异门；没有新的接收率结论。
下一步将真实查询、插值和源窗口接入有界前瞻与头部屏障，
再比较专用/共享银行的吞吐、存储和端口。未建模服务继续标为未知，不能填零周期。
方案与预算冻结后才评价新的独立RF保留集；当前全部输入为开发或固定回归。

本地全量4937/4948个用例身份全部保留，零失败/错误；分别38/5项显式跳过，
不能算成已验证算法。覆盖率均93.59%，四个分片均低于原120秒门，90.1%门不变。

工程内运行`PYTHONPATH=src uv run pytest tests/test_split_timing_flow.py -q`。
外部`split-timing-owners`目录保存冻结参数、输入SHA、全部节点转录、资源丢弃和共享冲突。
同步、CRC及载荷能力沿用原证据，不把本台架的数值正确当作整包正确。
