# 已选候选到真实帧终点的功能参考（SYS-C2E1）

本模块完成一个有限输入的功能闭环：已选定同步结果→现有Gardner/PI→严格头CRC→
合法长度/MCS→实际载荷终点→数据CRC→MAC。标准依据为已登记版本的§6.3帧结构、
§6.4控制字段、§6.9 CRC和§6.10编码；不增加厂测常量或改变合法波形。
这是[尾部回放](capture-tail.md)之后所缺的帧消费参考，尚未把解调/译码接入其周期日历。

## 使用接口

`SelectedPSKReceiver`只接受一个上游选择：八分之一采样坐标、差分CFO、分数及原细搜索选出的
同步符号向量。相干Q继续使用原0.45门限和该原始向量；不会以另一插值结果替换确认依据。
激活后复用`PSKStreamReceiver`的四点局部三阶插值、Gardner/PI和严格解析器，
不重新执行RRC、能量检测、同步搜索或CRC重试。原未知起点流式API及默认算法保持兼容。

调用者必须显式提供`PSKReceiveProfile`和固定`sample_limit`，以`feed_filtered(array)`
输入一维数值NumPy数组。输入是已匹配滤波样本，坐标以所供窗口起点为零；不是原始ADC坐标。
每次调用后`last_input_consumed`指明已消费前缀，剩余输入仍归调用者。
本端口按单采样因果推进，不以外部分块改变计算次序；输入数组借用，不整体复制或转换。
只校验被消费前缀的有限性；未消费后缀不属于本次接收。

同步插值需要一过去、两未来采样，缺历史明确拒绝。头部完整前不知道载荷长度；
真正校验成功并确认长度/MCS合法后才记录`frame_end_symbol`，沿实际定时轨迹消费到最后一个符号
及所需插值未来点，不按期待长度或名义SPS猜终点。
`header_decision_after_filtered_samples`记录真实头判定时刻。

坏头不读取长度、不继续载荷；非法长度/MCS立即终止。数据CRC失败仍保留符号轨迹和失败，
不给MAC载荷。`MacSelectedReceiver`复用原交付门：状态、真实头/数据CRC和长度都通过才交付。
CRC用于信任头部、结束本候选和交付，不选择不同同步/CFO/定时答案。
每个实例只处理一个上游选择，终态后不消费后续输入；下一候选须创建新状态。

EOF不生成补样；已经滤波的EOF冲洗如存在，必须由上游显式提供。
`finish(reason="eof")`保留截断同步/头/载荷；容量用尽且还有输入时返回`retention_limit`，
头已验证则同时保留真实解析状态、长度和帧终点，不能把资源失败算CRC失败。
选择位置在容量以外也按容量失败退出，不修改选择去凑存储。

## 固定回归及新节点验证

30个原请求按输入归档和原NPY成员SHA核验，11个几何等待保持未评分；其余19个使用原整数
细搜索的同一个最优位置、相关相角和采样向量。比较完整后续输入与“原拥有窗口＋首4096字”。
后者是**假设该前缀被保留**的可用性对照，不是C2D真实环形保存/排程已经实现的结果。

| 19个可评分请求 | 完整后续参考 | 窗口＋首4096字 |
|---|---:|---:|
| 相干确认通过 | 15 | 15 |
| 真正头CRC通过 | 15 | 15 |
| 数据CRC及完整载荷 | 13 | 6 |
| 容量不足 | 0 | 8 |
| 终态及全部采样轨迹与完整参考相同 | 基线 | 11 |

固定/随机分块与整段逐数组完全一致。有8次容量不足，其中7次在完整后续参考中完整正确，
另1次完整参考也有数据CRC错误；不能据此放宽预算、隐藏资源丢包或断言无法恢复。
原C1浮点参考用`medium-head`载波PI，本阶段用声明的默认`coherent`载波；
各自完整正确恰同为13不证明轨迹或载波相同，也不宣称捕获增益。
本阶段请求是外生重放，没有把新头部判定反馈到前级后重新生成请求，整链工作量仍未闭合。

新开发与独立节点验证各8个合法包＋4个负例，变化载荷、帧型、MCS、包长、导频、
干扰组合、幅度和CFO/SRO；选择固定后不调参。其上游用整段一次差分最大值，
因此验证的是已选端口，不是有界未知起点捕获率。
完整后续参考各7/8正确，固定前缀各2/8、3/8；保留全部其他结果。
两组负例共57344个原始采样、3.584ms（16MS/s），测试中零误交付；观察量很小，
不能表述为全环境零误检。已查看集合均成为固定回归。

同后端分块要求完全相同；真实Python/Rust后端预算预先冻结为中心2e-9采样、
符号绝对差2e-9、速率2e-6ppm，头/长度/MCS/数据CRC/完整载荷判定必须完全相同。
新接口另有坏头、错误种子、非法MCS/长度、截断、最大合法厂测未编码长度、零能量、
有限输入和错误域反例；可选Rust缺失明确跳过，具备扩展的CI实际执行。

## 存储、计算及四项独立验收

`sample_limit`为4..2^20的显式研究上限，预分配复数参考数组，不据此批准FPGA容量。
`reference_memory()`枚举并去重NumPy底层分配，另计交付事件的轨迹副本。
保留合法最大符号数组，每符号40字节（复符号16＋中心/速率/误差各8）；
不能为省数组而把协商的合法长度改小。Python对象、调用者数组和FFT/Polar临时工作区明确未计齐，
这些是软件参考内存，不是目标定点RAM位宽或整机资源总量。

| 验收 | 本阶段所得 | 仍缺 |
|---|---|---|
| 完整流式接收 | 已选候选端口可分块、按真实头结束或明确失败 | 物理回放/实时交接反馈、多候选完整调度；FT1流式 |
| 全链定点 | 原46bit输入按原指数还原，不新增量化 | 本端口插值/环路/载波/译码仍浮点；旧2.348%＞2%保留 |
| 整机资源 | 列出实际参考存储，不给未知项零成本 | 实际字数据通路/端口、全部译码/TX/MAC/接口预算 |
| 连续16MS/s | 没有新增通过结论 | 插值、相干、头/载荷/译码服务周期均未知，不能套搬运II4 |

原三槽4096尾部24BRAM、运输10及基础73合计107BRAM的部分账本仍保留；
本功能端口不意味着这24BRAM方案已获采用，也不新增一套免费副本。
下一步将真实头判定/实际终点变为有服务延迟的消费反馈，再比较早释放、单读口争用及过载。
不能把18641字“追到实时”的旧需求当合法帧内存下界，也不能忽略未验证头之前的等待积压。
新的容量或误差预算须独立成本曲线、前瞻冻结及新保留验证，不覆盖原16KiB和2%失败。

## 复现与失败出口

先运行原`model_capture_fine.py`、`model_score_words.py`生成或读取SHA核验的父阶段制品，再执行：

```console
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_selected_frame.py --capture-root CAPTURE_ROOT --score-root SCORE_ROOT --output NEW_OUTPUT
```

完整结果仍返回1，表示整机/全链定点/连续调度未验收；CI单独核验功能事实和该失败出口，
并保存输入、参数/源码SHA、完整/分块轨迹、全部CRC/容量失败、冻结规则和清单。
离线参考或测试通过不等于实际FPGA或完整SLE验收。
