# 有界头部预取实验

`HeadPrefetchedCaptureReplay`复用[有限初始化桥](initialized-capture-bridge.md)，
只改变初始化期间的样本复制调度。浮点默认接收器、捕获评分、预筛、候选数量、
相干确认、Gardner/PI参数、插值、头部和载荷算法均保持。
对应已核对§6.2.1.2、§6.3、§6.9；版本与SHA见[标准来源](standard-sources.md)。
本实验限普通FT2/3/4、4Msym/s、SPS4、MCS8/12及现有真实字头；厂测A3与FT1不在覆盖内。

## 为什么仅复制确定需要的头部前缀

原桥在同步样本备齐后暂停复制，直到初始化完成才继续追赶实时输入。
全局4096字源仍持续推进，暂停ADC或保存整份采集都不能消除历史过期。
新方案在初始化读私有RAM时，利用其独立写端口复制头部必需的后续前缀。
读端仍使用原全局单一帧端口，私有容量仍为1024字；满时等待，并保留源过期失败。

采用已有有限PI的最小步长下界：

```text
min_step_q32 = LOWER_Q32 - RNE((KP_Q48 × (2 << 32)) / 2^48)
head_prefix_end = floor(start + (known_head_symbols - 1) × min_step_q32 / 2^32) + 3
```

这里乘法和移位在编译固定profile的8个初始分数相位时完成。
接纳候选时仅查表并加上整数起点，注册一沿后可用；相干确认仍必须先完成。
误差限幅为±2，速率有已有下界，故实际完整头部的最后查询不会早于该前缀。
下界保守地少复制部分头尾样本，不能提前读取未经校验长度推导的载荷。
单独用实际有限NCO的极端PI提交验证下界；不依靠CRC或真值调整它。

初始化完成后恢复原8字查询前瞻及可信边界最后三符号的禁止额外预取规则。
坏头、非法长度/MCS、EOF、源过期和取消沿用明确失败退出；不补样本、不重试答案。
回执、索引、真实头CRC、合法帧尾和单次MAC交付仍由原拥有者负责。

## 新增成本与尚未覆盖的成本

| 项目 | 增量估算或模型 | 限制 |
|---|---|---|
| 边界及可用时钟状态 | 21+63=84bit | 总桥预留628→712bit；不是整机FF总量 |
| 单profile常量 | 8×11=88bit，查表至多11 LUT6 | 多profile切换及控制映射尚未知 |
| 接纳计算 | 21bit加法，一沿 | 尚无综合及Fmax证据 |
| 初始化复制请求检查 | 63bit可用时钟比较及21bit边界比较 | 增加源读取和私有写入次数必须实测计费 |
| DSP/BRAM36/全局读端口增量 | 0/0/0 | 已有1024字私有源和所有全局窗口仍收费 |

既有初始化/帧19DSP、相干1DSP没有新增共享证明，旧18DSP门继续失败。
新增状态不抵扣TX、译码、实时MAC、DMA或调试预留；整机LUT/FF及端口期限仍未闭合。
同源full12的2.34835%＞2%、独立插值及旧16KiB失败不变。
本次不组合full14或双路径单音抑制，不借用它们的独立收益。

## 验证和采用规则

先在冻结证据根`initialized-head-prefetch/baseline-development`保存原输入、
逐窗/逐包、源码和SHA，再评价单一预取候选。新开发改变载荷结构、帧型/MCS、
导频、包长、间隔及干扰组合；旧集合只作固定回归。
三臂均比较整段、固定和随机RRC输入分块；独立解析脉冲提供事后真值。
原/新消费器反馈龄和插值不同，按算法变化报告；同龄数值门另用已有浮点检测/PI/归一化。
共享的插值和初始化不能因该门通过而视为独立验证通过。

采用必须同时满足：原成功零丢失，负例确认及误MAC零新增，资源退出总量不增加，
原数值门通过，新增控制≤128bit、私有历史/端口不增，并有恢复或调度收益。
细搜请求的累计elapsed包含端口等待，不是全链总处理周期；不能以请求减少掩盖资源丢包。
失败仍返回1，拒绝采用且不产生新保留集；通过后才冻结源码/参数/预算并评价独立新保留集。

```sh
PYTHONPATH=.:src:scripts uv run python scripts/model_head_prefetch.py --output /tmp/head-prefetch-development
```

`--inputs`及`--baseline`复核SHA冻结的原输入和旧结果；`INPUT-BINDING.json`
同时绑定输入元数据和结果，避免相同IQ对应的期待答案或配置被后来索引替换。
`--role fixed-regression`的结果不能授权生成新保留集。
载荷和描述符转换仍有显式离时钟参考，完整周期及全链定点均未通过，
当前仅200MHz模型输入时序，100/160MHz及完整16MS/s仍待验收。

## 开发结果：拒绝采用

10流包含12个合法PHY包。与原始捕获消费器相比，有限路径的反馈龄与插值不同；
M36与本次M37之间仅复制调度变化。双包间隔为压力输入，未证明符合具体MAC合法业务期限。

| 路径 | 相干确认关联捕获 | 头CRC | 数据CRC/完整载荷 | 可计算BER |
|---|---:|---:|---:|---:|
| 原捕获消费器 | 10/12 | 10/12 | 8/12 | 217/7424 |
| M36有限桥 | 8/12 | 4/12 | 3/12 | 2/2992 |
| M37头部预取＋功能载荷 | 7/12 | 4/12 | 3/12 | 2/2992 |
| M37未知载荷服务退出 | 7/12 | 4/12 | 未执行/无交付 | 不计算 |

BER对应实际完成解调且可关联的不同集合，不能以幸存者BER较小宣称性能提高。
相对M36，恢复0、完整成功丢失0，尾历史过期4→3，但队列丢弃29→30；
相对原消费器丢失5个原成功包，均保留原输入及实际成功证据。
细搜请求13→8、累计elapsed404760→192510，同时关联捕获8→7，
这不是等召回、等工作负载的计算节省。私有历史峰值505→1024字，未增加容量或端口。
不放宽门限、候选或资源预算；**拒绝该调度，不生成新保留集，不推广默认**。

4个完整同龄事务的有限/浮点门均通过：最大中心差1.933e-6采样、速率差0.001719ppm，
归一化符号RMS9.449e-6、峰值5.430e-5；另3个未完成事务不计数值通过。
此门仍共享插值和初始化，不覆盖它们的独立旧失败，也不等于全链定点通过。
负例32768采样（16MS/s下2.048ms）没有新增确认或误MAC，仅代表该有限观察。
剩余9包中5包已由同一IQ的实际原路径完整恢复，另4包缺少充分诊断，
不据此宣称理论不可恢复。旧正式61/96本轮没有重跑，默认算法数据通路未改。

原型完成10流后，报表误把只在原始回执中的帧资源计数当作摘要字段而抛KeyError；
原始回执、源码、异常及全部结果保留。修正只读取已有实测差值，并先严格核对
原路径摘要及原始传输回执相同；不把缺失字段补零。增加真实安静流的CLI反例，
分别保存原数值实验和修正后的报表来源。最终源码双后端原输入复核另行留证，
不能把报表修正当作恢复包或改变原失败。

最终源码用实际Python/Rust环境各重放10流，均以结构化拒绝返回1；79个输出文件和
90个字/轨迹NPY数组完全一致，跨后端只14处实际整数预筛后端标注不同。
整段、固定和随机RRC输入分块完全一致；新服务本身没有新增Rust实现。
20项针对性测试通过；全量Python5976/Rust5987、覆盖率均超过93.9%。
本地7进程同时运行曾触发120.707/128.847秒时间门失败，原报告保留；
按预先设定的最大4并发重跑完整相同集合，最大102.976/96.951秒，覆盖率门不变。
这些是每个pytest分片的时间，不是整个验证工作流在120秒内完成，也不是FPGA吞吐。
完整CI lint和严格文档验证通过；实际远端CI及制品状态另随提交回执保存，
不把本地通过冒充远端通过。
