# 同步局部插值字的有界复用（SYS-C2E2B-R）

这是[有限Lagrange节点](interpolation-word.md)的单因素结构实验，
对应§6.2.1.2的接收实现选择，复用§6.3/6.9的原严格帧消费。
只缓存初始化已经计算的实际局部插值字，再交给同步保持阶段。
不使用全局样条的`selected_sync`替换局部结果，不改变同步最大值、未来样本等待、
初始拟合、功率更新、Gardner/PI、载波或解析，也不根据CRC/期待载荷重试。

## 接口与寿命

`WordInterpolatedPSKReceiver(..., reuse_sync_interpolants=True)`显式开启，默认仍为False。
字端口仍为4Msym/s、SPS4、1..32字批次和Python时序；未增加Rust字插值ABI。
本轮完整配方比较16/2/22格式、普通FT2/3/4；其他格式的缓存单元测试不代替整链验收。
WS63新增字路径及未知编码前缀未因此获得支持，FT1/GFSK仍独立补齐。

`InitialInterpolantCache`只允许32/62/126同步符号，128槽、实际46/52bit编译输出布局。
第一次填充后只允许一次顺序回放。首整数位置、量化相位和固定SPS4进度必须一致；
错序/改相位明确报错，不回退到另一个同步答案。终态或EOF只失效有效状态，不要求清空RAM。
固定同步阶段的每一次功率更新仍执行；不能通过跳过整个阶段获得虚假收益。
插值质量统计按实际核执行计数；缓存命中不再次量化，也不重复计RNE/饱和事件。
计数减少不表示原输入损伤或量化失败已经恢复。

已知同步末尾的两个原始字仍是第一个数据Gardner中点的依赖。
源字送入插值流水后，流水拥有私有副本；只有证明后续同步保持改读缓存，才可退休较早源字。
最后两字及后续数据必须留在历史中，不能因缓存齐全就释放整个原窗口。
头CRC/合法长度仍只决定帧信任、实际末尾和交付，不选择缓存、相位或载波答案。

## 功能与数值门

`tests/data/initial_reuse_policy.json`在新开发数据生成前冻结：
配对字路径的完整帧、消费/交付索引、CFO/增益、功率及全部采样轨迹要求精确一致，
零原成功丢失、零新增误交付。无观测字段须两侧同时缺失，不制造零轨迹。
新开发改变PID、MCS、包长、载荷、导频、干扰、CFO/SRO及分数起点；
独立保留的正负例配方另列，冻结源码/预算/采用规则后才生成。
旧已查看集合仅作固定回归。

首轮新开发完整数6→6，原30请求中19评分、13→13完整，判定和轨迹精确。
两组合计省1540次插值/6160次原字读。这是同步段复用，不能写成整包工作量减半。
源码/参数/预算及采用规则冻结后，新独立保留完整数5→5（6包），零原成功丢失；
省440次核调用/1760次原字读。开发加固定回归总调用293822→292282（0.524%），
新保留121508→121068（0.362%），不将局部节省写成整体吞吐倍数。
新保留`validation-1`仍4/7096bit错误、数据CRC失败；与原路径相同，尚未有足够诊断支持归因。
不得将其写成理论不可恢复或已修复。两组负例分别30720/33280采样内零新增误交付，
重复分块不增加独立观察量；不宣称任意环境绝对零误检。
原RMS0.000150245＞0.0001仍失败，字接收后端仍未通过采用门；
位精确复用不修复初始化量化误差，旧RRC2.34835%＞2%及16KiB失败不改写。
接收改善、数值门与结构节省分别记账，不以整包相同覆盖数值失败。

## 实际端口及周期节点

`InitialStencilService`借用已有`ReceiveHistoryPort`，不复制私有整段尾部。
保留原最后同步点的未来样本等待条件，使用四字暂存、现有七阶段Lagrange流水和有界缓存。
`InitialInterpolantPort`每周期最多一写/一读、注册读1周期，只有一个保持回复槽。
填充与回放阶段互斥，最后缓存字出库后，未消费回复仍有独立所有权。
输入满、EOF缺未来、输出长期阻塞均明确终止候选、清理在途信用；不静默丢输入后继续宣称有效。

节点模型停在“缓存齐全，初始拟合服务未知”。模型给出若不再退休原样本时的剩余容量及截止时间，
但不把初始拟合、同步功率更新、PI、载波、头或译码填成零周期。
持续到达的**已选窗口**不等于完整ADC→RRC→捕获→MAC；实际运输/窗口服务组合仍待闭合。
保留原始样本用于第二次计算的控制实验只是寿命反事实，不是完整旧接收机性能。

FT4正常写出时：从原等待条件满足到缓存齐全1036周期，
100/160/200MHz下保留原字策略仍在索引512退出；有界复用节点可完成初始化。
长时间堵塞仍导致资源退出，全部失败关联输入字和周期；不能据此抹去原三项整链启动失败。
即使本节点完成，原双查询反馈的100MHz超期、160MHz零余量、200MHz仅10周期仍需闭合。

## 增量成本与整机关系

| 项目（16/2/22） | 增量/假设 |
|---|---|
| 缓存 | 128×52＝6656逻辑bit；拟1个RAMB36E1 SDP512×72，未用容量无共享信用 |
| 另一存储候选 | 104 LUT6＋52 MUXF7的128×52单口分布RAM，填充/回放互斥；未综合 |
| 缓存控制 | 106bit，含首位置64、相位17、长度/写/读各7、状态及有效位 |
| 注册端口/回复/时钟 | 317bit，含真实52bit回复、7bit索引、64bit就绪时刻与3×64时钟字段 |
| 源访问控制、四字暂存及等待统计 | 418bit；完整新增控制/暂存合计841bit |
| 原字端口 | 既有1R1W，不新增读口或隐含复制；原历史RAM及状态另计 |
| 既有插值核 | 保留6 DSP估算、2057bit流水、统计/ROM；未增加DSP或获得跨模块共享信用 |
| 控制逻辑 | 缓存键64bit加法/比较及17bit相位比较；源2条64bit地址加法、3条10bit索引路径等，LUT/时序未知 |

计费曾漏服务长度7bit与退休配置1bit，首版769bit及源码保留；另加64bit等待统计后为841bit。
1024bit控制/6656bit载荷/1BRAM且额外DSP和源读口为零，是事先冻结的候选节点预算，
**不是新批准整机预算**。未改变旧模块限制，也未用芯片空余资源改写旧失败。

FT4同步段252→126次核调用：少756次实数原语乘积、3780次系数/Horner加减、
1764次除6 ROM读、504次46bit源读；新增126次缓存写和126次52bit缓存读及地址/控制。
包内数据段的工作量不变。缓存与初始拟合暂存不能直接认定共用，源与缓存是不同银行。
收发、Polar、实时MAC、DMA和调试预留仍见整机账本；本节点没有综合/布局布线证据。

## 复现与验收边界

```console
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_initial_reuse.py --split development --selected-root SELECTED_ROOT --capture-root CAPTURE_ROOT --word-root WORD_ROOT --output NEW_DEV
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_initial_reuse.py --split validation --freeze NEW_DEV/freeze.json --output NEW_HELD
```

脚本预期返回1：保留整体数值/资源/接收验收缺口，节点精确不转换为整机成功。
头CRC、数据CRC、长度、MCS、载荷、BER、原SHA关联和所有资源退出分别保存。
Python/Rust环境中的字插值时序均为Python，实际原生组件由后端记录核对。
