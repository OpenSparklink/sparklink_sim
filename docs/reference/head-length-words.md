# 有限字级帧几何：B1线上长度到帧末尾

本模块是接收机的一个标量节点，不是完整流式接收机。
继承已验证的整数SSC银行和已有头部原型中的有限几何程序，不重写捕获、定时、载波或Polar。
原型接收B1真实长度39时，重复加CRC，四个末尾397/621被算为410/634或415/639；
旧源及四个反例在本阶段证据`head-word-standard/geometry-port-baseline.json`保留。

## 接口与合同

`HeaderGeometryService(frame_type, crc_len, pilot_interval, length_contract="standard")`
编译FT2/3/4、CRC24/32及导频0/4/8/16的标量几何。输入`issue(length, mcs)`只接受
11位长度和MCS0–12，**上游仍须实际校验头CRC、检查长度/MCS政策**；本节点不提供成功CRC标志。
MCS15重传上下文、A组空包语义及完整波形合法组合不能由本节点补足。

- 标准B1原始长度含CRC，实际程序执行`payload=length−CRC字节数`、`B=length<<3`。
  长度0走显式零数据分支，`coded_bits=0`、`data_crc_present=False`；不编码空数据块。
- 非零长度等于3/4字节时是CRC-only，与没有数据CRC的零长度不同。
- FT2的信息长度仍加CRC一次。既有B1模型的payload-only长度通过接收前明确选择的
  `legacy-b1-payload-length`保留，不做CRC回退或猜测合同。
- 长度比较只做端口有效性前提校验，Python返回的导出长度不传给数据通路。
  测试把该返回值故意改为999，实际微程序仍计算出正确35字节和397末尾。

输出是符号索引，起点为已选同步字首符号，前导不包含在该坐标内。
`data_crc_present`只表示字段存在，不能作为数据CRC校验成功或MAC交付条件。
数据导频计数保持当前参考模型；FT3/4恰落整导频间隔的末尾规则仍另行审计，
见[B1长度合同](b1-length-contract.md)。不由参数可构造推断所有标准配置已经验证。

## 有界数据通路与状态

一个拥有的上下文，无请求FIFO。`input_ready`为False时拒绝请求并计`input_stalls`；
结果保持到`take()`，每个等待周期计`output_stalls`。不丢弃结果、不累积无界工作。
`abort`放弃当前运算，`reset`要求先排空或中止；计数器64位溢出明确报错。

输入接受边沿捕获11位长度和4位MCS。编译上下文保持；无需每包清零所有物理寄存器，
程序在读取动态寄存器前写入它。下一边沿锁存一次384位常量行，此后每周期执行一条指令。
两个24位组合FF操作数读端口、一个24位寄存写端口；输入长度和MCS捕获另列。
ROM使用分布式LUT：常量行／分段表共享一个数据读口，指令ROM另有32位组合读口。
宽常量行按真值列和384位参数锁存计费，不能当成免费单个BRAM口。

所有数据寄存器signed24，24槽；除法输入/余数/商unsigned23，试减中间量unsigned24。
恢复除法真实执行23步，乘法真实执行10步移位加法；没有隐式变量除法或单DSP任意宽乘法。
整数运算无舍入、截断或饱和，越界抛模型错误，不静默回绕。
这些检查不是已经综合的运行期故障检测器；合法操作数范围必须成立。

最宽直接移位上界为`(2047×8+32)×8=131264`，故signed18不足。
当前选择signed24，与原型一致，没有为通过旧反例增位宽。
分段乘数最多10位、所有MCS由编译表提供；程序及实测节点范围保存在模型JSON。
采样边界覆盖不等于对任意未列配置的溢出证明。

## 操作、容量与周期

| 项目 | FT2 | FT3/4标准B1 |
|---|---:|---:|
| 编译指令数 | 49 | 25 |
| 本阶段最坏服务周期 | 181 | 69 |
| 分配数据寄存槽／实际最高使用 | 24／21 | 24／15 |
| 总逻辑状态及常量容量 | 8452 bit | 7684 bit |
| 独立DSP／RAMB18 | 0／0 | 0／0 |
| 常量／指令ROM真值LUT上界 | 58 | 56 |

表中LUT数**只含ROM真值逻辑**；两路FF读多路器上界3024个2:1位选择器、
24位加减、比较、移位、控制及布线未变成综合LUT总数，完整LUT/FF和Fmax仍未知。
64位统计、周期、控制、参数锁存、串行引擎及输出保持均计入；输出复用稳定寄存器，
没有隐藏输出FIFO。相对旧原型8260/7364bit，FT2增加192bit、标准B1增加320bit；
其中两项反压计数为128bit，其余为实际指令ROM扩展。动态寄存器最高21/15槽仍在原已计费24槽内。

在100/160/200MHz**假设成立**时，181周期分别1.81/1.13125/0.905us，
69周期分别0.69/0.43125/0.345us。单上下文II包含服务和任意输出等待。
这不包含捕获、头部解映射/解扰/CRC、载波、载荷或译码调度，不能推导整链16MS/s。
上游校验周期为null，不填零；原16KiB、数值及连续输入资源失败均保留。

## 验证与复现

```sh
PYTHONPATH=src uv run --frozen python scripts/model_header_geometry.py --output /tmp/new-header-geometry
```

输出目录必须不存在。模型保存原始输入SHA、源SHA、实际参考后端、完整字表、节点范围、
实际微程序周期、操作计数及六个逐边沿日历。
40个结构配置各91个标量边界/MCS样本，共3640次；其中标准FT2/B1与旧legacy分别记录。
输出容差为整数0；50项针对性测试涵盖坏长度、零分支、CRC-only、所有MCS、端口/保持/中止。
六个原始冻结符号帧经已有真实头CRC解析后，有限几何输出与参考逐字段一致。
这是已选符号域标量交接对照，没有形成新的未知起点捕获或RF保留集结论。

浮点接收功能和既有载荷不变；本节点四层结果只有整数/结构/可执行周期证据，
没有综合或布局布线证据。四项完整接收机验收仍各自未通过。
下一步将此有限程序接入真实头部服务和同一已选帧消费，计入合同/导出长度/握手状态；
不能用主机先算好末尾再把未知处理写成零周期。
