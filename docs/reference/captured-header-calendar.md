# 捕获帧的已知头部服务日历（M30，实验）

`ClockedHeaderCapturedFrameReplay` 在已有实际候选回放中补上有限头部服务的可用时刻。
它继承原所有者，复用同一选中同步、Gardner/PI、严格头部解析、合法帧尾及 MAC 门，
不重新搜索或根据 CRC 重试答案。依据为原标准 §6.3、§6.9 及既有头部 Polar 服务；
标准版本、SHA 和已核对范围见 [原始依据](standard-sources.md)。

## 补上的关系

原 word 头部确实完成硬位解扰、有限 SSC、真实 CRC、字段策略和合法帧几何，
但实际捕获帧所有者在一次 off-clock 调用后立即公开结果，没有等待其正的服务边沿数。
冻结基线中 FT2 好头／坏头分别需要 1837／1768 沿，FT3 为 4421／4351 沿，
公开结果相对最后头部原始样本返回沿的间隔却均为 0。该基线是已承认的调度缺口，
原实现没有因此获得完整延迟或 16 MS/s 通过结论。

新类仅接受 `word-dense` 或 `word-depth-parity`，从实际 `head_word_model.service_edges`
取得正且不超过 10000 的服务数，调用者不能指定延迟。最后头部样本触发原功能接收器，
实际头部回执暂时私有；公开的 `header`、长度／MCS、头失败终止和载荷消费均等待
`issue_cycle + service_edges`。原功能对象中的早到元数据只供调试，不能作为调度接口。
下游阻塞可继续推迟交付，不能提前交付。只复用这一份回执，不运行第二个头译码器。

这是**实际整数服务回执的延迟回放**，不是第二份逐边沿译码执行。
假设 N 个硬解映射位在显式功能边界同时齐备，之后不抵扣解扰、SSC、CRC 和策略服务。
它还没有给插值、定时、归一化、头部解映射、相干确认或载荷载波／译码建立完整时间线；
这些工作仍为 off-clock，完整绝对延迟保持 `None`，完整周期证据保持 false。
不能把增加一段已知等待描述成整链接收周期已闭合。

## 样本和失败所有权

等待期间 `needs_word` 为 false，没有新原始读取，实际消费索引与退休前沿不变；
输入生产者、共享环及其他窗口搬运继续运行。只借用原同步窗、4096 样本共享源、
512 样本功能历史和一份回执，未增加整段尾部缓存。
头 CRC／长度合法后按已有真实帧尾继续消费。坏头或非法字段只在服务就绪后退出，
不读取不可信长度、不处理载荷、不向 MAC 交付，也不选择替代候选。

EOF 不能绕过待完成头服务。正常服务完成后，缺少的载荷仍报告截断，不能填充 IQ。
源 epoch 故障、历史过期或显式取消会丢弃待交付头结果，形成资源终止，不能交付部分包。
终止被取走后才能释放窗口；逐包时钟状态复位，累计统计保留。
调度等待导致的历史过期或槽满必须与算法本身漏检分开报告。

## 有限成本

新增日历 397 bit，上限为预先定义的 512 bit 模块研究预算：三个 63 bit 时间戳、
14 bit 服务数、两个有效标志、三个 64 bit 统计。服务数 0 表示未发起，
就绪／公开时刻 0 为无效哨兵（正服务不可能在第 0 沿结束）。
累计所有者控制为 1090+397=1487 bit；每次发起有一个 63 bit 加法，
等待检查有一个 63 bit 比较，控制按一沿假设。LUT、FF 映射及 Fmax 未综合。
无新增原始 RAM、DSP 或样本端口，不以此省略已有译码器。

| 实际头布局 | 已有头服务逻辑 bit | RAMB18 等价 | BRAM36 站上界 | 并行硬位输入 |
|---|---:|---:|---:|---:|
| FT2 A2 dense | 18384 | 3 | 3 | 64 |
| FT3/4 B1 depth-parity | 42078 | 6 | 5 | 256 |

这是已有 `HeaderWordService.cost()` 的逻辑／布局估算，需与 RRC、粗细核、共享历史、
选中缓存、TX、实时 MAC 等同时计账。未证明跨模块复用，不抵扣任何 RAM 或译码预留。
头服务自己的逐位读取、SSC RAM 端口、几何与 CRC 成本保持原账本；
新类没有增加它们的并行度，也没有新增免费端口。

仅以好头回执换算的敏感性如下；这是时间／到达量算术估算，不是这些频率的整链模拟。

| 时钟 MHz | FT2 1837 沿 µs／其间 16 MS/s 到达样本 | B1 4421 沿 µs／到达样本 |
|---|---:|---:|
| 100 | 18.37 / 294 | 44.21 / 708 |
| 160 | 11.48125 / 184 | 27.63125 / 443 |
| 200 | 9.185 / 147 | 22.105 / 354 |

## 复核与采用限制

`scripts/model_captured_header.py` 要求显式冻结清单 SHA，每个 IQ 文件再逐一核对 SHA，
比较原功能所有者和新日历的整段／固定块／随机块、CRC、完整载荷、BER、
真值仅供事后关联的轨迹，以及资源丢弃。原始输入只读，派生轨迹独立保存。
所有已查看输入只作固定回归，不用于调参或宣称独立新保留集接收增益。
如增加原成功包丢失或资源丢弃，报告与命令以失败保留，不通过扩缓存消除证据。

```sh
PYTHONPATH=.:src:scripts python scripts/model_captured_header.py \
  --input-dir /path/to/frozen-inputs \
  --manifest-sha256 SHA256_OF_inputs.json --output /path/to/new-output
```

命令返回 1 表示该对照增加资源丢弃或丢失原成功包，不能当成入口异常忽略；
返回 0 也只表示这些已测固定输入的局部对照通过。
默认接收器、同步／载波选择、数值预算、16 KiB 旧失败均不改变。
原 word-full12-c18 2.34835%>2%、插值超预算以及四项总门继续分别保留。
适用范围仍是普通 FT2/3/4、4 Msym/s、SPS4、MCS8/12 无编码载荷；
FT1/GFSK、未知厂测编码、完整定点和整链连续 16 MS/s 均未由本阶段验收。

## 固定回归结果与拒绝结论

对原 SHA 绑定的 20 个合成输入做固定回归，含两组各 12 个目标包及四类负例。
两组均已查看，不称作新保留集，不据此选择服务步数或调整参数。
密集输入沿用 M28 压力间隔，未验收为合法 MAC 业务间隔；因此不能仅据此次失败
推导所有合法业务负载下的 16 MS/s 都无法实现。
下表的捕获是实际相干确认次数，不是理论可恢复包数；完整载荷另按长度、MCS、
真实头／数据 CRC 和全部期待字节检查。期待字节与真值只进入事后分析。

| 固定集合／所有者 | 相干确认 | 头 CRC 通过 | 合法长度／许可 MCS | 数据 CRC／完整载荷 | BER 错误／可计算位 | 槽满 |
|---|---:|---:|---:|---:|---:|---:|
| 开发，原功能 | 10 | 9 | 9 / 9 | 9 / 9（目标12） | 0 / 4248 | 23 |
| 开发，已知头日历 | 9 | 8 | 8 / 8 | 7 / 7（目标12） | 99 / 4096 | 28 |
| 已查看回归，原功能 | 10 | 8 | 8 / 8 | 6 / 6（目标12） | 170 / 5120 | 21 |
| 已查看回归，已知头日历 | 9 | 7 | 7 / 7 | 5 / 5（目标12） | 170 / 3736 | 25 |

完整包合计从 15/24 降为 12/24，无新增恢复。原成功丢失为开发 case3/packet1、
case5/packet1，及已查看回归 case5/packet1；原获胜候选分别为 id5、id7、id4，
在新时间线中均明确 `owned_queue_full`。新增槽满共 9 次，不能用相同源输入或
幸存包正确掩盖它们。开发 case3 随后实际接收了另一个已有候选 id8，产生 99/296 位错误，
仍按数据 CRC 失败保留；没有以 CRC 在两个答案间挑选。
所以聚合 BER 的分母／包群也改变，不能把上表差值当成同一批判决的量化损失。

共同原成功包的起点、分数和采样轨迹精确一致，共同细搜索的整数结果与输入窗精确。
整段／固定块／随机块结果、真实 Python／Rust 环境的所有非后端标签 JSON 及
176 个 NPY 成员逐字节一致。36 处 `integer_screen_backend` 标签差异的严格全 JSON
失败单列保留；新日历和头部整数结构均仍在 Python 执行，未增加 Rust 实现或速度结论。
四类负例在两个集合共 65536 个唯一输入采样（16 MS/s 下 4.096 ms）中无 MAC 误交付，
不把重复分块或后端运行翻倍计算为观察时长，也不声称所有环境零误检。

头日历本身因果可用关系和有限接口测试通过，但当前单所有者资源调度方案不通过
“原成功不丢失”的资源验收，保持显式实验，不推广默认。
测试、浮点功能、数值门、资源门和完整周期门继续分开：全量 Python/Rust 环境
分别 5690/5701 个测试身份，覆盖率 93.88%/93.89%，最大分片 110.055/105.770 秒；
这些测试通过没有覆盖原 RRC／插值数值失败，也没有证明整链 16 MS/s。
新增服务只让原有成本进入部分日历，不能当成新增算法接收退化后隐藏或回退成免费工作。

下一步优先检查已退休窗口的更早入场拒绝／槽位释放及细搜索与头服务的有限并发，
须先定义状态与端口成本，并在新的开发配置组合上独立选型。
原单所有者的失败和所有输入、候选、CRC、轨迹及 SHA 关联保存在冻结证据根
`captured-header-calendar/RESULTS.json`、CSV、逐流报告和原型留证中。
