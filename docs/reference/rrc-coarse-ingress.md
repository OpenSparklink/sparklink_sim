# RRC与粗捕获的有限入口（M21，实验）

对应普通PSK §6.2.1.2/§6.2.3实现结构。仅限当前4 Msym/s、SPS4、81抽头实验RRC、
scaled10和FT2/3/4；同步字、评分、门限、相位选择和环路不变。不是FT1/GFSK实现。
`CoarseIngress`复用现有RRC字桥、原始能量标志对齐器和银行粗核，不改变默认接收流水线。

## 接口与样本所有权

每沿可分别输入一个连续标号的原始能量标志及一个单调标号的RRC输出脉冲；
`None`表示上游已判无效的RRC结果。输入后调用一次`step()`，显式消费既有候选输出信用。
不能直接驱动内部节点的时钟。RRC、桥、标志及粗核使用相同源采样身份，不能压紧缺失标签。

顺序为：提交旧待查标签→将旧就绪对齐字移交粗核→各节点推进一沿。
移交本沿创建的查询不得本沿提交；必须等待该采样标签所需全部评分已提交。
每32个已移交标签，在完整搜索窗存在原始能量时提出一个固定原范围的查询。
一个待查标签、原粗核两个排队查询和一个结果信用全部有界；未获信用的请求明确计为资源丢弃。
不按CRC、期待载荷或真值改变查询、同步答案或重试次数。

RRC身份缺失、无效、桥信用拒绝或节点故障将终止本epoch。已持有候选和待查标签取消并计数，
其后原始标志及RRC输出仍计数，ADC没有被暂停；不自动重新捕获或用后续数据填补缺口。
合法业务是否能无丢弃持续承接与过载时是否有界分别验收。

`drained`只表示可结束内部工作，仍可能存在等待EOF判定的缺失标志/字。
`finish()`要求排空工作及持有候选，否则拒绝且不关闭；随后真实处理孤立标志、缺失RRC尾部或缺失标志。
返回值仅表示该源/查询前缀未损失，不能当成CRC、MAC交付或完整接收机成功。
每包和重新捕获的epoch交接尚未连接完整帧所有者，不能由此宣称任意多包整链完成。

## 格式与成本

沿用19+19+8 RRC字、10bit粗核及其全增长整数域。样本ID、故障标签、待查标签和时钟按63bit计费；
查询端口较窄，入口先限制坐标至signed62范围。非法编码指数在消耗事件/标签前拒绝，
不把已报错输入作为成功接收。合法RRC生产者的指数范围仍为[-96,48]。
对软件类型/生产者不变量的断言不等于已有物理故障检测器；额外硬件异常响应周期仍未知。

新控制状态包括待查信用、RRC连续身份、每沿单写保护、故障和EOF及12个64bit统计。
研究上限1536bit在实现前冻结，没有新增IQ FIFO、DSP或采样RAM。
既有桥、标志FIFO、历史、系数、评分、查询及候选容量分别相加，不能用新节点的零新增DSP代表整个前缀。
宽地址减法、端点增量、比较、选择和统计加法单元单列，组合LUT、映射FF与Fmax仍未知。

RRC仍采用已有8DSP与实际端口/历史生命周期日历；首选银行粗核另需12DSP，无已证明的共享。
每路径已知专用前缀为20DSP，检测器、细搜索、译码及包内处理尚未据此取得周期资格。
原18DSP/16KiB粗核研究界继续有效，这个相加结果没有批准新的整机预算。
RAM原语、端口复制、流水寄存器、双路径、TX/译码/实时MAC预留和基础工程仍需整机账本核对。

## 验证与边界

独立整数参考检查每个已提交点及归一化查询，真实RRC输出时刻来自既有`PairRRCFlow`，
不会将滤波、信用等待或初始化设为零周期。功能RRC分别使用整段主机调用、固定和随机分块，
所有调用内部仍遵守原1..32样本入口上限；比较字和采样身份，不能解除入口检查冒充支持。
源、标志、桥、粗核、未退休工作、请求/候选取消及EOF分别核算。

原始检测标志目前由既有浮点检测器提供，10/80沿只是明确的服务延迟假设，检测算术周期未知。
RRC日历与字算术保持独立，尚无综合/布局布线或整条逐沿物理数据通路证据。
预先冻结200MHz首选布局的源/查询无损条件；100/160MHz、FT4八银行、慢标志及输出阻塞作为显式失败对照。
正常负载不能以丢弃通过；过载有界也不能填成正常接收率。

开发输入变化载荷构造、帧型、MCS、长度、导频、干扰、起点、CFO/SRO及幅度；
冻结源码、参数、预算及采用规则后才能生成新保留输入。所有已查看数据仅作开发或固定回归。
现有未计时IQ→MAC上下文单列，不能为未连接该控制器的MAC结果计入新RF收益。
原RRC2.348%>2%、插值及16KiB等失败、正式61/96未重跑结论保持。

## 冻结实验结果

两环境全量收集5411/5422项、无断言失败，旧M20用例全部保留；覆盖率均93.82%，本节点97.83%，
最长分片80.459/76.670秒。开发21项、冻结502项源码/参数/预算后新保留21项，
所有已提交整数、归一化查询和源/EOF记账精确；只有六个首选200MHz布局通过入口采用条件。
每项源前缀3072采样（192微秒），不足以据此宣布任意业务的持续整链接收。

| 条件 | 入口结果 | 归因 |
|---|---|---|
| 200MHz，FT2/3八银行、FT4十六银行，标志延迟10沿 | 六布局均3072接受/提交，无请求损失 | 仅该源/查询前缀通过 |
| 100/160MHz | 各6项失败 | RRC服务/历史、标志积压或源身份缺失 |
| FT4八银行，200MHz | 失败 | 粗核服务不足，桥拒绝后显式终止epoch |
| 标志延迟80沿 | 失败 | 只有一个IQ信用，无法等待如此晚的标志 |
| 候选下游阻塞 | 字源3072仍提交，入口失败 | 查询丢弃和历史过期；不是漏记或暂停ADC |

每个集合15/21资源失败保留。原始标志FIFO的首选布局观测峰值5/16、差分队列47/64，
桥/待查/候选信用均1；模块内粗输入和查询峰值均1，不能用控制器边界采样值0替代模块内部峰值。
只读profile观测与原事件、字、查询逐项精确，不反馈到算法；若在FPGA增加峰值监控，还需另计资源。
每沿实验驱动先送原始标志，再送RRC释放脉冲，最后推进时钟；同时异常时首故障分类按该顺序报告。

| 首选布局，serial2 | 每路径已知逻辑bit（含RRC，不含检测等） | 未含RRC/检测的寄存器上界 | 末512字最大延迟（沿） |
|---|---|---|---|
| FT2 / 8 | 80335 | 25011 | 115 |
| FT3 / 8 | 95083 | 25411 | 119 |
| FT4 / 16 | 128729 | 30765 | 120 |

原Q12流水线对应逻辑bit为84559/99390/133142，末512字延迟120/124/125沿；
新入口自身1026bit，无新DSP/IQ RAM，每路径已知RRC+粗核专用20DSP，粗核预留2BRAM36站。
逻辑容量不能直接等于物理BRAM或整机预算。两FT4路径在未含RRC/检测时寄存器上界已为61530bit，
高于原待论证25%余量方案的58089bit；该保守映射没有取得整机资源资格，也不能据此证明芯片理论上放不下。
当前逐沿只验证原始路径，单音路径及其并发不能由同格式成本估算直接取得时序资格。

未计时旧字银行/银行功能版IQ上下文各13流、39次整段/固定257/随机1..257比较精确：
正常均6/7完整，恢复0、丢失0；总漏斗9捕获、8头CRC、6数据CRC及6完整。
错误同步字背景各一漏检，尚未做该新样本的真值重放，信息是否足够未知。
坏头、坏数据及截断控制独立拒绝。负例共139264独立采样、8.704毫秒未新增MAC交付，
后端和分块重复不增加暴露量；这不是新的定时入口已连接MAC或绝对零误检证明。

仅供诊断地观察原载荷译码器返回值，并确认所有帧、CRC和轨迹不变：
正常可比较位分别0/12672、0/15568错误；两个故意坏数据控制各16/2056错误，CRC仍失败。
漏检、坏头及未调用完整载荷译码的截断不填成BER零。没有改变期待答案、剥离前缀或用CRC挑答案。
两真实依赖环境各103JSON/277NPY成员及全部解压事件精确，输入直接按原SHA复制，没有再生成后换输入。
新入口和粗核仍是Python模型，Rust实际用于既有CRC/Polar；未伪造原生入口或主报告。

原默认接收源码没有改变，原压力61/96未重跑。全链定点旧失败和四项总门仍开放；
输入浮点到12bit共同指数的适配、检测算术、细搜索、窗口/帧所有者及译码调度尚未闭合。
真实FPGA综合、布局布线和200MHz没有新增证据。下一步优先查清RAM/端口映射和细搜索最坏工作量。
