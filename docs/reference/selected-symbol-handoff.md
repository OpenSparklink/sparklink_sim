# 已选候选的实际缓存、插值与严格帧消费交接

SYS-C2E2D-HANDOFF沿用[有限同步初始化](known-sync-word-fit.md)，对应已登记标准的
§6.2.1.2接收实现、§6.3帧结构、§6.4控制字段和§6.9 CRC。
新增的是实际字值和所有权交接，不改变同步评分、候选、相位网格、原Gardner/PI或载波方法。
普通FT2/3/4、4Msym/s、SPS4是本轮验证范围；FT1/GFSK和新WS63字路径不据此宣称支持。

## 交接及接口

`SelectedFrameReplay(profile, prepared, **selection)`只接受已就绪的
`InitialSyncFitService`。同时核对实际同步模板、粗CFO种子、位置/相位、缓存状态、
源历史与流水信用；缓存未就绪、已读或种子/模板不符时明确拒绝。
取走拟合结果后，原初始服务不能再step/abort/EOF，避免另一个拥有者清掉接收中的源样本。
复用同一个源银行、注册缓存端口和6DSP插值核，不复制整段尾部，不重新拟合同步区。

源银行可从真实的非零`first_index`开始：头/尾指针初始化为空窗，不能读取此前未提供的样本。
地址仍用真实索引取模；没有将NCO坐标减去窗口原点，避免浮点累积因重定位产生新轨迹。
测试驱动从**实际已选**起点的前一采样开始供给原字，记录父归档和原窗口原点；不使用真值位置。
初始服务的`start_cycle`支持非零运输时钟域起点，默认0保持兼容。
这不是捕获槽到历史银行的生产者已经实现的证明，生产者的搬运/共享和排程仍需接入。

`InterpolantPSKReceiver`复用现有的初始化安装、每符号Gardner/PI、归一化及严格帧边界函数。
默认接收器仅抽出同义钩子；本轮固定回归还与此前冻结的数值/帧结果逐项核对。
同步回放中的每次功率更新都保留，前一采样在已知同步期间不参与TED，符号0会安装实际值。
新消费端没有私有原始采样历史；实际52bit插值字从原缓存或注册源→原插值核进入。
原有合法最大符号数组仍是浮点参考存储，不能当作已经分配的定点RAM。

控制器有三个明确的未知算术服务：

1. `symbol`：功率、Gardner/PI/NCO、坐标生成、初始载波校正和增益归一化。
2. `header`：原载波/软信息、头部解码及真实CRC、长度/MCS检查。
3. `payload`：原载波/导频、解映射/LLR、实际编码译码和数据CRC。

`step()`只推进已经建模的真实端口和字流水，遇到服务请求后停在等待状态。
继续给step不会偷偷执行浮点算法。`resolve_functional()`显式执行原参考算法，
从此将整链周期证据置为无效，完整延迟保持`None`；它不是零周期或一周期的硬件实现。
时钟标记用于已知运输子图/信用，不用来证明离线函数能实时处理ADC。

## 合法帧终点、EOF与余量返回

头CRC通过前，控制器只产生已知同步及头部的当前/中点查询；头服务未完成时不预取载荷。
只有严格解析返回可信头及合法长度/MCS，才设置`frame_end_symbol`。
坏头、错误种子、非法长度/MCS立即终止；数据CRC或完整载荷错误仍失败，不换相位/CFO重试。
普通头部固定导频独立于载荷导频设置：本轮FT4、载荷导频0仍有
126同步＋256编码BPSK控制数据＋63控制导频，完整头末尾为445符号。
测试的385符号截断仍在头部，不得假设已进入数据。

每个当前/中点只读真实的四点模板。除了四点齐备，还保持原
`ceil(current_center+3)`未来样本等待条件；EOF缺这一点时，已算但未提交的插值结果也丢弃并记录。
不制造未来补样，不因为四点插值值已可算而提前提交一个原接收器不会接收的符号。

按真实下一查询依赖退休源字，最后两同步原字一直保留到首数据中点使用。
终止清掉在途插值、源/缓存回复和候选状态，只退休确实读过的前缀；
已经到达但未消费的后缀留在同一源银行，由`release_source()`归还下一拥有者，不拷贝或静默清除。
补强测试刻意推迟就绪结果的交接，让包后超过128个样本先到达，再逐字核对原银行后缀。
这与只有一个保守未来样本的普通短包终态不同。

`take_mac_result()`通过公开的`mac_result_from_events`复用原严格MAC门，只有状态、
真实头/数据CRC、合法长度和完整payload均满足才交付；一次取走后不重复交付。
`feed_replay_words(1..32字)`是可暂停功能源，仅接收当前所需前缀。
`write_input`则用于显式不停顿到达日历；溢出/耗尽会产生资源失败，不当作算法CRC错误。
每个上下文只消费一个选定候选。包间新建环路/拟合/缓存状态，源银行后缀可移交；
上游连续RRC历史不在这里重置。完整多候选/密集包生产者和仲裁仍未闭合。
本包消费者的退休位置不授权全局检测器跳过这些采样；其他候选所需历史及多拥有者租约
仍需生产者/仲裁设计证明，不能把局部源归还当作全局样本完整性通过。

## 四字暂存的有限重叠复用

比较两个结构，不同时修改插值或环路：

- 参考：先当前、后中点，各读4个原字，共8次读。
- 候选：先中点、后当前；原核拿走自己的四字后，四字暂存保留重叠后缀，只补新地址。

查询角色、中心和分数相位保持，返回时按角色提交相同字，不按相关幅度或CRC排序。
通常复用2字，实际按地址差处理并校验0..4，不截断高位造成错误别名。
仍至多4个源暂存、2个返回插值字和一个待执行服务，不新增第二套原始包尾。
原核自身保存的四点上下文继续计入其既有2057bit流水，没有遗漏在途副本。

| 项目 | 当前优先参考 | 中点优先复用 |
|---|---:|---:|
| 新开发实测源字读 | 370400 | 277796 |
| 新开发完整包 | 6/6 | 6/6 |
| 典型每跟踪符号源字读 | 8 | 6 |
| 数据齐备时局部运输调用边沿 | 45 | 45 |
| 新控制状态估算 | 同一数量级 | 1446bit |
| 四字压紧数据mux2上界 | 0 | 368 |
| 附加DSP/原始RAM | 0/0 | 0/0 |

读次数减少约25%，不是整链接收率或吞吐提升。
数据全齐的独立运输测试：首读请求到末插值返回相差44边沿，控制器事务占45个调用边沿；
两结构相同，不能用可暂停输入时的总运输边沿差推断硬件速度。
当前串行反馈结构在100/160/200MHz每4Msym/s符号分别只有25/40/50周期；
45边沿仅是已建模子图，在本模型约定下100/160MHz不足，200MHz只余5个边沿给后续未知服务。
这不是综合结果，也不证明其他架构不可能实现。

新增1446bit计入4×46暂存、2×52返回字及有效位、64bit地址/期限/服务时间、
两个查询坐标/相位/角色、状态和11个64bit统计计数器；与原初始控制的暂存不计免费共享收益。
复用方案另需一个64bit地址差、两条64bit范围检查和至多两层四字压紧选择；
368为数据选择mux2上界，不是完整LUT数。控制LUT、宽加法/布线与时序均未知。
源1R1W、缓存注册读1周期；原512×46银行、128×52缓存、拟合和6DSP插值核仍分别记账。
浮点功率/PI/NCO、归一化、头/载波/译码的节点格式、存储和周期未知，不填零。

## 验证、采用范围与失败

开发配方变化载荷、FT/MCS、导频、包长、PID、幅度、干扰、CFO/SRO和分数起点。
已查看集合仅固定回归；方案、预算、源代码及采用规则冻结后才生成合法的新保留集。
首个保留配方PID6在FT3/4合法性检查时失败，未产生任何IQ或载荷，原配置及日志保留；
更正为合法PID5并添加双配方预检查，算法和预算不变。

新开发6/6、原30请求中的19个有可评分几何、15个可交接，原13完整全部保留。
4个原相干拒绝、2个数据CRC失败、11个几何不可用继续关联原输入SHA，不算独立包接收率。
冻结后的独立合法新保留集6/6，头CRC、数据CRC、长度及完整载荷均6/6；
开发载荷0/21392bit、保留0/25648bit错误。原路径与新路径的真值定时最大误差分别
为0.138859/0.116483采样，逐符号相同；这是本次测试观测，不是新的定时合格限值。
纯Python与实际Rust扩展环境共有1228个数组和126个帧记录逐项完全相同；
新字运输/环路桥仍为Python，不能据此宣称已存在对应Rust硬件数据通路。
负例开发43008、保留45056个采样（16MS/s下分别2.688/2.816ms）均零误交付，
观察时间很短，且仍使用单候选测试夹具，不能推广为连续接收误检上界。
没有独立定义锁定判据，本阶段不把残差或零载荷错误冒充失锁/周期滑移测量。

本阶段上游整份记录的一次最大差分峰仍是夹具，不是有界未知起点捕获率证明；正式61/96不改写。
整段32字、固定7/31、随机1..32的帧和轨迹逐数组相同；实际插值字逐个按角色与原位置核对。
头CRC、数据CRC、长度、MCS、完整载荷及可计算BER分别记录，未知厂测编码前缀不参与本轮。

不停顿输入的9个100/160/200MHz情景保留：FT4原初始化在100/160MHz仍溢出；
其余情景到达第一个未知符号服务后不执行它，最终产生有界资源失败。
这是服务缺口/阻塞对照，不是断言实现了该服务后也必定丢包。
从功能回放得到正确包，不覆盖这些周期缺口。

原RRC2.34835%＞2%、插值RMS0.000150245＞0.0001、原16KiB及被拒绝的三槽整段尾部仍保留。
采用范围仅限显式功能/结构候选，默认浮点接收器不变，四项验收仍分别开放：

| 验收 | 本阶段补齐 | 尚缺 |
|---|---|---|
| 完整流式 | 实际源/缓存/拟合到严格MAC的值交接和后缀归还 | 捕获槽生产者、完整实时/多包调度；FT1 |
| 全链定点 | 字采样/初始化继续复用，旧数值不变 | 功率/TED/PI/NCO/载波/LLR及译码接口 |
| 整机资源 | 增量状态、压紧逻辑、端口和旧共享对象记账 | RX/TX/Polar/实时MAC/接口/DMA完整并发 |
| 连续16MS/s | 有值运输子图和未知服务显式阻塞 | 实际算术服务、反馈延迟、头/译码及系统仲裁 |

下一步先收敛真实字功率/TED/PI/NCO的数值和服务成本，结合已知45边沿反馈瓶颈选择结构。
不再仅优化Python/Rust墙钟，不把减少源读次数当整机达标；TX预留仍在账本，大规模TX尚不开展。

## 复现及API

冻结根`selected-symbol-handoff/`保存原失败、配方、输入/源码SHA、全部插值请求、轨迹和资源退出。
驱动`model_selected_handoff.py`需要三个父根：已选帧、捕获细搜索、有限拟合开发制品。
所有父清单逐项核验；不使用后来被覆盖的数据集索引。命令预期退出1，四项总门仍未通过。

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_selected_handoff.py \
  --split development --selected-root "$SELECTED" --capture-root "$CAPTURE" \
  --fit-root "$FIT" --output /tmp/selected-handoff-development
```
