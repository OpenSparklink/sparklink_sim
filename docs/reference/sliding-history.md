# 已选接收的滚动采样历史与字端口（SYS-C2E2A）

本阶段扩展[已选帧消费参考](selected-frame.md)，将原始采样历史从固定首段变成有限环形历史。
实际跟踪、插值、载波和严格头/数据CRC沿用原实现，默认接口不变。
本阶段Gardner带宽0.003、速率夹限500ppm，相干Q门限0.45，载波方法coherent；每个事件另保存实际配置和系数。
对应标准§6.2.1.2的接收实现选择及§6.3/6.9帧消费，不改变规定波形。

## 功能状态与接口

`SelectedPSKReceiver(..., history_capacity=512)`显式选择新模式，`None`保持原首段参考。
`sample_limit`仍限制本候选的输入总跨度；它不再被误解为环形RAM容量。
实验保持上限2^20，不预知载荷长度。已选起点之前不再需要的样本直接略过；
同步初始化保留其实际局部插值区间，进入现有Gardner后按下一符号中心与中点的依赖释放历史。
`feed_filtered`仍只消费返回计数指定的前缀，CRC不会用于重试同步/定时/CFO答案。

每个四点查询需要`floor(t)-1..floor(t)+2`。同步期间暂停TED，初始化会先读取全部同步样本；
初始化完成后，下一次查询的最早依赖为当前中心及Gardner中点中较早者的`floor(t)-1`。
只有更早的历史才退休，不按期待载荷、真值或名义包长删除数据。
所有终态释放有效历史；EOF、跨度耗尽和历史满分别保存明确失败。
`raw_history_at_termination`保留清理前区间与计数，可按输入SHA复现内容，不另复制整段历史。
审查曾发现原型EOF遗漏释放（仍有3个有效点），已保存原型源码SHA/复现/失败测试后统一修复。
复用物理槽位不等于清零RAM，必须靠绝对索引/有效区间阻止旧数据重入。

原始采样保留依赖包内实际NCO轨迹；载波、软解映射及译码仍需要的符号数组另计，
本阶段没有把完整符号/FFT缓存从成本里删除。

## 初始推导的反例与纠正

最初按四点区间推导最大`4×126=504`点，但首轮测试发现FT2非整数相位峰值129而非128。
原接收器使用`last_sync <= input_count-3`，分数相位时多等待1个输入；这是既有语义，未修改。

令同步长度N、已选起点s，则首次启动时：

- 最早保留位置为`floor(s)-1`。
- 可启动输入计数为`ceil(s+4(N-1)+3)`。
- 最大有效历史为`4N+int(frac(s)>0)`，FT4最多505点。

原504点启动推导不成立，失败及原冻结说明继续保留；九个独立整数/分数边界用例验证了纠正公式。
512点容量、逐轨迹精确要求和所有接收预算均未放宽。
进入稳态后，默认Gardner参数下实际依赖跨度最多8点；原等待规则可能比纯四点窗口多1点。
其他环路配置不能仅据这个8点结论宣称通过。

## 存储与端口模型分开记账

浮点/Rust接口要求连续数组，`RetainedSampleHistory`用两个512点镜像提供跨环边界视图。
主机实际分配**16384字节**，每个新样本写两份；不存在按2^20跨度预分配后再丢弃的临时大数组。
镜像是软件适配成本，不要求未来硬件复制两份RAM，也不算免费存储。
最大合法符号数组及事件轨迹副本仍由`reference_memory()`完整报告。

`ReceiveHistoryPort`是独立实际字值的有限1R1W节点：46bit格式沿用19+19+8，
没有新增量化或改变指数。它有绝对头/尾、一个注册读请求/回复信用，读延迟1周期。
满时明确背压回放生产者，不能覆盖未消费数据。回复被阻塞时保持原字，退休前必须消费在途回复。
同址读写推迟读操作，不依赖器件未指定行为；未来或已退休索引明确拒绝。

| 项目 | 成本/证据 |
|---|---:|
| 逻辑历史 | 512×46＝23552bit＝2.875KiB |
| 物理映射估算 | 1个RAMB36E1 SDP72×512，逻辑1R1W |
| 地址/时间戳、在途数据及有效状态 | 623bit上界 |
| 八个统计状态 | 512bit |
| 若需独立上游保持寄存器 | 另111bit；尚未证明可与旧回复共享 |
| 插值/初始相位拟合/环路/头/译码周期 | 未知，不能填零 |
| LUT、综合和实际时序 | 尚未验证 |

容量映射依据[AMD UG953 2025.2 RAMB36E1](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/RAMB36E1?contentId=Nm2aVbtVbH5UQNZ3PFqKqw)的7系列512×72 SDP模式，
不是其他E310/UltraScale/Versal原语。读延迟1和控制路径仍是模型假设，不能据容量资料保证时序。

数据路径每字仅搬运，无乘法、除法、开方或非线性操作；控制不是零成本。
按可复用中间结果的逻辑图，一次成功写含两次占用减法、端指针和接受统计各一次64bit递增，
以及范围、容量、忙和峰值比较；一次读请求含ready时间与请求统计两次递增及索引/同址比较。
回复另有一次统计递增，退休有一次区间减法和一次统计加法；环地址是常数容量掩码。
这些为操作图估算，未把宽加法/比较、计数溢出、地址选通和扇出当成免费或保证200MHz单周期。
API的单调时间保护属于模型检查；如保留为硬件诊断，还须另计连接和比较逻辑。

这是**消费者历史**，不能直接代替捕获细搜索期间的拥有窗口/尾部银行。
现有基础73＋运输10＋被拒绝私有尾部24的部分107BRAM若再加入此银行，为108，
仍缺其他RX、译码、TX、实时MAC和接口增量，不是整机通过；不能把主机16KiB与原模块16KiB预算混同。

八组新的字端口开发/验证情景包含100/160/200MHz、反复读、跨环、满缓存和下游长阻塞。
无阻塞时生产者按精确有理16MS/s节拍请求，背压时仅保持一个字并推迟后续请求，
因此这是**可暂停回放源**。ADC不可暂停，整链尾部积压/资源丢弃尚须反馈到原运输模型，
不能据本节点字值全部正确宣布持续输入通过。
这些情景并非实际插值/头部的服务日历；它们验证端口语义和有限容量，未知算术没有获得零周期信用。

另加入FT4最坏启动的**不停顿输入负例**：相位1/8、126同步符号，启动就绪时已占505点。
保持当前初始化期间不能退休的顺序，单读口至少需扫描504个字；尚未加入任何相位拟合或译码服务。
100/160/200MHz分别在启动后50/80/100周期、第512号输入第一次发生满缓存拒绝，
这时分别只返回50/80/100个初始化读字，尚不足504。
这证明“直接把本512点银行接到不停顿输入＋当前初始化顺序”不成立，
并不证明整个接收机不能实现16MS/s：上游拥有窗口可暂停回放或被借用，另有带成本的缓存/复用候选。
`startup-live-failures.json`保存三项资源失败；算术周期仍为未知，
这里仅用更乐观的RAM必要条件证明失败，没有给未知计算零周期的通过信用。
下一步优先比较借用已存在拥有窗口及初始化结果缓存/复用，再决定容量或并行度，不能省略代价。

实际参考轨迹另记录初始化/同步保持的重复读取，以及当前/中点的六至七个唯一字依赖。
目前源算法逻辑上每完整符号约八次原始样本访问（含同步初始化的额外一次）；
共享读取是下一候选，尚未将逻辑访问数当作CPU profile或已实现硬件优化。

## 固定请求及新节点验证

保持原一个已选结果，不重做搜索或用CRC挑候选。原30请求11次未评分等待保持；
19个可评分请求仍15头CRC、13完整正确。相对完整历史零原成功损失，整段/固定/随机块逐数组精确一致。
原首4096尾部参考只完成6包；滚动历史在上游持续提供样本的功能条件下保留另7包，
历史峰值505、稳态依赖最多8，没有新增历史/跨度失败。
这是**条件性保留收益**，实际捕获队列/ADC调度恢复数仍未知，不更新正式96包统计。

新的6包开发/6包独立功能验证完整参考与滚动历史分别同为6/6、5/6，保留未恢复样本。
变化载荷、MCS、帧型、包长、导频、干扰及CFO/SRO组合；第一轮观察后不调算法或容量。
八个负例共49152采样、3.072ms（16MS/s），观察中零误交付，不泛化全环境。
所有已查看集合此后均作固定回归。普通链路与已知WS63未编码A3上下文独立验证，未知编码前缀不变。

全链定点、整机资源和连续16MS/s三项没有被功能结果替代。

```console
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_sliding_history.py --selected-root SELECTED_ROOT --capture-root CAPTURE_ROOT --output NEW_OUTPUT
```
