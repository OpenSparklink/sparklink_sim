# RRC到scaled预筛的有限字接口

对应标准§6.2.1.2的既有PSK滤波和§6.2.3接收同步实现，未改变发射波形。
当前实验链为`word-full12-c18`→带指数的`scaled10`；
[旧固定22位预筛日历](rx-acquisition-hardware.md)的18DSP不能当作这条链的成本。
默认浮点前端、同步/相位/载波选择、Gardner/PI及实际CRC均保持。

## 接口与数值规则

`FixedRRC.feed_output_words`接受1..32点，复用原输入适配、80点历史和同一整数FIR，
返回实际signed19+19+8字。原`feed`接口保留。流接收器的实验RRC+scaled组合
直接向已有银行的`advance_words`交字，省去先重建浮点再量化的环节。
细搜索/跟踪仍取同值浮点视图；单音路径仍含浮点处理，全链定点尚未完成。

输入指数为[-96,48]，输出沿用`ScaledBankFormat`的[-48,32]和现有8..14位格式。
首个周期候选编译为10位；兼容格式测试不等于其它配置已完成硬件验收。

1. 对非零字，以两分量最大绝对值的位数计算目标指数，保留原一位余量并限幅。
2. 共用指数做有界signed RNE。左移前先检查饱和界，避免生成无必要的宽中间量。
3. 输出限幅并记录指数下溢、上溢、分量饱和和抹零。

零字保持原适配器的规范指数`-(mantissa_bits-2)`，与输入零字指数无关，
其移位控制旁路为0。非零字移位范围[-16,48]，7位有符号控制足够；
19位输入的大右移直接抹零，不构造超大掩码。原三个量化计数保持，整批验证后再更新，
64位计数耗尽明确报错。相对旧适配器字值/计数必须精确，不能用CRC掩盖转换差异。

## 三沿结构与成本

`RRCScaledBridgeService`保存一个字和sample tag，依次注册归一化、RNE及限幅。
结果阻塞时保持同一信用；take后下一沿才接受新字，非阻塞II4。
转换没有前瞻样本、包内历史或包间算法状态；RRC历史继续由原所有者保留。
节点abort终止本实例并清除未交付字，不允许残留回执；完整源的复位/丢字策略仍须上层闭合。

| 项目 | 估算/模型 |
|---|---|
| 输入/输出 | 46位RRC字→27位scaled10字，另携64位sample tag |
| 字、tag、临时量及控制 | 266 bit，同一组寄存器原位复用 |
| 九个64位计数器 | 576 bit |
| 总寄存器上界 | 842 bit，低于预定义1024 bit节点研究界 |
| DSP/采样RAM/系数ROM | 本节点均无分配，移位/加减/比较使用fabric |
| 运算/每复采样 | 4个abs19、1个LZC19、3个9位加减、2个9位范围比较 |
| RNE/限幅 | 2个19位RNE、2个左界移位/比较、4个限幅比较；guard/sticky及符号恢复另列 |
| 计数更新 | 最坏6路64位加法上界，不能作为免费监视 |
| 端口 | 一个输入/输出信用，寄存器接口，无额外历史RAM读口 |

完整操作图、零检测、标志逻辑和字段位宽由`estimate()`输出。
三段组合逻辑与计数更新各按一沿是假设，LUT/FF映射和Fmax尚无综合证据。
节点II4并不证明RRC、scaled银行、细搜索或整个接收机能承接16MS/s。
842 bit必须加入整机账本；1024 bit是预先定义的节点研究界，不是已批准的新整机预算。

## 验证与边界

Fraction舍入及旧适配器分别核对全字域边界、零、正负半平局、指数切换、饱和和计数。
实际普通A2/B1的FT2/3/4、已编码/未编码、Q12银行、真实头/数据CRC及MAC反例均经过测试。
验证禁止原raw银行调用浮点量化或RRC浮点输出接口，确保新字口实际接入。

12条预先冻结输入三种分块对照：8条目标配置的包输入中，6条未故意损坏CRC的包
保持完整正确，另2条是故意损坏头/数据CRC的拒绝反例；
37份JSON、324个NPY成员与旧源码结果精确一致。四条负例共65536点=4.096ms，
零新增MAC误交付仅适用于该观察量；重复分块不增加独立曝光量。
正式61/96未重跑，本阶段不宣称捕获率增益。真实IQ及原冻结数据未修改。

节点开发/独立数值验证各8种不同波形族和长度；源、独立oracle、uv.lock、
参数与采用规则先冻结。范围失败单列；“映射精确”不能代替源误差预算或绝对量化损失通过。
每例记录相对RRC字视图的RMS误差、源/目标范围事件及相对旧适配器的零增量字误差。
零能量时RMS比值为未知，不填0。

六个RRC输出日历携实际字进入本节点。假设200MHz、无阻塞的1024点可完整交接；
100/160MHz的RRC丢弃及输出阻塞时的节点丢新字全部保留。
本模型继续按原RRC节拍出队，不把桥接背压反馈为免费上游缓存；它不是整链背压设计。
缺失标签不能直接喂给连续scaled银行，原始能量标志的对齐、银行周期及细搜索仍为未知。

原2.34835%＞2%、插值、16KiB、18DSP和控制状态预算失败保持。
FT1/GFSK、未知厂测编码前缀及其它符号率/SPS不由本接口推断支持。
四项接收机总门均未关闭，无设备、RTL或新综合/时序证据。

## 复现

```sh
PYTHONPATH=src:scripts uv run --frozen --no-sync python -m scripts.model_rrc_bridge \
  --output /tmp/rrc-bridge-development
PYTHONPATH=src:scripts uv run --frozen --no-sync python -m scripts.model_rrc_bridge \
  --split validation --freeze /tmp/rrc-bridge-development/freeze.json \
  --output /tmp/rrc-bridge-validation
```

目录必须不存在，两条命令预期退出1；还应核对`model.json`的字/节点界结果，
保留范围失败、资源丢弃和未知整链工作。不能仅凭退出1接受驱动异常。
CI已配置在两个真实依赖环境执行上述模型并保存日志、字与日历；
实际作业及制品另行核验，新节点本身仍为Python模型。
原源码、输入SHA、整段/固定/随机分块、归档复现及失败关联保存在冻结证据根的
`rrc-scaled-word-bridge`，不依赖被覆盖的数据集索引。
