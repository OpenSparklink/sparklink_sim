# 窗口搬运、整数细搜索与后续样本保留（SYS-C1）

本阶段将[窗口搬运](capture-transport.md)与[整数细评分](spline-score.md)相连，
不改变接收器的同步、载波或CRC选择，不推广新接收后端。对应标准§6.2.1.2/§6.2.3的接收实现。
当前结论：复制和评分能够完成，不代表结果返回时还有连续样本可用于头部/载荷处理。

## 几何、字与拥有权

实际普通profile的FT2/3/4同步分别32/62/126符号，搜索窗口256/376/632点；
新增两种窗口经过实际模板、端口索引、回绕、EOF及独立值参考验证，不能推断其它窗口/波形支持。
源为连续双路径19+19+8位字，每个周期日历只读取当前输入，环和拥有槽容量固定。
增加到632点后，目标索引需要10bit，复制进度需要10bit，不能继续按FT2的8/9bit计账。

每请求包含实际路径、最多两个粗峰、最小位置、未来需求及到达计数；没有CRC/载荷/真值。
复制结束的下一拍才交给已有`SplineScoreFlow`，原始RAM在评分及结果持有期间不可复用。
评分器直接读取同一份拥有槽的字像，Y/M工作银行另计；复制写和评分读不重叠同一槽。
该节点已经有实际值/单端口日历，本阶段按其测得微操作周期预约完成时间，期间源仍持续写入。
重放其它时钟时先逐字SHA核对相同输入，复用确定性微轨迹；这是主机仿真复用，不是硬件查询答案。
源窗在完成时再次核对SHA，不能因结果阻塞或新输入而覆盖拥有者。

已有常量服务API继续可用。新`FineService`只能返回有界周期、离散状态和选中时间，
不允许无限延迟、数组或CRC挑选结果；微轨迹和证据由主机持有，未当作接收硬件缓存。
类型、字段宽度、结果归属及异常都明确检查；资源中止不能伪装成数值或CRC失败。

## 相干确认语义不能混淆

首轮集成发现：实际接收器配置相干Q确认时，不以差分0.85直接拒绝。
0.85仍为统计门限，几何就绪候选需要后续相干确认。原模型将4个低于该诊断门限的就绪窗
提前分类为拒绝，首轮源码/输入/运行全部保存后修正，不改实际接收算法或门限。

`CaptureFineWorker`现在要求显式提供`confirmation_required`；缺少上下文会报错。
相干配置下返回`confirm_pending`，不返回“捕获成功”；纯差分模块测试才显式选择差分门。
本阶段尚未调度相干确认，不能据`confirm_pending`计算硬件捕获/整包正确率。
新增三个计数状态多192bit；不能免费忽略。六种结果状态仍可放入3bit离散字段。

## 实际固定回归与数值

使用上一阶段24条已查看流，原输入NPZ SHA冻结在`capture_fine_inputs.json`。
本地按原件读取；无数据集的CI显式重建原配方并要求原SHA完全一致，不能换输入。
已查看集合只作固定回归；本阶段无接收参数选型，也未生成新的接收保留集。

观察器只转发原函数一次。加入观察前后，接收结果、采样轨迹、载波数组全部相同。
参考浮点链15/16捕获、15个头CRC通过、13个数据CRC/完整载荷正确；
可算载荷1748/51640bit错误，编码/未编码配置逐帧保存，不能当作统一原始信道BER。
这一列是原浮点参考结果，不是调度后的接收通过率。

523680原始采样产生30次细请求，最短间隔32点；FT2/3/4分别9/9/12次。
滤波器另有每流40点的明确EOF冲洗；它不是无限补零，也不能代替连续ADC输入。
为连接现有整数端口，对浮点滤波输出逐字做19+19+8参考转换：RNE、溢出报错、
单字相对分量误差界2^-18独立核对，不宣称额外ADC精度、RRC/单音已定点化或转换吞吐通过。
整数评分与浮点同窗的分数/起点/未来状态分别按原0.005/0.125预算检查，失败全部保留。
起点差是相对浮点搜索结果的误差，不是绝对定时精度；1/8网格也不代表实际精度。

## 周期与保留缺口

| 固定24流，100/160/200MHz均相同的计数 | 数量 |
|---|---:|
| 提出请求 | 30 |
| 完成复制/细搜索/结果释放 | 28 |
| 拥有槽满而丢弃 | 2 |
| 完成但仍需未来样本 | 11 |
| 完成、待相干确认 | 17 |
| 待确认结果的后续样本保留缺口 | 17 |

复制过期和启动不足均为0，不能据此写成链路通过。队列丢弃、数值拒绝、等待未来、
相干待定和后续样本缺口分别记录，不将资源问题计为评分算法漏检。
长服务结束后也有结果已晚于输入EOF；离线能排空不代表满足真实回复截止时间。

必要检查以“当前拥有窗+连续历史环”是否缺少后续样本为准；即使没有缺口，也还要证明
回放端口、插值、头/载荷缓冲、译码及截止时间。其它槽不在本移交合同内，不能免费借读。
额外离线诊断甚至假设所有提出过的窗口都被保留（包括实际丢弃者），
本轨迹下仍有缺口。这只是当前存储/处理结构的边界，不是实验包理论不可恢复的证明。

200MHz下，为掩盖所测串行服务延迟，单路径历史长度需求最高分别10220/18748/37109点。
这只是成本投影，没有将这些值调成参数后宣称通过；也不能解决队列满或回放端口问题。
FT4直接双路46bit TDP映射的历史环单独需要148个BRAM36，已超过芯片140个，
尚未算基础工程73个、拥有槽、译码/TX/MAC。应该优化服务/调度，而非无限扩缓存。
实际基础工程只有100MHz证据，200MHz仍为假设。

## 成本、接口兼容与未完成项

| 编译几何 | 历史/窗口 | 运输BRAM36 | Y/M工作内存LUT |
|---|---|---:|---:|
| FT2 | 384/256 | 10 | 320 |
| FT3 | 504/376 | 10 | 640 |
| FT4 | 760/632 | 10 | 1280 |

384/504/760历史均按固定128点余量预定义。每个结果描述符448bit，包含峰/边界、
服务计数及状态；复制读流水按实际索引位宽增长。源和目标端口复制及BRAM粒度显式计费。
Y/M为现有有限单端口银行；LUT/FF/控制时序未综合，不填0。
细评分的一个共享DSP不能冒充整个细引擎：另列准备的2个乘积原语估算，
本阶段不计跨阶段共享收益，保守分配准备2+评分1。ALU/移位/RNE/宽比较成本沿用节点报告。
原始拥有RAM与细节点原始读银行有互斥生命周期，工作银行不是免费共享。

搬运子模块12BRAM研究界仍保持；这不替代旧16KiB捕获预算，也不是整机预算批准。
原RRC2.34835%>2%、旧16KiB和串行细搜索压力失败全部保留。
100/160MHz下RRC II12已不满足16MS/s，本阶段理想滤波字到达不能掩盖这一失败。
浮点滤波、单音、银行/转换调度、相干确认、包内回放/环路、Polar/TX/实时MAC/DMA并发仍未统一。
当前请求来自零调度延迟参考链，未将资源丢弃反馈给捕获器；实际异步链可能有额外请求。
不能将本开放环重放写成完整16MS/s、实时FPGA或SLE验收。

旧API另以18个时钟/端口/阻塞场景对照冻结源码，结果、每个事件、字和成本完全一致。
原语、地址/宽运算延迟仍为模型假设，无新增综合/时序证据。

## 复现

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_capture_fine.py \
  --output /tmp/capture-fine-repro
```
