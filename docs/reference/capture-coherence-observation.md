# 相干确认漏斗的失效后观测（M29）

本阶段修正[细搜索前退休实验](pre-fine-retirement.md)的观测与报告。
对应§6.2.3同步的实现诊断，不新增标准字段或接收选择规则。

## 缺陷与原始证据

`CapturedFrameReplay.begin()`使用已经选定的同步字执行相干确认。
确认通过后，原有`coherent_accepted`计数已经增加。
若随后共享历史失效，终止事件`tail_history_expired`可能不带`sync_confirmation`。
原台架只用终止事件字段判断是否捕获，因而漏记了实际已确认的同步。
这不改变该包的尾部资源失败，也不能把它视为完整交付。

在M28原20条SHA输入的旧/新40次接收上，只读记录`begin()`前后的真实计数差，
所有原结果、事件元数据及算法参数不变。发现三次漏记：
开发case2、选择4的旧/新两条路径，以及已查看保留case5、选择4的旧路径。
均为`tail_history_expired`；原冻结报告、归档及其错误捕获列保留。

| 指标 | 开发旧→新 | 已查看保留旧→新 |
|---|---:|---:|
| 原错误的不同包捕获列 | 8→9 | 9→10 |
| 实际相干确认且真值后关联到不同包 | 9→10 | 10→10 |
| 完整正确 | 8→9 /12 | 5→6 /12 |
| 相干确认候选总数 | 9→10 | 10→10 |

保留组没有同步捕获率增益；完整交付多一包来自同一候选的历史及时消费。
真值位置只在接收结束后关联不同包，不进入同步、定时、载波、相位或候选选择。
上述集合已查看，仅作固定回归，不称为新的独立验收集，不用于重新选择参数。

## 观测接口与不变量

`tests.captured_frame_reference.receive(...,coherence_observer=...)`是台架接口。
默认None，保留旧事件模式和接口结果。每个真实终止事件调用只读观察器，传入
`id`与`accepted`。后者取相邻终止事件之间已有实际确认计数的差，不查看头CRC、
数据CRC、期待载荷或终止事件是否携带确认字段。

单信用帧所有者逐次终止，该差必须为0或1；观察器遗漏事件时明确报错。
回调返回值忽略，不能把拒绝变为通过；异常作为台架错误传播。
坏头CRC、坏数据CRC、非法长度和尾部历史失效仍按原规则失败、不交付。

实验驱动保存`coherent_decisions`及每帧的`coherent_accepted`。
不同合法包捕获单独保存在`captured_packet_associations_diagnostic`，
不能以候选数代替包数。其集合必须唯一、合法且不多于实际确认数；
完整交付必须属于已确认的包关联。丢失确认字段不再默认为未捕获。

## 验证与硬化边界

覆盖历史失效、头/数据CRC失败、非法长度、相干拒绝、观察器返回假指令与非法接口。
整段、固定和随机分块的确认事件必须一致。
原SHA输入的复核须保持原结果、元数据、CRC、载荷、原字和采样轨迹不变，
只新增明确的观测字段；不得重生成输入以替换冻结文件。

观察器游标和证据列表在接收算法之外，是调用者的诊断存储。
算法、滤波、评分、环路、信号位宽、硬件状态、采样端口及既有周期成本均不改变。
这不是新的物理遥测接口；实际调试队列、端口、丢记录与时序成本仍需独立建模。
相干计算本身仍未闭合周期服务，不能用这里的功能布尔结果宣称零周期或16MS/s。

原RRC 2.34835%>2%、插值数值、16KiB、整机并发及完整16MS/s失败继续保留。
四项接收机总验收未通过，默认配置不改变。

证据在冻结根`capture-funnel-observability-audit/`：只读`AUDIT.json`及
`READONLY-AUDIT-BINDING.json`关联原SHA、真实计数与遗漏事件；
`implementation/`保留实现前反例、源码差异、分块/后端复核及完整测试记录。
