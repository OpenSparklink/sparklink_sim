# 实际捕获候选到合法帧尾的所有权（M26，实验）

对应PSK §6.2.1.2、前导§6.2.2、同步§6.2.3、帧结构§6.3及CRC规则。
本模型补齐实际RRC/粗查询/原窗口/细搜索结果到已有严格帧消费者的功能交接。
它不增加CRC重试，不改变原差分最大值、全相位网格、等待规则或Gardner/PI。
头CRC决定字段是否可信及何时释放资源，数据CRC决定交付；二者均不选择同步/载波答案。

## 编译范围与接口

`CaptureFineWorker(capture_selection=True)`记录原微轨迹最终选出的同步字，默认False。
`FineSelection`携带原请求ID/窗口端点、真实服务返回沿、1/8采样坐标、共同指数、
最多128个22+22bit有序同步字及完整相关/能量。重复ID、重叠服务时刻、未就绪和重复取出均拒绝。
`reference_selection()`是显式off-clock浮点桥，依据原分子/能量计算归一化分数及差分频偏。
零能量分数为零；不按相关幅度替代归一化排序，不截断非法分数迎合门限。

`CapturedFrameReplay(profile,coherent_threshold=...)`仅允许普通标准A2/B1、4Msym/s、SPS4、
协商及允许MCS8/12。A2使用协商MCS，B1以CRC正确头中的实际MCS决定载荷。
当前不包含编码载荷、厂测LQI推导MCS/旧长度语义、FT1/GFSK或其他速率；限制是实验边界。
`CaptureTransport.simulate(...,source_owner=...,released_requests=True,frame_replay=...)`
复用单路径46bit源、三拥有同步窗和4096点共享历史，保持旧无帧回放接口及默认结果不变。

帧开始后同步字借用选中缓存，原始前缀直接读活动拥有槽；后续样本按原绝对索引读共享历史。
只保留一个注册回复，延迟一沿，堵塞时保持回复和信用。源TDP两端口依次安排ADC写、帧读、
剩余复制读；同地址读写等待，所有输入脉冲继续计数，ADC不背压。原窗直到真实终止才释放。
外部诊断回调保存采样字/索引/轨迹，不属于硬件缓存，也不返回任何选择指令。

已有`SelectedPSKReceiver`执行相干确认、持续定时、真实头CRC、长度/MCS合法性、
载荷和数据CRC，之后通过已有MAC适配器交付。头未验证前不信任长度；坏头/错误种子/非法长度
终止且不读载荷、不交付。有效头后只消费实际需要的帧尾及插值未来样本，未消费后缀仍归共享源。
EOF调用真实终止，不制造未来零样本；历史过期、源epoch取消及明确中止不交付部分载荷。
同一候选只有一个答案，CRC失败也不重新搜索或换载波结果。

实际已消费前缀退休重叠候选，独立于CRC结果。该所有权策略是显式算法变化，
会拒绝起点早于退休位置的候选；不把此类结果当作相干统计失败。
当前在完成原细搜索后执行退休检查，仍有重复细搜成本；提前排除须另做召回与成本实验。

## 四层状态和成本

| 增量 | 容量/服务 | 限制 |
|---|---:|---|
| 选择标量 | 563bit | 原ID/端点/坐标/指数/完整C/E等 |
| 有序服务状态 | 127bit | 最后请求与下一合法服务沿及有效位 |
| 帧所有者 | 1090bit | 原索引、单回复、时钟、10×64统计及峰值计数 |
| 搬运帧控制 | 386bit | 2状态位和6×64统计 |
| 新控制合计 | 2166bit | 实现前研究上限4096bit；不是整机批准预算 |
| 选中同步缓存 | 128×44=5632bit逻辑 | 估算1个BRAM36，SDP72×512，1R1W、读延迟1 |
| 私有整段尾部 | 0 | 借用原三同步窗及4096点共享历史 |
| 浮点消费者原始历史 | 512点、主机双镜像 | 另有合法有限帧符号数组；硬件映射未知 |

主机消费者持久NumPy根数组加选择逻辑缓存的研究界为512KiB，实际逐对象去重计量；
不包含Python对象开销、FFT/译码临时空间或进程RSS，也不是FPGA RAM预算。
浮点帧消费者的LUT/FF/DSP/RAM/端口仍为未知，不能填零。选择缓存之外原窗口、
源历史、RRC、相关银行和微程序设施均不抵扣，双路径和新队列也不能免费加入。

原RRC8DSP、粗核12DSP、含准备细搜19DSP保守相加39DSP只是部分专用结构估算。
选中桥、相干确认、逐字浮点帧消费、残余载波及译码明确是off-clock功能解析；
完整延迟为`None`，逻辑日历乐观，不能用它证明ADC服务率或整链16MS/s。
已有微程序和头部字服务有自己的非零周期，不能把它们扩大成所有后续工作已计时。
没有新增综合、布局布线、真实200MHz或完整FPGA资源证据。

原16KiB、控制与端口失败、RRC 2.34835%>2%、插值0.000150245>0.0001均保留。
预算如需调整，仍必须独立成本/性能决策并在新验收前冻结，旧失败不改写。

## 参考与验收方法

新台架使用独立解析脉冲与重采样，改变载荷族、FT/MCS/包长/导频、幅度、CFO/SRO、
分数偏移、单音/噪声/突发/强弱变化/错误同步字背景；普通profile与厂测分开。
头/载荷字段编码仍复用既有已核对模块，不将此回环称为新的独立CRC互通认证。
§6.2.2的FT2/3/4前导10/12/16us在4Msym下分别40/48/64符号。
原PDF版本与SHA见[标准来源](standard-sources.md)及证据`PREAMBLE-SOURCE-CHECK.json`。
旧固定40符号的FT3/4原型和输入原件不修改，明确只作功能回归。

整段/固定/固定随机分块要求同一后端的所有原字、候选、帧结果、采样轨迹逐字节相同。
原消费者对实际交付的同一字序列再次回放是组合一致性参考，不是假装独立接收机。
真值只在接收完成后计算定时与粗差分CFO误差，不传给算法或决定通过率。
头CRC、数据CRC、长度、MCS、完整内容和可计算BER分别记录；单比特CRC失败仍失败。

```sh
PYTHONPATH=.:src:scripts uv run --frozen --no-sync python -m scripts.model_captured_frame \

PYTHONPATH=.:src:scripts uv run --frozen --no-sync python -m scripts.model_captured_frame \

```

目录必须不存在。预期退出1且必须存在正向`model.json`，驱动异常不算通过。
开发合格后才在完全冻结的源/参数/预算下生成独立组合；保留集失败后不围绕该集合调参。
组件合格至少要求一个正例完整、负例无确认/交付、源与原字/分块精确、端口/新容量不超界，
不要求全部压力正例通过。四项总门始终另记，正式61/96本阶段未重测，不宣称弱包恢复增益。

## 已保存边界

短FT3/4输入可能在细搜服务结束前已经输入完毕，之后才能功能交付；保留该延迟反例。
FT2另测在4096个后续采样持续到达时先交付，不能据此推断所有配置持续承接。
原密集三包台架只交付两包，13请求中7细搜完成、6槽满丢弃；按资源失败保留。
下游长阻塞导致共享历史过期；源故障取消活动帧且仍计入全部后续ADC脉冲。
完整解调/译码周期尚未映射，这些观测不等于规定业务下的最坏实时能力。

下一步优先据原输入/请求轨迹减少已消费区域的重复细搜与存储上下文占用，
再将实际插值、环路和译码服务接入统一有界日历。FT1路径、全链定点、整机并发资源、
连续16MS/s和最大合法配置仍分别未验收，不能以本阶段功能闭合代替。

## 冻结结果与未通过项

| 集合 | 总输入点 | 请求/细搜结束/槽满 | 相干/合法头 | 数据CRC/完整 | 解码BER |
|---|---:|---:|---:|---:|---:|
| 新开发6正+4负 | 45348 | 25/18/7 | 6/6 | 6/6 | 0/3440 |
| 冻结独立组合6正+4负 | 47728 | 26/18/8 | 6/6 | 5/5 | 1/3984 |

独立突发197字节包仍有1bit错误，头、长度/MCS通过而数据CRC失败，不交付。
每集负例16384采样，即16MS/s下1.024ms观察；无相干确认/误交付，不能推广为任意环境零误检。
两集主机预分配NumPy根数组加缓存最高410352/451352字节；这不是完整运行期或FPGA内存。
原默认路径在两后端重放M25的12个冻结SHA输入，12份日历/48个NPY成员各精确，
7/8槽满失败仍保留；相同实际端口字交给旧严格消费者的结果也一致，不据此宣称射频接收率提升。
真实Rust依赖环境新20流的所有字/轨迹/判定及每集50个NPY成员精确，
每集6个原接收器`integer_screen_backend`可用性标签为rust；新捕获节点仍是Python，
该标签差异单列，不忽略其他数值差异。首轮标签导致的严格JSON比较失败保留。

后处理发现独立脉冲参考返回`origin+40×step`，新驱动却标为首前导位置，导致定时误差
带约160采样坐标偏置。原输入、冻结输出和两项诊断失败保留；**本阶段真值定时误差未合格**。
这不改变任何接收选择/载荷/CRC；下一独立修复只更正真值坐标并以原IQ复核，
不能把该诊断修复计为算法恢复或保留集调参。完整载波收敛/滑移也仍未知。

针对性144通过；全量纯Python收集5595、5557通过/38跳过，Rust依赖5606、
5601通过/5跳过；覆盖率93.87%/93.86%，最大单片67.386/63.319秒，原测试身份保留。
新源覆盖率选择口92.59%、帧所有者95.07%；测试通过不覆盖定时诊断、资源或整链吞吐失败。

## 真值坐标的独立修复（M27）

M26的原输入/模型/失败和约160采样偏置不改写。独立解析参考的脉冲首符号原点为
`512+offset`，返回坐标为`origin+40×step`；信道再加`prefix`。
新生成器只在诊断元数据中减去`40×step`，之后按实际FT前导数和因果RRC延迟40点
计算首同步符号坐标；不移动IQ，不改接收器、期待载荷、参数、预算或任何CRC。

修复复核使用M26原始SHA输入，原新保留集在本阶段只算已查看固定回归，不再称为新保留集。
逐项核对除真值定时统计以外全部决定、端口字、采样轨迹、成本和载荷完全一致，
每集合50个NPY成员保持；独立由`512+offset+prefix`计算的坐标再次验证报告。
这是诊断可信度修复，完整仍6/6与5/6，突发1bit数据CRC失败保留，不能计为接收改善。
旧RRC/插值量化失败、整机资源及连续吞吐缺口仍分别开放；修正坐标不代表定时性能已过冻结预算。
修复后的12包观测最大绝对误差为0.136042采样；开发逐包RMS为0.01043–0.03238，
已查看验证回归为0.01331–0.05037采样。这是模拟真值误差，真实IQ不据此获得精确定时真值。
针对性30通过；全量纯Python5558通过/38跳过、Rust依赖5602通过/5跳过，覆盖率均93.86%，
原M26测试身份全部保留；此处仍未完成整链定点、资源、连续调度或实际硬件验收。
