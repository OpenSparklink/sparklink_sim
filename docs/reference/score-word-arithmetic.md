# 有界逐字算术与细搜索相位并发（SYS-C2C）

本阶段针对[完整增长评分](spline-score.md)的实际周期归因：一个FT4就绪窗口215262周期，
其中147887周期为串行ALU预约，62946周期为DSP分片。不能仅增加DSP并宣称解决最坏吞吐。
对应标准§6.2.3的接收实现选择，沿用实际同步模板，不改变合法波形。

## 运算与因果调度

`SplineScoreFlow(..., word_fabric=WordFabricAssumptions(alu_lanes=2))`是显式研究配置。
默认仍使用原宏模型。输入必须有9上下文、共享六字样条缓存，第二整数峰顺序复用这些上下文。
每符号分别推进最多9个相位，结束后合并；不存18×128采样向量。
候选、网格、归一化门限、排序、平局和峰值等待语义均保持。

`WordCommand`分别声明两个输入及结果的位宽/有符号性，不能从当前值的正负推断格式。
ALU输入最多208bit；扩展至最多210bit，逐个32bit段执行进位、补码减法/取负及符号比较。
比较从高段向低段推进，符号先判；无符号乘积绝对值是注册接线。
宽寄存器移动按注册接线计，不假装是一个宽加法；译码、选通和宽范围检查的LUT及频率尚未综合。

固定样条舍入明确是有符号33bit输入，右移10位，输出22bit。
四步分别是低32位幅度、高1位/余数和商、ties-to-even增量、符号恢复和越界检查。
不再根据22bit输出宽度估算输入舍入成本，不使用通用除法或变量移位器。
乘法仍只使用正24×17的原生乘积，装入有符号25×18 DSP；先寄存输入，再原生乘积，
再流水寄存，3周期后进入邮箱，II=1。宽乘积继续按已有分片与部分和执行。

最多9个活上下文，各只有一条未完成指令和一个预留结果邮箱。
全局每周期最多发射一条、成功取回一条；同周期多单元完成写不同上下文的私有寄存器邮箱。
完成后不能同拍发射依赖指令，反馈至少另隔一周期。
每上下文按序使用有限16bit令牌，耗尽必须复位；阻塞时保留结果，不覆盖或无界排队。
显式取消用一周期清空流水/邮箱/令牌，过时结果不能复活。
诊断事件、完成时间戳和主机轨迹不是硬件历史；实时路径不访问CRC、期待载荷或真值。

共用Y/M银行、四个在途读信用、真实读回复、选中相位回放和输出阻塞均继续计时。
每符号分发和合并各计一周期。准备饱和在评分前拒绝；几何等待不评分、数值状态仍为未知。
有限周期中断是资源失败，不能回退浮点后判通过。

## 状态和端口账本

运行前冻结算术设施上限8192bit，新增算术加相位上下文上限24576bit。
它们是研究候选的增量上限，不能替代原16KiB失败或当作已批准整机预算。

| 项目 | 预留bit | 依据 |
|---|---:|---|
| 每个ALU32通道 | 832 | 两个208bit操作数、210bit结果、固定RNE临时、游标/进位/比较/格式/标签/令牌 |
| 一个DSP的三个阶段 | 240 | 每阶段43bit数值与37bit标签/上下文/令牌/控制 |
| 九个私有邮箱 | 2304 | 每个256bit，包含210bit数值、格式/标签/令牌/状态 |
| 九上下文控制 | 216 | 每个24bit，包含17bit下一令牌/耗尽、忙和反馈状态 |
| 全局时钟/四计数器/仲裁 | 384 | 64bit时钟及四个64bit计数器、轮询和端口标志 |
| 每个相位执行上下文 | 1792 | 活中间量、一个待发指令、查询/乘积/符号状态，最多九份 |

两ALU的设施4808bit，加九上下文16128bit，新增20936bit（约2.56KiB）；
继续保守保留原查询状态7219bit，共28155bit，未凭推测扣除可共享寄存器。
准备阶段2个DSP另计，评分1个DSP，未证明跨阶段共享。
新增样本RAM和Y/M副本为0，邮箱/上下文按寄存器估算；不能把逻辑bit数直接当成BRAM数量。

相位1792bit预留涵盖：当前字44、四乘积180、差分90、贡献92、功率44、
乘积幅度/部分和180、原生积43、符号/游标10、查询33/游标9、
程序/模板/位置/符号/有效位57、调用状态48、待发命令480、进入/工作状态292，共1602bit，
另预留90bit符号贡献负号临时及100bit分配余量，总计1792bit。
这是有限寄存器分配预留，尚无综合LUT/FF和实际端口选通时序报告。

整机已有基础占用21711FF；新增设施不能免费复制四份，也不能挤掉译码、TX、实时MAC和接口。
按当前保守FF映射，四份查询状态已需112620bit，超过106400FF物理容量，且尚未加基础工程。
这是该寄存器预留映射的失败，不是已综合的资源结果；转存RAM仍须重新证明端口与时序。
[整机账本](system-feasibility.md)中的25%余量仍是建议，200MHz未获新PSK布局布线证明。

## 验证与采用边界

独立整数和Fraction参考覆盖极值、混合符号、跨段进位/借位、舍入半值及越界。
新节点开发改变窗口、FT2/3/4模板、PID、相位峰数、常量/噪声/弱字/突发构造；不是射频保留集。
预定义规则：两ALU需使已评分开发窗口总周期减少至少30%；四ALU还需比两ALU减少至少10%。
开发965728周期；一/二/四ALU分别694179/513937/500470。
按规则冻结两ALU，四ALU的额外收益只有2.62%，不计为免费并行。
随后固定两ALU评价独立节点组合；不据其结果另选通道数或调整数值预算。
开发6例中4例评分，1例等待、1例无合法位置；独立节点验证6例中5例评分、1例无合法位置。
未评分例保持未知，不能表述为12例数值全部通过。

再按冻结哈希重放实际捕获窗口，逐一比较全部候选分数、样条字、选择及几何等待。
这不是新的RF捕获收益验收，也没有将提早完成导致的资源可用等同于同步/CRC恢复。
输入SHA、逐请求结果和有限队列/保留缺口由复现输出保存，原全部RF/数值失败继续关联。
本阶段只接受显式结构候选，不推广默认接收器，不宣称整链16MS/s通过。

## 复现

先按[捕获窗口命令](capture-fine-integration.md)生成输入，再运行（新输出目录）：

```sh
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_score_words.py \
  --capture-root /tmp/capture-fine-repro --output /tmp/score-words-repro
```

预期退出1表示整链尚未验收；还必须检查`model.json`和`manifest.json`存在并逐项核验，

这些是上阶段冻结输入，不能称为新保留集。

总服务周期减少45.23%；每个未评分等待窗反而增加17周期，原因是新算术反馈，不隐藏退化。
全部19个已评分窗的所有候选、样条字、选择与原结果相同，11窗数值状态保持未知。
没有正式包恢复收益、没有资源丢弃恢复；不得以更快的确认待处理结果冒充CRC/载荷成功。

还要拥有槽、前端、译码、TX和实时MAC等。100MHz投影76、160MHz投影48，也不满足整机门。
节点几何等待控制、粗筛、RRC、相干确认和包内跟踪仍存在各自未闭合部分。
继续保留原2%/16KiB、数据CRC、截断及数值失败，不把本次逐字精确解释为浮点兼容全部通过。
