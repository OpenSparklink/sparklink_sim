# CI测试分片与耗时证据

CI的测试运行时长门与接收算法、数值、资源和16MS/s验收分开。当前仍为core/front/rrc/head四份互斥分片，Python/Rust单元作业各四片；独立Python覆盖率也执行相同划分。每片必须小于120秒，合并覆盖率至少90.1%，失败仍上传JUnit、日志、后端身份及诊断。

## 实际失败与调整依据

提交811ecbd的CI运行44782119275中，Rust头片453项、0失败、0错误，耗时127.676秒，因此耗时门正确失败。Python同片116.343秒，3项可选依赖跳过。RRC片各98项，Python35.486秒、Rust38.910秒。该失败及官方ZIP/SHA和JUnit保存在冻结证据根`head-retention-budget`，不会被后续绿色运行覆盖。

迁移以下完整文件到RRC片，保留每项断言与身份：

| 文件 | 该次Python耗时秒 | 该次Rust耗时秒 |
|---|---:|---:|

| test_split_sampling_replay.py | 17.082 | 18.194 |

## 检查规则

`check_test_shards.py`检查各JUnit失败、错误、测试数、重复身份和时长；合并后端检查要求每片的提交与实际加速能力一致。覆盖率从四个真实独立进程的数据合并，不用覆盖率数值代替关键反例。新划分不改变源算法、冻结参数、接收能力或任何FPGA计算/存储预算。
