# 已选接收的有限 Lagrange 插值（SYS-C2E2B-I）

本阶段补齐[滚动历史](sliding-history.md)之后缺失的一个计算节点，
为后续拥有窗口/消费者背压组合提供实际字值及周期依赖。
当前流式参考已经使用四点三阶Lagrange；本阶段保留同一多项式和四点窗口，
不将全局样条细搜索的符号替换成另一同步答案，不改变Gardner参数、峰值等待或帧解析。
对应标准§6.2.1.2的接收实现选择及§6.3/6.9的帧消费；以下格式与误差门是工程预算，非标准射频限值。

## 数据路径及接口

`interpolate_filter_word(words, phase, format)`接收连续四个已有19+19+8输入字。
实际值为`(r+j*i)*2**exponent`；零字不决定公共指数。
四点对齐到非零字的最大指数，按最近偶数舍入，过大指数差明确擦除低幅分量并计数。
不增加ADC标度假设，也不假定增益能改善信干比。

令输入为a/b/c/d、分数u，则使用分母6的整数Horner结构：

```text
A = -a+3b-3c+d
B = 3a-6b+3c
C = -2a-3b+6c-d
D = 6b
numerator = ((A*u+B)*u+C)*u+D
output = numerator/6
```

u以16或20小数位表示，包括舍入到端点1；仍只用原四点，不增加未来采样。
输入对齐后增加0或2个小数保护位。各Horner乘积右移按最近偶数舍入，
状态声明为23或25bit；`/6`也最近偶数舍入。输出采用共同复数指数及显式19/22bit有符号分量，
指数范围−128..127，输出溢出饱和、过小指数及擦除分别记录，未见溢出不代表无量化误差。
输入46bit；22bit输出是52bit，不能按旧46bit布局解析。

`WordInterpolatedPSKReceiver(..., word_format=...)`只通过`feed_words`接受1..32个实际输入字。
它复用一个上游选择、原头/数据CRC、合法长度/MCS和包内跟踪；初始拟合与整个Gardner/PI仍为浮点。
只替换插值，保持原带宽0.003、500ppm夹限及coherent载波解析；不根据CRC重试同步、相位或CFO。
新增字端口本轮只验证普通FT2/3/4；已有WS63浮点回归保留，未宣称新增字端口厂测验收。
未知厂测编码前缀不作处理。

该显式实验接口目前只有Python时序控制，不存在原生字插值ABI；传入Rust/auto会明确拒绝，
不会悄悄宣称Rust加速。原浮点Python/Rust路径仍保留。
字历史512×46bit及继承的两份复数镜像都记账，Python整数对象/临时数组另有开销，
不把这些参考兼容副本写成硬件免费共享。
终态按原依赖释放有效区间，不消费调用者剩余后缀；EOF不制造补样。
原型曾在已拒绝同步后先检查未消费字，已保存对照并修正为拒绝/缺历史优先；
输出格式须为编译枚举，指数下限事件也传入统计，不遗漏为零。
本阶段没有接入MAC构造器或运输调度，不能把已选字端口当完整未知起点IQ接收。

## 独立数值门与采用规则

开发前冻结：同后端分块精确；判定相同；零原成功丢失、零新增误交付；
符号归一化RMS≤0.0001、峰差≤0.001，中心峰差≤0.001采样、速率峰差≤0.1ppm。
候选先按DSP再按寄存器成本选择，固定回归也必须过门，之后才准生成新的接收保留集。
本阶段未放宽这些预算；原RRC 2.34835%＞2%和16KiB失败继续保留。

独立有理数参考直接计算四个Lagrange基函数，不共享接收整数Horner/除6实现。
同量化u下，未饱和时的保守绝对误差界为：

```text
5/8 * 2**common + 3/4 * 2**(common-guard) + 1/2 * 2**output_exponent
```

它分别计入对齐误差、三次Horner舍入和除6、输出舍入。
相位量化及初始化/环路传播另由实际接收轨迹检验，不能用局部有理界覆盖整包数值失败。
原格式、擦除、饱和、指数极值、端点、堵塞、时钟/计数耗尽均有反例；
全零及无接收观测不被记成接收验收成功。

## 开发与固定回归结论

| 候选（相位/保护/输出） | DSP估算 | 新开发完整数 | 新开发数值 | 固定回归 |
|---|---:|---:|---|---|
| 16/0/19 | 6 | 6/6 | 拒绝 | 不推广 |
| 16/2/19 | 6 | 6/6 | 拒绝 | 不推广 |
| 20/2/19 | 12 | 6/6 | 拒绝 | 不推广 |
| 16/2/22 | 6 | 6/6 | 通过 | 13完整、零成功损失；仍有1项数值失败 |

前三者在长MCS0包上RMS分别约0.001226/0.000197/0.000197，均超0.0001。
已保存原源档、失败输出与只读拟合重放：初始化的CFO差约0.0595/0.00957/0.00957Hz，
足以解释大部分包内累积相位差；扣除该预测后残差约3e−6。
20相位位没有改善同步八分之一网格处的相同输出舍入，DSP却翻倍。

随后在开发阶段单独比较保留保护精度的22位输出；输入和25bit状态不变，输出多6bit、DSP不增。
这项改动未改变预算或期待载荷。它通过新开发，但固定原SHA回归
`development-development-4-fine-1`仍为RMS0.000150245＞0.0001，尽管CRC和完整载荷均正确。
因此**接收采用规则拒绝，默认接收算法不变**。
不以包结果相同覆盖数值失败，不围绕该固定反例再增加位宽；下一步须结合实际载波边界分配误差。

30个固定请求的11次未评分等待保留；19个已选结果仍15个头CRC、13完整，零原成功损失。
开发四个负例共26624采样（16MS/s下1.664ms），观察到零新增误交付，观察量不支持绝对零误检结论。
新接收保留配方尚未生成。另设冻结的独立**算术节点**验证，不能替代接收机保留集。
全部输入、候选失败、分块轨迹、量化边界、源文件及哈希由脚本保存。

## 有限流水与系统成本

`LagrangeInterpolationFlow`逐值执行对齐、系数、三层Horner、除6及打包七个有限阶段。
每阶段只保留一个查询，最后阶段同时作为单回复槽；堵塞会逐级停止接收，不覆盖旧回复。
除6按十六进制长除，每周期查一个96×7表；复数两分量各有一份表，余数始终0..5。
没有通用除法器、开方或无限指令/候选队列。

| 16/2/22节点 | 成本/假设 |
|---|---|
| 实数25×18乘积 | 每查询6次；三Horner阶段各2DSP，共6DSP估算 |
| 系数/Horner加减 | 每查询30次；系数准备峰值12条25bit加法路径 |
| 对齐/舍入 | 8条19bit对齐、6次Horner RNE；打包/比较/优先编码另计 |
| 除6 ROM | 逻辑1344bit、2读口；拟分配2个128×7单读分布ROM |
| ROM映射候选 | 28个LUT6＋14个MUXF7；容量1792bit，非综合最小值 |
| 流水有效数据/控制 | 2057bit保守上界，另256bit统计＋64bit时钟诊断 |
| 字端口量化质量统计 | 另4×64bit；与流水接受/输出计数未获共享信用 |
| 若硬化每查询延迟监视 | 接收时间戳另7×64bit；当前仅主机诊断，未免费计入硬件 |
| 另加查询FIFO2深 | 434bit载荷＋4bit控制；非ADC停顿能力 |
| 源访问 | 每查询4个原46bit字；源RAM端口与延迟仍须组合 |
| 无阻塞节点延迟/II | 32/8周期；只有下述原语假设下成立 |

乘法容量依据[AMD UG953 2025.2 DSP48E1](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/DSP48E1)的25/18bit端口。
模型假定DSP乘法3周期、定宽加法/RNE1周期、ROM1周期及打包3周期；宽移位、比较、控制与布线尚无综合/时序证据。
不能将任意宽乘法当成一个DSP；20位相位明确拆成两个17/4bit片并计入46bit合并加法和12个DSP。

在每4Msymbol/s到达两个完整查询、原四字已可用的乐观负载下：

| 时钟 | 无阻塞查询丢弃 | 插值最差反馈余量 |
|---|---:|---:|
| 100MHz | 0 | −15周期，32组均超下一个符号期限 |
| 160MHz | 0 | 0周期 |
| 200MHz | 0 | 10周期 |

输出堵塞60..360周期时，同一64查询负载分别明确丢弃18/9/5个查询；所有队列有界。
这里没有加入RAM读取、初始拟合、Gardner/PI、载波、头部或译码周期，它们保持未知，不填零。
在此成对到达日历和原语假设下，160MHz零余量不能承接额外反馈工作；200MHz也不能据剩余10周期宣称整链接收16MS/s。
ANTSDR现有基础工程的100MHz证据不证明160/200MHz布局布线成立。
本节点6DSP、ROM及寄存器是整机账本的实验增量，不与既有细搜索/TX/译码资源自动共享；
原部分108BRAM账本仍不是已批准整机预算。

## 复现与后续

```console
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_interpolation_word.py --split development --selected-root SELECTED_ROOT --capture-root CAPTURE_ROOT --output NEW_DEV
PYTHONPATH=src uv run --frozen --no-sync python scripts/model_interpolation_word.py --split node-validation --freeze NEW_DEV/freeze.json --output NEW_NODE
```

两步均预期返回1：原数值失败和整机验收缺口不隐藏。
`--split validation`在冻结选择为空时明确拒绝生成接收保留集，不能转而挑选其他格式。
开发选择/预算/源码与节点格式先冻结，再独立验证算术。
后续继续将已有拥有窗口/原始字端口、实际插值请求及服务背压组合；
同时定位初始化/载波边界的精度分配，保留当前拒绝，不同时重设插值、搜索或环路参数。
完整流式、全链定点、整机资源、持续16MS/s四项门仍分别未关闭；FT1/GFSK另行补齐。
