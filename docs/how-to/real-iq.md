# 使用真实 SLE IQ 数据

## 先下载数据集

[sle IQ数据集](https://github.com/OpenSparklink/sparklink_sim/releases/tag/sle-iq-20261116-r2)
记录了 WS63 发出的真实星闪测试信号，由 E310 通过 30 dB 衰减连接采集。
IQ 是无线波形的两路采样数值，可以用于离线解调、接收算法开发和 FPGA 回放测试。

本版有 72 组配置、360 份文件，覆盖 GFSK、QPSK、8PSK 及 1/2/4 MSym/s 符号率。
每组包含三次发射采样，以及发射前后各一次静默采样。下载约 450 MB，解压后 IQ 约 1.51 GB。
旧错位编码样本已由修复后的实测样本替换，发布包不含旧错误 IQ、试采和失败空文件。

在全新目录执行以下命令。需要 GitHub CLI、zstd、tar、sha256sum 和 uv，预留至少 3 GB 空间。

```sh
gh release download sle-iq-20261116-r2 -R OpenSparklink/sparklink_sim -D sle-iq-assets
cd sle-iq-assets
sha256sum -c SHA256SUMS
cat ws63-rx2-20261115-r2.tar.zst.part-* > sle-iq.tar.zst
sha256sum -c ARCHIVE_SHA256SUMS
mkdir restored
zstd -dc sle-iq.tar.zst | tar -xf - -C restored
uv run --no-project python verify_dataset.py restored/ws63-rx2-20261115-r2
```

四个分卷必须全部下载、按编号拼接后再解压，不需要 Git LFS。
原始数据在解压目录的 `raw/` 下；先看 `iq-index.csv` 选样本，再从 `samples.jsonl`
读取对应的采样参数和验证记录。完整的附件、压缩包和原始文件都可分别校验。

数据为 16 MS/s、约 2441 MHz、10 MHz 带宽，RX2 手动增益 15 dB。
小端有符号 16 位整数按 I、Q 交错，每四字节构成一个复数采样；原生 ADC 只有 12 位有效数据，
其余位作符号扩展。每份文件约 65.536 ms，未裁切、归一化或重采样。

这些是厂测程序的选定测试信号，不覆盖全部 SLE 业务和配置。完整帧已核对同步、CRC、长度
和已知载荷；边缘半包不计成功。部分早期固件身份未知，采集也没有硬件丢样计数或空口时间戳。
本数据集不能单独证明生产接收机、标准互通或绝对射频指标已经通过。

## 检查 GFSK IQ

先读取采集元数据，按实际 I/Q 顺序、字节序及有效位宽解包。
保留整段原始 IQ 和关联静默对照，不按已知载荷或同步位置预先裁切。
调用 `nearlink_sdr.phy.gfsk.analyze_gfsk_capture` 时显式提供实际采样率、
请求符号率和同增益的静默对照；当前前端支持整数 SPS ≥4，不固定为8。

前端以每符号平均功率的静默99.9%分位数乘4作为检测门限。
采用65抽头Hamming低通，截止频率为请求符号率，因果群延迟32样本。
每个能量段都输出：过短段、记录边界截断段、无法区分双频状态的段不会伪装成完整包。
CFO取双簇鉴频中心的中点；定时取每符号积分鉴频眼图的最大平均绝对值，
不使用期待载荷、CRC或同步相关结果选择定时。实际比特判决复用原有GFSK解调器。

`bit0_filtered_index` 为滤波后第一个判决区间的开始；
`bit0_raw_reference` 减去32样本群延迟，后续判决区间相隔SPS样本。
该坐标是原始文件偏移和一个样本的定时网格，不是空口硬件时间。
符号时钟还提供请求附近±10%的过渡能量谱峰、谱峰对比和观测时长；
FFT零填充后的网格间隔不是绝对时钟精度或独立SRO校准。

`prbs9` 定义数学约定为x⁹+x⁵+1、全一初态、stage8优先输出。
厂测固件是否使用相同种子、位序、扰码和帧封装，必须另外确认。
GFSK波形比较、能量段、同步候选或PRBS相似性都不能替代控制头、CRC和逐字节验收。
采集前端只返回未解析比特及诊断。若上下文已确认，可另调用
`phy.frame.decode_ft1_a3_candidates`：显式提供同步字、CRC24A种子与加扰种子
（`None`明确表示无加扰），扫描全部同步候选，复用已有A3解包和CRC算法。
头CRC12通过才使用长度，数据CRC24A通过才返回载荷；坏候选和截断候选保留，
继续搜索后续同步。不使用期待长度或载荷选择同步位置，也不为通过而枚举种子。
这是指定FT1/A3/CRC24A配置的解析器，不代表全部厂测模式或业务配置都相同。
不要直接把假定对齐的 `rx_chain` 或FT1 `decode_head` 的简化成功标志作为真实头CRC证据。

`prbs15`使用x¹⁵+x¹⁴+1、全一初态、stage14输出，与SDK厂测生成器的14/13反馈一致。
字节位序在采集分析调用处显式指定，不用期待载荷辅助同步。


## PSK采集与FT2/A3检查

`phy.psk.acquire_psk_capture`接受完整IQ、静默、实际采样率、显式符号率及已知同步符号。
当前整数SPS≥4。采用原beta=.4、span10 RRC居中离线滤波，能量阈值与GFSK相同。
在各整数采样相位搜索已知同步的差分归一相关，最大值达到固定.85才获取；
CFO、相位和增益仅由同步估计，不用期待载荷或CRC选择同步。所有短段、边界段、
未同步段保留。raw索引为居中滤波后的符号中心文件坐标，不是硬件空口时间。

用`PSKModulator.map_symbols`和`PSKDemodulator.demap_symbols`的`start_symbol_index`
维持帧起点的奇偶关系；不能在控制/数据字段或导频后隐式重置。
`refine_psk_carrier`在去交替旋转后作M次方盲FFT和相位拟合，
归一频率搜索±.1，依靠前置同步消除星座歧义，不枚举相位以迎合CRC。
该前端不含SRO恢复、均衡或绝对EVM标定，不能声称全部PSK接收能力已验收。

`phy.frame.decode_ft2_a3_capture`限定显式无加扰、CRC24A配置；
控制Polar(64,48)经真实A3头CRC后才信任长度/MCS。控制16:1导频，
数据导频必须显式指定0/1/4/16；1:1仅适用于明示厂测配置。
MCS6/8/10/12的数据复用原有码块分割、Polar及CRC，数据CRC通过才返回载荷。
CRC合格仍须另外核对已知内容，不能把未知厂测前缀解释为已确认协议字段。
原有`rx_chain`/`frame_to_symbols`的对齐假设和字段局部相位组织未由本增量全部验收；
真实IQ分析直接使用上述显式帧参考接口，不把已有通路的简化成功标志作为证据。


### 同一ADC输入的分数定时对照

`acquire_psk_capture(..., timing_subdivisions=8)`在原RRC之后用三次样条，
以1/8原始采样间隔搜索同一已知同步相关最大值；默认1保留整数路径。
能量、滤波、载波与CRC不变，不用期待载荷或CRC选择分数相位。
这是同一ADC记录的插值算法实验，不增加真实采样率、不证明原4SPS不足。
当前仅估计固定分数相位，不实现SRO或分数定时跟踪。
比较不同实际采样率需另控模拟带宽、数字滤波/抽取、增益和丢样状态，
高实际采样率成功也不能单独证明低采样率混叠。
